# @tweakpad/ui

## 0.1.3

### Patch Changes

- bb4b28d: Keyboard focus stays visible at full strength: a focused invalid Input, Text area, Input group, Checkbox, Radio, Select trigger, Switch, File upload or One-time code slot shows a destructive-colored ring instead of a faint tint, Navigation menu, Attachment, Switch and Slider focus rings no longer rely on a translucent halo, and the highlighted row of a Menu, Command palette, Select or Emoji picker gains an inset ring beside its fill.
- 27974e2: Arrow-key navigation in Radio group, Toggle group, Tabs, Toolbar, Calendar and Questionnaire now leaves consumed keys and arrows carrying Alt, Ctrl or Meta to the browser, and Questionnaire mirrors its inline arrows in right-to-left writing.
- 59383c4: Radio Group items and Slider thumbs no longer carry ARIA states their roles do not allow, Resizable Panel Group handles and Map pins and viewports omit `aria-disabled`/`aria-busy` while false, Calendar and Time honour the closest `lang` (Time also sets `lang` on its value when `locale` is explicit), and File Upload keeps keyboard focus on a neighbouring Remove Button or its input after an item is removed or the list is cleared.
- 564a31c: Text editor: the built-in `redo` tool scopes its `Ctrl+Y` shortcut to Windows and Linux through the key-binding owner's platform instead of reading the host machine's platform when the module loads, so an editor configured for Apple platforms never binds it and the behavior is the same on every machine. Key-binding patterns accept `{ pattern, platforms }` entries.
- 5256f29: Publish part state markers through the shared `stateMarkers`/`applyMarkers` helpers. Checkbox, Switch and Radio group items no longer emit the undocumented `data-read-only` alias; `data-readonly` is the canonical marker.
- 2942ce5: Text editor: the engine adapters and the optional controls are opt-in by import. `createTiptapEngine` and `createLexicalEngine` move from `@tweakpad/ui/text-editor` to their own entries, `@tweakpad/ui/text-editor/adapters/tiptap` and `@tweakpad/ui/text-editor/adapters/lexical`, so an application bundles only the adapter it imports; `@tweakpad/ui/text-editor` stays engine-free and `@tweakpad/ui/widgets` no longer re-exports the factories. The widget's block editing, tables, images, links, selection toolbar and suggestion lists are now features: `textEditorBlocks()`, `textEditorTables({ stickyHeaders })`, `textEditorImages({ upload, accept, maxFileSize })`, `textEditorLinks()`, `textEditorSelectionToolbar()` and `textEditorSuggestions()` from `@tweakpad/ui/widgets`, assigned to the new `features` property; without any, `tp-text-editor` is the core editor (toolbar, marks, block kinds, colors, alignment), at about half the size. The `imageUpload`, `image-accept`, `image-max-file-size` and `sticky-table-headers` members are removed in favor of the feature options. A feature's built-in tools exist only while it is assigned: the default layouts leave them out silently and a layout that places one reports `text-editor-layout-unknown` naming the feature; two features of one name report `text-editor-feature-duplicate`. The built-in tools split into a core set and one set per feature, and the content converters no longer load the tools and their icons. The size report gains a "Text editor (all features)" row and checks that the core ships no feature module. The alternative text field of a selected image shows only once its upload resolved the source; a pending image shows its File upload alone. The default image URL policy now also allows `blob:` object URLs, which only the page itself can create, so an upload hook can resolve a preview of the file; the documentation examples resolve the dropped file itself instead of a stock picture. The custom nodes example embeds a sample tide table page shipped with the examples (`/pages/tide-table.html`, a Storybook static directory) instead of an external placeholder site; the example's embed also accepts pages of the document's own origin, and its frame has a fixed height. New `measure` property and attribute (default 65): the longest line of text in characters, with the content centered in a wider viewport; `null` or 0 removes the limit. The Storybook stories and the Docs usage examples document the two main modes, the classic toolbar editor and the block editor, beside the default and core setups. The alternative text field of a selected image now shows in the context bar, a slot centered just below the fixed toolbar and outside the scrolling viewport that the editor's contextual editors share, instead of floating inside the image. While the caret or the selection sits inside a link, the links feature shows a link editor in the same context bar (part `text-editor-link-editor`): the destination with its apply, open and remove actions; Enter applies, Escape returns to the text, Alt+F10 reaches it, and the link popover hides it while open. The two context bar editors enter sliding down from under the toolbar while they fade in and leave the way they came, through the new `context-bar` motion role (`textEditorMotionRoles.contextBar`, context `editor`); the reduced motion policy shows and hides them at once.

## 0.1.2

### Patch Changes

- cfd5fa2: `tp-button` in a text size (`xs`, `sm`, `default`, `lg`) hides its `button-label` part when the label has no text, no element and no `content` contract. A Button that shows only an `icon-start` icon and an `icon-end` chevron then has one gap between its marks and the icon padding at both edges; name it with `aria-label`. Content added to the label later shows it again. Labelled Buttons and the `icon-*` sizes are unchanged. The Button owns the `hidden` attribute of the label, as it does for the marks, so a `hidden` value in the label's `hostProperties` no longer applies.
- cfd5fa2: Command palette items take an optional `description`, a secondary line after the label in the new `command-palette-item-description` part, which is the item's accessible description. `tp-command-list` takes an external input: with `queryOwner` set to an editing element that keeps focus, the list renders no input, takes its query from `inputValue` and its keys from `handleQueryKey(event)` and `activateHighlighted(event)`, each reporting whether it consumed the key, never moves focus, also when an item is pressed, and aborts a pending `source` call when it closes; with `inline` false it shows its list in a popup at `anchor`. `activeDescendantReference()` returns the element that forwards `aria-activedescendant` to the highlighted item. Lists and Selects without an external input are unchanged.
- cfd5fa2: Add content color roles to the default token set: `--tp-content-<hue>` and `--tp-content-<hue>-foreground` for gray, brown, orange, yellow, green, blue, purple, pink and red, in light and dark. The surface role paints highlights and table cell backgrounds and the foreground role paints colored text; they are meant for colors that user content names and the swatches that offer them, never for interface controls. `TOKEN_FAMILIES` gains a `content` family, so `REQUIRED_TOKEN_ROLES`, `TokenSet` and `assertCompleteTokenSet` now include the 18 roles: complete replacement themes must define them.
- cfd5fa2: Add `ContextualToolbarController`, a toolbar that its owner shows and hides from its own state, without a trigger, in a non-modal surface anchored to an element or a virtual anchor, in place or in the top layer. Showing never moves focus; `focus()` moves focus to the first enabled control; Escape inside it, and hiding it while it holds focus, return focus to its `finalFocus` target; and with `sequentialFocus: false` it stays out of the Tab sequence while Tab and Shift+Tab inside it return focus as Escape does. It follows a moved anchor without closing and hides when the anchor is removed. `ToolbarController` gains the `sequentialFocus` option and `focusFirst()`. The flow node toolbar now uses the contextual toolbar, with no change to its behavior.
- cfd5fa2: Add `deferRelease(view, release)`, which runs `release` two animation frames later on the given window or frame source, or after two 16 ms timeouts where there is no `requestAnimationFrame`, and returns a cancel function, so an element that is moved and reconnects within that window keeps what it would otherwise release. `deferMediaDestroy` is removed from `@tweakpad/ui` and `@tweakpad/ui/media`.
- cfd5fa2: Add the protected `associationContainer()` hook to `TpFormElement`, which chooses the node that holds the Field description and error text; the default keeps the current placement, so existing controls are unchanged.
- cfd5fa2: Add the protected `applyFieldAssociation(attributes)` hook and the `FieldAssociationAttributes` type to `TpFormElement`. A form control whose labelled element it cannot write directly receives the Field label, `aria-describedby`, `aria-errormessage` and `aria-invalid` there after every update and applies them itself by returning `true`; its Field description and error text then exist in its shadow root even when `associationTarget()` returns `null`. Existing controls are unchanged.
- cfd5fa2: Flow's lock, node library and tool Toggles use the icon size: they are square like the controls bar's icon Buttons, and a vertical controls bar of icon controls is as wide as one of them. The tool Toggle group is announced once, as the group named by its label, and its Toggles move with the bar's arrow keys. In a controls bar that lists the node library or the zoom field with other actions, the node library Toggle and the zoom menu trigger join the bar's single tab stop and its arrow-key sequence instead of adding tab stops. In a vertical controls bar, ArrowDown and ArrowUp on the zoom menu trigger open its menu, so list `zoom` last or use Home and End to reach the controls after it.
- cfd5fa2: The Flow marquee now fills with the selection fill that the library's selection paint shares, the `--tp-accent` role mixed toward transparent, instead of a tint of `--tp-primary`. Its dotted outline keeps `--tp-primary`.
- cfd5fa2: Keyboard shortcuts of the media player (including `tp-media-hotkey` bindings), the navigation panel shortcut, the carousel and the Flow widget match two more keyboard-layout cases. On Apple platforms a shortcut with Alt also matches its physical letter or digit key, because Option types another character there: `Mod+Alt+1` fires for Cmd+Option+1 and `Mod+Alt+C` for Cmd+Option+C. On every platform, while AltGraph is held, a shortcut with Mod and without Alt no longer matches, so characters typed with AltGraph, such as brackets and the backslash on many layouts, are typed instead of firing `Mod+[`, `Mod+]` or `Mod+\`. Shortcuts with both Mod and Alt still match while AltGraph is held.
- cfd5fa2: Defining Key hint group with `defineElement` now also defines Key hint, the element a group arranges.
- cfd5fa2: The custom elements manifest no longer lists an attribute that an element switches off for a property it inherits. `tp-file-upload` lists no `value` attribute, and its `value` property has the type `readonly File[]`; `tp-switch` lists no `indeterminate`, `parent` or `keep-mounted` attribute. The elements never observed these attributes, so their behavior is unchanged.
- cfd5fa2: `windowFrameSource` and the `TweenFrameSource` type are removed from `@tweakpad/ui` and `@tweakpad/ui/map`; the map runs on the library's shared window frames. `tweenCamera` and `MapControllerHost.frames` still take any object with `requestAnimationFrame`, `cancelAnimationFrame` and `now`.
- cfd5fa2: In `tp-markdown` at `size="sm"`, a code span inside a heading now takes the heading's font size, as it already did at the default size, instead of the smaller code span size. Code spans in other text keep their size, one step under the body text.
- cfd5fa2: `@tweakpad/ui/markdown` adds `serializeMarkdown`, which writes a Markdown tree back as markdown that parses to the same tree. It escapes only what would be read as syntax, gives each construct one form, and writes alerts, admitted elements and footnotes so that they resolve again. The entry also exports the sanitizing rules the resolve step applies, for code that cleans imported HTML: `isAlwaysRemovedAttribute`, `LINK_URL_ATTRIBUTES`, `IMAGE_URL_ATTRIBUTES`, `linkProtocols` and `imageProtocols`, beside the default element policy and protocol lists, which are now frozen.
- cfd5fa2: `ObservableStore` no longer calls a subscriber that another subscriber removed earlier in the same publication. An error thrown by a subscriber no longer stops the subscribers after it or propagates out of `set` and `update`: the store rethrows it in a microtask.
- cfd5fa2: Adds `ResizeSeparatorController`, the separator behavior of the resizable panel group for one extent that its owner controls, such as a table column outside a panel group. The owner supplies the value, its limits and the key steps (base, Shift and Alt) and receives live and settled proposals from pointer drags and key presses; the separator exposes its role, orientation and values, mirrors the inline arrows in right-to-left content, jumps to the limits with Home and End, restores the start value on Escape or pointer cancellation and releases pointer capture, the resize cursor and its listeners on every end of a drag. `resizeSeparatorTargetCss` gives the enlarged pointer target, which reads `--tp-resize-target-fine` and `--tp-resize-target-coarse` with 10 and 20 pixel fallbacks, so a separator outside a group gets it too. The resizable panel group now runs on it, with its behavior unchanged.
- cfd5fa2: Add text-editing icons: the modules `@tweakpad/ui/icons/text-blocks`, `text-align`, `link`, `table-editing`, `arrows`, `ellipsis`, `image-plus`, `at-sign` and `ban`, and `strikethroughIcon`, `codeIcon`, `superscriptIcon`, `subscriptIcon`, `highlighterIcon`, `baselineIcon` and `removeFormattingIcon` in `@tweakpad/ui/icons/text-formatting`. Each is a separate 24×24 outline definition, so importing one keeps the others out of a bundle; importing one definition of `text-formatting` no longer bundles the bookmark artwork. The package ships the artwork's license notice as a `LICENSE.*` file. The Icon documentation states the real `size` default.
- cfd5fa2: Add the `tp-text-editor` widget (`@tweakpad/ui/widgets`, registered by `@tweakpad/ui/register/widgets`), a rich text field for formatted documents. The document belongs to an editing engine that the application installs and assigns to `engine`, built from the engine's modules by an adapter factory of `@tweakpad/ui/text-editor`; that entry also provides the built-in tools, default layouts, strings and types, and `@tweakpad/ui/widgets` re-exports it. A toolbar above the content offers undo and redo, block types, lists, quotes and code blocks, text marks, superscript and subscript, and alignment as Toggles, Toggle groups and Menus behind one tab stop, moved through with the arrow keys, with tooltips that show each tool's shortcut; tool groups that do not fit move into a More menu whose label states how many groups it holds. Every document change from a tool, a shortcut, a paste or the `run` and `setContent` methods first dispatches the cancelable `tp-text-editor-request`, and a rejected change dispatches `tp-text-editor-request-failed`; while `readonly` is set, a paste is rejected the same way. `defaultValue` in `format` (`html`, `markdown`, `text` or `json`) supplies the initial content, shown as a static preview until the engine is ready unless the format is `json`. The read-only `value` is a snapshot of the committed document, serialized on request by `getContent(format)`. `tp-value-change` follows each applied change, `tp-value-commit` follows each applied request that changed the document and focus leaving the editor after typing, and `tp-text-editor-ready` and `tp-text-editor-error` report the engine's mount. The editor submits its content with a form through `name` and `form`, form reset restores `defaultValue`, and it performs no validation. Its accessible name comes from a Field label, else `label`, else its own `aria-label`, else the default name in `strings`. `disabled`, also from a disabled fieldset or Field, leaves nothing in it focusable, opens no tooltip or menu and submits no value. `tools`, `layout`, `nodes`, `strings` and `placeholder` configure it, and `state`, `subscribe`, `focus` and `blur` read and drive it. `textEditorStrings` holds the English defaults, `emptyBlockHint`, `instructions` and `grip` among them; the hint in an empty block names no key, and `moreTools` takes a `{count}` placeholder, the number of tool groups the More menu holds.
- cfd5fa2: Toggle and Toggle group `size` gain `xs`, `icon-xs`, `icon-sm`, `icon` and `icon-lg` beside `sm`, `default` and `lg`, the same set as Button, with their `toggle-size-*`, `toggle-content-size-*`, `toggle-group-size-*` and `toggle-group-item-size-*` presentation keys and the exported `ToggleSize` type. The `icon-*` sizes are square at the height of the matching step, with no inline padding, also inside a zero-spacing Toggle group; use them for Toggles whose content is only an icon. The existing sizes are unchanged. The Theme switcher's `group` variant now renders its Toggles at `icon-sm` for `size="sm"` and at `icon` by default, so its items are square and narrower than before. A Toggle's host is now exactly the box of its size, as a Button's is: a surrounding line height taller than the size, or a Toggle without text such as a color picker swatch, no longer makes the host taller than the visible toggle.
- cfd5fa2: Inside a toolbar, a Toggle registered as an item now takes its tab stop from the toolbar, so it no longer adds a second Tab stop, and a disabled Toggle stays a focusable stop with `aria-disabled="true"` that does not activate, as other toolbar controls do. A Toggle group inside a toolbar root now joins the toolbar by itself: its group part becomes the toolbar group and its Toggles join the toolbar's arrow-key sequence, with no tab stop or arrow keys of the group's own, while its selection mode and values are unchanged. Register Toggles as toolbar items, and leave Toggle groups and their Toggles unregistered.
- cfd5fa2: `ToolbarController` adds the `preserveFocusOnPress` option, its read-only accessor and the same option on `registerItem`. While it is on, pressing a control with the primary pointer button leaves focus and the text selection where they are, for example in an editor that the toolbar acts on; the control still activates on click, keyboard activation is unchanged and the pressed control shows no focus indicator. A primary press on the toolbar's own surface, such as the gap between controls, a separator or a group, also leaves focus and the selection in place and activates nothing. An item's own value overrides the toolbar's, so `preserveFocusOnPress: false` lets a control such as a drag handle take its press as usual. Input items, and presses made while focus is already inside the toolbar, always move focus. Escape on a disabled control of a toolbar is no longer prevented, so an enclosing Dialog or another dismissible layer closes; Enter, Space and character keys stay blocked on it. Controls slotted into a toolbar from an outer tree are now watched one by one: their `hidden`, `inert` and `disabled` changes still update the arrow-key order, and unrelated changes elsewhere in that tree no longer cause updates. A focused control that moves out of the toolbar and keeps focus, as a `moveBefore()` move does, now keeps it; only the tab stop moves to the nearest remaining control. When the focused control leaves together with its neighbours, such as the Toggles of a group or the controls of a removed wrapper, the tab stop and the focus repair now go to the remaining control nearest to where it was, instead of one further along.
- cfd5fa2: `projectDepth(rows, index, depth, canNest?)` takes an optional nest predicate that decides whether a row accepts the dragged row as a child. With one, the projected depth is lowered to the deepest depth within the clamp whose projected parent accepts the row, depth zero always being accepted; when no depth within the clamp is accepted, the projection reports `vetoed: true`. `TreeProjection` gains the `vetoed` field, which is always `false` without a predicate, and the `TreeNestPredicate` type is exported. Tree view reordering is unchanged.
- cfd5fa2: A `VirtualAnchor` may supply `getClientRectangles()`, its client rectangles in order, such as the lines of a text range. With two or more of them, positioning picks the reference rectangle among them: a surface above attaches to the first line, one below to the last line, one at a side to the lines that reach furthest to that side, and the new `inline` option of `positionSurface` (`{ x, y, padding }`) selects the line that holds a pointer point instead. When collision handling moves the surface to another side, it is placed again at that side's line. `inlineFragmentRect()` returns that reference rectangle. Anchors without client rectangles position as before.

## 0.1.1

### Patch Changes

- e37903f: Add `tp-citation` and `tp-citation-list`. A citation is an inline reference to a source: an outlined chip with muted text that can show a site icon (`src`, with a default mark when the image fails), a label and a number. - 4df1343: Add `tp-cursor` and `tp-cursor-zone`: a decorative custom pointer that hides the native cursor for mouse and pen users and trails the pointer with a spring (stiffness, damping, mass, rest thresholds, published position and velocity) in the top layer, with zones that declare a named state, cloned template content, scoped `--tp-cursor-*` appearance, native passthrough, center or bounds attraction and physics overrides. The custom elements manifest now lists each attribute's own default: overridden defaults (such as `orientation` on Citation list, Description list, Menu or Radio group) and defaults set from constants no longer show the inherited value or the constant's name.

- 037dc3c: Add `tp-file-upload`: a dashed drop surface over a native file input with accept, count, size and duplicate limits, custom validators with metadata, rejected files kept as error items, previews, chips, rows and image grid layouts, an optional upload adapter with progress, retry and cancellation, opt-in clipboard paste scoped to the control or the page, and Field and Form integration.

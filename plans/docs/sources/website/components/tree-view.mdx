## Usage

Nest `tp-tree-item` elements: text forms the label, `slot="leading"` and `slot="trailing"` hold marks and actions, and nested items are the children. `default-expanded` and `default-value` take JSON arrays of item values and apply before the first render, so the tree appears already open without change events. The tree is one tab stop; arrow keys move, Right expands and Left collapses or returns to the parent.

### Multiple selection with checkboxes

`selection-mode="multiple"` with `checkbox-selection` shows a checked indicator in every row. `selection-propagation` cascades a parent's selection to its descendants and derives mixed parents.

<Preview
  title="Permissions"
  code={`<tp-tree-view label="Permissions" selection-mode="multiple" checkbox-selection selection-propagation default-expanded='["billing", "projects"]' default-value='["invoices", "create", "archive"]' style="inline-size:18rem">
  <tp-tree-item value="billing">
    Billing
    <tp-tree-item value="invoices">View invoices</tp-tree-item>
    <tp-tree-item value="payment">Manage payment methods</tp-tree-item>

Disabled items stay focusable but are never selected by user input.

### Activation

Enter or a press fires a cancelable `tp-action` with the item's value, separately from selection. Use it to open a file or navigate; canceling it keeps the press from selecting or expanding.

### Records

For large or data-driven trees, set `defaultItems` (or controlled `items`) to records of `{ id, label, children }`. Records mode renders flat rows, which enables `virtualized` and `reorderable`; give a virtualized tree a block size.

<Preview
  title="From records, reorderable"
  code={`<tp-tree-view id="tree-view-records" label="Sprint backlog" reorderable size="sm" style="inline-size:18rem"></tp-tree-view>`}
  script={`await customElements.whenDefined('tp-tree-view');
const tree = document.querySelector('#tree-view-records');
tree.defaultExpanded = ['checkout', 'search'];
tree.defaultItems = [
  { id: 'checkout', label: 'Checkout redesign', children: [
    { id: 'cart', label: 'Persist cart across devices' },
    { id: 'wallets', label: 'Apple Pay and Google Pay' },
  ] },
  { id: 'search', label: 'Search', children: [
    { id: 'typo', label: 'Typo tolerance' },
    { id: 'filters', label: 'Saved filters' },
  ] },
  { id: 'onboarding', label: 'Onboarding emails' },
];`}
/>

Drag a handle, or press Control+Enter (Command+Enter) on an item and move it with the arrow keys. Each move is proposed through a cancelable `tp-items-change`.

### Custom rows

In records mode, `renderItem(item, state)` returns each row's content, so the artwork can follow the row's state. Here folders open their icon while expanded and show a child count in the `trailing` slot, built with `html` from `lit`. `canDrop` vetoes moves before they are offered, so files cannot hold other items, and Enter or a press on a row fires `tp-action`.

### Large trees

`virtualized` mounts only the rows near the viewport, so tens of thousands of records stay fast. Keyboard navigation, typeahead and `focusItem()` mount a row before focusing it. Give the tree a block size so it has a viewport to fill.

<Preview
  title="Virtualized"
  code={`<tp-tree-view id="tree-view-virtual" label="Log archive" virtualized size="sm" style="inline-size:18rem;block-size:16rem"></tp-tree-view>`}
  script={`await customElements.whenDefined('tp-tree-view');
const tree = document.querySelector('#tree-view-virtual');
const months = ['January', 'February', 'March', 'April', 'May', 'June', 'July', 'August', 'September', 'October', 'November', 'December'];
tree.defaultItems = [2024, 2025, 2026].map((year) => ({
  id: String(year),
  label: String(year),
  children: months.map((month, m) => ({
    id: \`\${year}-\${m + 1}\`,
    label: month,
    children: Array.from({ length: 28 }, (_, d) => ({
      id: \`\${year}-\${m + 1}-\${d + 1}\`,
      label: \`\${month} \${d + 1} · 24 log files\`,
      children: Array.from({ length: 24 }, (_, h) => ({
        id: \`\${year}-\${m + 1}-\${d + 1}-\${h}\`,
        label: \`\${String(h).padStart(2, '0')}:00.log\`,
      })),
    })),
  })),
}));
tree.defaultExpanded = ['2026', '2026-10', '2026-10-14'];`}
/>

The archive holds about 25,000 records; only a few dozen rows exist in the document at a time.

### Controlled

To own selection and expansion yourself, set `items`, `value` and `expanded` and write back each accepted proposal from `tp-value-change` and `tp-expanded-change`. The tree then shows exactly your state; the methods still work and go through the same events.

<Preview
  title="Controlled lanes"
  code={`<div style="display:grid;gap:var(--tp-space-3);justify-items:center">
  <tp-tree-view id="tree-view-controlled" label="Help center" size="sm" style="inline-size:18rem"></tp-tree-view>
  <div style="display:flex;align-items:center;gap:var(--tp-space-3)">
    <output id="tree-view-controlled-status" style="color:var(--tp-muted-foreground);font-size:var(--tp-text-sm)">Selected: Refund policy</output>
    <tp-button id="tree-view-controlled-reveal" variant="outline" size="sm">Reveal selection</tp-button>
  </div>
</div>`}
  script={`await customElements.whenDefined('tp-tree-view');
const tree = document.querySelector('#tree-view-controlled');
const status = document.querySelector('#tree-view-controlled-status');
const state = { value: ['refunds'], expanded: [] };
tree.items = [
  { id: 'account', label: 'Account', children: [
    { id: 'password', label: 'Reset your password' },
    { id: 'two-factor', label: 'Two-factor authentication' },
  ] },
  { id: 'billing', label: 'Billing', children: [
    { id: 'invoices', label: 'Download invoices' },
    { id: 'policies', label: 'Policies', children: [
      { id: 'refunds', label: 'Refund policy' },
      { id: 'cancellation', label: 'Cancellation' },
    ] },
  ] },
];
const labels = {};
const index = (items) => items.forEach((item) => { labels[item.id] = item.label; if (item.children) index(item.children); });
index(tree.items);
tree.value = state.value;
tree.expanded = state.expanded;
tree.addEventListener('tp-value-change', (event) => {
  state.value = event.detail.value;
  tree.value = state.value;
  const [id] = state.value;
  status.textContent = id ? \`Selected: \${labels[id]}\` : 'Nothing selected';
});
tree.addEventListener('tp-expanded-change', (event) => {
  state.expanded = event.detail.value;
  tree.expanded = state.expanded;
});
document.querySelector('#tree-view-controlled-reveal').addEventListener('click', () => {
  tree.revealItem(state.value[0] ?? 'refunds', { focus: true });
});`}
/>

The selected article starts hidden inside collapsed groups; Reveal selection expands its ancestors through `tp-expanded-change`, which the owner accepts.

### Loading children on demand

A record with `hasChildren: true` shows a chevron before its children exist. On first expansion the tree calls `loadChildren(item, { signal })`, shows a loading row while it waits, and inserts the records it returns. The signal aborts if the item is removed or the tree disconnects first, and a failed load offers a retry.

<Preview
  title="Lazy folders"
  code={`<tp-tree-view id="tree-view-lazy" label="Shared drive" size="sm" style="inline-size:18rem"></tp-tree-view>`}
  script={`await customElements.whenDefined('tp-tree-view');
const tree = document.querySelector('#tree-view-lazy');
const folders = {
  contracts: ['Northwind MSA 2026.pdf', 'Contoso NDA.pdf', 'Fabrikam renewal.pdf'],
  invoices: ['September.xlsx', 'August.xlsx'],
};
tree.defaultItems = [
  { id: 'contracts', label: 'Contracts', hasChildren: true },
  { id: 'invoices', label: 'Invoices', hasChildren: true },
  { id: 'budget', label: 'Budget 2027.xlsx' },
];
tree.loadChildren = async (item, { signal }) => {
  await new Promise((resolve) => setTimeout(resolve, 800));
  if (signal.aborted) return [];
  return folders[item.id].map((name) => ({ id: \`\${item.id}/\${name}\`, label: name }));
};`}
/>

`reloadChildren(id)` discards loaded children so the next expansion fetches them again.

### Expanding from code

`expandAll()`, `collapseAll()`, `expandItem(id)` and `collapseItem(id)` change expansion through the same `tp-expanded-change` as the keyboard. `revealItem(id, { focus: true })` opens the item's ancestors, scrolls it into view and focuses it.

## Usage

`filename` names the resource and the actions generated for it; `description` carries type, size or progress. Your application owns uploading, retrying, previewing and removing: `status` only changes how the attachment looks.

### Status

  title="Statuses"
  align="stretch"
  code={`<div style="display:grid;gap:var(--tp-space-2);inline-size:100%;max-inline-size:26rem;margin-inline:auto">

  <tp-attachment filename="product-demo.mp4" description="Uploading · 38%" status="uploading"></tp-attachment>
  <tp-attachment filename="survey-results.xlsx" description="Scanning for viruses" status="processing"></tp-attachment>
  <tp-attachment filename="receipt-0412.heic" status="error" error-message="HEIC isn't supported. Export as JPG or PNG and try again." removable></tp-attachment>
  <tp-attachment filename="brand-guidelines.pdf" file-size="3355443" status="complete" href="#attachment-status" removable></tp-attachment>
</div>`}
/>

Busy states show a spinner when no media is supplied. An error must explain recovery, through `error-message` or the description. Without a description, `file-size` is formatted for you. `href` turns the attachment into a link to the resource.

### Triggers and actions

<Preview
  title="Preview trigger, download and retry"
  align="stretch"
  code={`<div id="attachment-actions" style="display:grid;gap:var(--tp-space-2);inline-size:100%;max-inline-size:26rem;margin-inline:auto">
  <tp-attachment filename="research-summary.txt" description="Text · 1 KB · Select to preview" status="complete" removable>
    <svg slot="media" aria-hidden="true" width="16" height="16" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round"><path d="M14 2H6a2 2 0 0 0-2 2v16a2 2 0 0 0 2 2h12a2 2 0 0 0 2-2V8z"/><path d="M14 2v6h6M16 13H8M16 17H8"/></svg>
    <tp-button slot="trigger" id="attachment-preview-trigger" aria-label="Preview research-summary.txt"></tp-button>
    <tp-button slot="actions" id="attachment-download" variant="ghost" size="sm" download="research-summary.txt">Download</tp-button>
  </tp-attachment>
  <tp-attachment id="attachment-retry-target" filename="interview-notes.docx" status="error" error-message="The upload was interrupted. Retry to continue." removable>
    <tp-button slot="actions" id="attachment-retry" variant="ghost" size="sm">Retry</tp-button>
  </tp-attachment>
  <tp-dialog id="attachment-preview-dialog" label="research-summary.txt" description="Uploaded by Priya Shah · 2 June">
    <p style="margin:0">Twelve of fifteen customers asked for shared dashboards. Most export to spreadsheets today and rebuild the same charts every week.</p>
    <tp-button slot="close">Close</tp-button>
  </tp-dialog>
</div>`}
  script={`await customElements.whenDefined('tp-dialog');
const root = document.querySelector('#attachment-actions');
const summary = 'Research summary\\n\\nTwelve of fifteen customers asked for shared dashboards.';
const url = URL.createObjectURL(new Blob([summary], { type: 'text/plain' }));
root.querySelector('#attachment-download').href = url;
root.querySelector('#attachment-preview-dialog').registerTrigger(root.querySelector('#attachment-preview-trigger'));

root.querySelector('#attachment-retry').addEventListener('click', (event) => {
  const attachment = root.querySelector('#attachment-retry-target');
  event.currentTarget.remove();
  attachment.status = 'uploading';
  attachment.description = 'Uploading · 40%';
  setTimeout(() => {
    attachment.status = 'complete';
    attachment.description = 'Word · 64 KB';
  }, 1600);
});
root.addEventListener('tp-remove', (event) => event.target.remove());`}
/>

A `trigger` button makes the whole attachment open something, here a preview dialog registered with `registerTrigger()`. Buttons in the `actions` slot stay separate controls, so Download, Retry and Remove never set the trigger off.

  title="Remove event"

  script={`document.querySelector('#attachment-remove-list').addEventListener('tp-remove', (event) => {
  event.target.remove();
});`}
/>

`removable` adds a Remove button that emits a cancelable `tp-remove` with the `filename`. Nothing is removed until your handler does it, so you can confirm first or delete the file on the server.

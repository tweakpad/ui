## Usage

Select picks from a list that is too long, or too dynamic, to show as radios. Native `option`, `optgroup` and `hr` children declare the choices; the component renders its own list, keyboard navigation and typeahead, and submits the selected value under `name`. Use Native Select when the browser's own picker is preferable, such as on mobile-first forms.

### Options

Each `option` contributes a `value` and its text. `disabled` keeps an option visible but unselectable, `optgroup` labels a group and `hr` draws a separator. `placeholder` shows while nothing is selected.

  title="Groups and disabled options"
  align="stretch"
  code={`<tp-field label="Plan" style="max-inline-size:20rem">
  <tp-select name="plan" placeholder="Choose a plan">
    <option value="free">Free</option>
    <option value="team">Team · $12 per seat</option>
    <option value="business">Business · $24 per seat</option>
    <hr>
    <option value="enterprise" disabled>Enterprise · Contact sales</option>
  </tp-select>
</tp-field>`}

### Authored options

`tp-select-option` is the library's own option element. It declares the same choice as a native `option`, accepts a non-string `value` when set as a property, and uses its text content as the label.

<Preview
  title="tp-select-option"
  align="stretch"
  code={`<tp-field label="Priority" style="max-inline-size:20rem">
  <tp-select name="priority" default-value="medium">
    <tp-select-option value="urgent">Urgent</tp-select-option>
    <tp-select-option value="high">High</tp-select-option>
    <tp-select-option value="medium">Medium</tp-select-option>
    <tp-select-option value="low">Low</tp-select-option>
  </tp-select>
</tp-field>`}
/>

### Searchable

`searchable` swaps the trigger for an editable query that filters the list as people type. `matching` chooses `contains` (the default), `prefix`, `exact` or typo-tolerant `fuzzy`; `highlight-matches` marks the matched text. The query is never submitted, only the selection.

### Grid

In a searchable Select with `grid`, `columns` lays each group's options out in rows of that many, and the arrow keys move in two dimensions. Filtering reflows the rows. It suits short, scannable options such as sizes, flags or symbols.

### Data

Assign `items` when choices come from your data. Records take a `value` and `label`, groups take `type: 'group'` with nested `items`, and `type: 'separator'` divides them.

  script={`const select = document.querySelector('#select-items');
select.items = [

    { value: 'u_102', label: 'Maya Lindqvist' },
    { value: 'u_118', label: 'Tomás Herrera' },

### Large lists

`virtualized` mounts only the rows near the visible part of the list while keeping its full scroll height, so hundreds or thousands of `items` open instantly. Keyboard navigation and typeahead still cover every option.

<Preview
  title="Virtualized time zones"
  align="stretch"
  code={`<tp-field label="Time zone" style="max-inline-size:20rem">
  <tp-select id="select-virtualized" name="time-zone" searchable virtualized placeholder="Search time zones"></tp-select>
</tp-field>`}
  script={`const select = document.querySelector('#select-virtualized');
select.items = Intl.supportedValuesOf('timeZone').map((zone) => ({
  value: zone,
  label: zone.replaceAll('_', ' '),
}));`}
/>

### Remote search

A `source` supplies the options for each query, such as a server endpoint. A query waits `search-delay` milliseconds after the last keystroke, a newer query aborts the previous one through `signal`, and the list shows a loading row meanwhile.

<Preview
  title="Search source"
  align="stretch"
  code={`<tp-field label="Customer" style="max-inline-size:20rem">
  <tp-select id="select-source" name="customer" searchable search-delay="250" placeholder="Search customers"></tp-select>
</tp-field>`}
  script={`const customers = [
  'Acme Logistics', 'Birchwood Dental', 'Cobalt Robotics', 'Delta Freight', 'Evergreen Grocers',
  'Fjord Outfitters', 'Granite Legal', 'Harbor Coffee', 'Ironclad Security', 'Juniper Health',
  'Keystone Builders', 'Lumen Studios', 'Meridian Travel', 'Northwind Traders', 'Orchard Bakery',
];
const select = document.querySelector('#select-source');
select.source = {
  // Stands in for fetch('/api/customers?q=' + query, { signal }).
  search: (query, { signal }) =>
    new Promise((resolve, reject) => {
      const timer = setTimeout(() => {
        const needle = query.trim().toLowerCase();
        resolve(customers
          .filter((name) => name.toLowerCase().includes(needle))
          .map((name) => ({ value: name.toLowerCase().replaceAll(' ', '-'), label: name })));
      }, 600);
      signal.addEventListener('abort', () => {
        clearTimeout(timer);
        reject(signal.reason);
      });
    }),
};`}
/>

### Value changes

`tp-value-change` reports each proposed selection with its `reason`, and is cancelable. Read the committed value from `value`.

<Preview
  title="Value change"
  align="stretch"
  code={`<div style="display:grid;gap:var(--tp-space-3);max-inline-size:20rem">
  <tp-field label="Sort by">
    <tp-select id="select-sort" default-value="updated">
      <option value="updated">Last updated</option>
      <option value="created">Date created</option>
      <option value="name">Name</option>
    </tp-select>
  </tp-field>
  <output id="select-sort-output" style="color:var(--tp-muted-foreground);font-size:var(--tp-text-sm)">Sorted by updated</output>
</div>`}
  script={`const select = document.querySelector('#select-sort');
const output = document.querySelector('#select-sort-output');
select.addEventListener('tp-value-change', (event) => {
  if (event.target !== select || event.detail.cancelled) return;
  output.textContent = 'Sorted by ' + event.detail.value;
});`}
/>

### States

A Field's `disabled`, `invalid` and `error` reach the Select. Read-only Selects still open and navigate, and keep their value in form data, but cannot change it.

### In a dialog

A Select works inside a Dialog without extra setup: its popup belongs to the dialog, so it opens above the modal and stays interactive while the rest of the page is inert.

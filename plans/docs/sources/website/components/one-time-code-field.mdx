## Usage

The slots are presentation over a single text editor, so typing, deletion, selection, paste and SMS autofill (`autocomplete="one-time-code"` by default) behave like one input. Screen readers hear one field with one name, and the form receives one value. Wrap it in a Field for the label.

### Character types

`validation-type` filters what can be entered: `numeric`, `alphabetic` or the default `alphanumeric`. Numeric codes also bring up the number keypad on touch devices.

</tp-field>`}

### Groups

`group-lengths` splits the slots into visual groups with a separator between them. The separator never enters the value or the accessibility tree.

### Masking

`mask` hides the entered characters on screen while the value stays intact. Use it for PINs entered where others can see.

### Completion

`tp-complete` fires once the last slot is filled, which is the moment to verify. Add `auto-submit` to submit the owning form instead of waiting for a button press.

<Preview
  title="Verify on completion"
  code={`<form id="otc-form" style="display:grid;gap:var(--tp-space-3);justify-items:start">
  <tp-field label="Email verification code" description="Use the code from your email.">
    <tp-one-time-code-field id="otc-field" length="6" name="code" group-lengths="[3,3]" validation-type="numeric" auto-submit></tp-one-time-code-field>
  </tp-field>
  <output id="otc-output" style="color:var(--tp-muted-foreground);font-size:var(--tp-text-sm)">Waiting for 6 digits</output>
</form>`}
  script={`const form = document.querySelector('#otc-form');
const output = document.querySelector('#otc-output');
form.addEventListener('submit', (event) => {
  event.preventDefault();
  output.textContent = \`Submitted code \${new FormData(form).get('code')}\`;
});`}
/>

### Controlled

Set `value` to own the code, and accept each edit from `tp-value-change` by assigning `event.detail.value`. Your application can then clear or prefill the field directly, for example after requesting a new code.

<Preview
  title="Controlled value"
  code={`<div id="otc-controlled" style="display:grid;gap:var(--tp-space-3);justify-items:start">
  <tp-field label="Two-factor code">
    <tp-one-time-code-field length="6" validation-type="numeric" group-lengths="[3,3]" value=""></tp-one-time-code-field>
  </tp-field>
  <div style="display:flex;gap:var(--tp-space-3);align-items:center">
    <tp-button variant="outline" size="sm" data-resend>Send a new code</tp-button>
    <output aria-live="polite" style="color:var(--tp-muted-foreground);font-size:var(--tp-text-sm)">0 of 6 digits</output>
  </div>
</div>`}
  script={`const root = document.querySelector('#otc-controlled');
const field = root.querySelector('tp-one-time-code-field');
const output = root.querySelector('output');
field.addEventListener('tp-value-change', (event) => {
  if (event.defaultPrevented || event.detail.cancelled) return;
  field.value = event.detail.value;
  output.textContent = \`\${field.value.length} of 6 digits\`;
});
root.querySelector('[data-resend]').addEventListener('click', () => {
  field.value = '';
  output.textContent = 'New code sent. The old one no longer works.';
  field.focus();
});`}
/>

Disabled codes are left out of form data. An invalid Field paints every slot and announces its error once for the whole code.

## Usage

A Questionnaire walks people through a short, ordered set of questions, one at a time, inside a single native form. Use it for intake flows, setup wizards and feedback where focusing on one question beats a long page of fields. Questions are data: assign the `questions` property, then handle `tp-submit`. The host owns saving and sending the answers.

### Answers

Single-choice questions render native radios and `kind: 'multiple'` renders checkboxes. An `input` adds a freeform answer beside the choices, and a question without choices is a plain text question.

### Skipping and validation

`required` questions must be answered before Next. Optional questions can offer Skip with `skippable`; skipped answers are left out of the submitted data. `validate(answer)` returns an error message for answers that are present but wrong.

  <tp-questionnaire id="questionnaire-skip" label="Workspace setup"></tp-questionnaire>
</div>`}
  script={`const questionnaire = document.querySelector('#questionnaire-skip');
questionnaire.questions = [
  {
    name: 'constraints',
    title: 'Any constraints we should know about?',
    description: 'Optional. Skip if there are none.',
    skippable: true,
    input: { label: 'Constraints', placeholder: 'Must stay on the EU region…' },
  },
  {
    name: 'seats',
    title: 'How many seats do you need?',
    required: true,
    input: { label: 'Seats', type: 'number', placeholder: '12' },

];
questionnaire.actions = { submit: { label: 'Create workspace' } };
questionnaire.addEventListener('tp-submit', (event) => event.preventDefault());`}

### Conditional questions

A question with `disabled: true` drops out of navigation, progress, validation and submission. Listen for `tp-value-change` and reassign `questions` to include follow-ups only when an answer calls for them.

  title="Follow-up question"

  <tp-questionnaire id="questionnaire-conditional" label="Deployment"></tp-questionnaire>
</div>`}
  script={`const questionnaire = document.querySelector('#questionnaire-conditional');
const questions = [
  {
    name: 'target',
    title: 'Where should this service run?',
    description: 'Cloud deployments ask for a region next.',
    required: true,
    choices: [
      { value: 'on-premises', label: 'Our own servers' },
      { value: 'cloud', label: 'Managed cloud' },
    ],
  },
  {
    name: 'region',
    title: 'Which region should host it?',
    required: true,
    choices: [
      { value: 'eu-west', label: 'EU West (Dublin)' },
      { value: 'us-east', label: 'US East (Virginia)' },
      { value: 'ap-south', label: 'Asia Pacific (Mumbai)' },
    ],
  },
  {
    name: 'alerts',
    title: 'Who should be paged when it goes down?',
    required: true,
    choices: [
      { value: 'on-call', label: 'The on-call engineer' },
      { value: 'team', label: 'The whole platform team' },

questionnaire.addEventListener('tp-submit', (event) => event.preventDefault());`}

### Controlled checkpoint

Set `item` and accept moves in `onItemChange` to own which question is active, for example to keep it in the URL. Owners are fixed when the element connects, so create it in script and configure it first. Owning the checkpoint also lets a submit handler check answers against each other, mark a question `invalid` with an `error`, and send the person back to it.

<Preview
  title="Checkpoint and cross-answer validation"
  code={`<div id="questionnaire-controlled" style="display:grid;gap:var(--tp-space-4);inline-size:28rem;max-inline-size:100%">
  <output style="color:var(--tp-muted-foreground);font-size:var(--tp-text-sm)"></output>
</div>`}
  script={`const root = document.querySelector('#questionnaire-controlled');
const output = root.querySelector('output');
const questionnaire = document.createElement('tp-questionnaire');
questionnaire.label = 'Incident report';
questionnaire.questions = [
  {
    name: 'detail',
    title: 'How much detail should the report include?',
    required: true,
    choices: [
      { value: 'summary', label: 'Short summary' },
      { value: 'timeline', label: 'Full timeline with root cause' },
    ],
  },
  {
    name: 'audience',
    title: 'Who will read it?',
    description: 'Customer-facing reports need the full timeline.',
    required: true,
    choices: [
      { value: 'internal', label: 'Engineering only' },
      { value: 'customers', label: 'Affected customers' },
    ],
  },
];
questionnaire.actions = { submit: { label: 'Publish report' } };
const titleOf = (name) => questionnaire.questions.find((question) => question.name === name).title;
questionnaire.item = 'detail';
questionnaire.onItemChange = (event) => {
  if (event.defaultPrevented || event.detail.cancelled) return;
  questionnaire.item = event.detail.value;
  output.textContent = \`Checkpoint: \${titleOf(event.detail.value)}\`;
};
questionnaire.addEventListener('tp-value-change', () => {
  questionnaire.questions = questionnaire.questions.map((question) => ({ ...question, invalid: false, error: '' }));
});
questionnaire.addEventListener('tp-submit', (event) => {
  event.preventDefault();
  const { detail, audience } = event.detail.answers;
  if (audience === 'customers' && detail === 'summary') {
    questionnaire.questions = questionnaire.questions.map((question) => ({
      ...question,
      invalid: question.name === 'detail',
      error: question.name === 'detail' ? 'Customers need the full timeline. Choose it to publish.' : '',
    }));
    questionnaire.item = 'detail';
    output.textContent = \`Checkpoint: \${titleOf('detail')}\`;
    return;
  }
  output.textContent = 'Published: ' + JSON.stringify(event.detail.answers);
});
output.textContent = \`Checkpoint: \${titleOf('detail')}\`;
root.prepend(questionnaire);`}
/>

### Navigation buttons

`actions` sets the label, `variant`, `size`, `disabled` and `hidden` of Previous, Skip, Next and Submit. Derive availability from `status` in each question's `onStatusChange` and after `tp-item-change`, here to keep Next and Submit disabled until the current question has an answer.

<Preview
  title="Disabled until answered"
  code={`<div style="inline-size:28rem;max-inline-size:100%">
  <tp-questionnaire id="questionnaire-actions" label="Access request"></tp-questionnaire>
</div>`}
  script={`const questionnaire = document.querySelector('#questionnaire-actions');
const synchronize = () => {
  const disabled = questionnaire.status !== 'answered';
  questionnaire.actions = {
    next: { variant: 'secondary', disabled },
    submit: { label: 'Request access', disabled },
  };
};
questionnaire.questions = [
  {
    name: 'resource',
    title: 'Which environment do you need?',
    required: true,
    choices: [
      { value: 'staging', label: 'Staging' },
      { value: 'production-read', label: 'Production, read-only' },
      { value: 'production', label: 'Production, full access' },
    ],
  },
  {
    name: 'duration',
    title: 'For how long?',
    required: true,
    choices: [
      { value: '1h', label: 'One hour' },
      { value: '1d', label: 'Until end of day' },
      { value: '1w', label: 'One week' },
    ],

### Entrance animation

The `questionnaire-question` part's `elementReference` runs each time a new question becomes active, while progress and buttons stay in place. Animate that element only, scale the duration by the inherited `--tp-motion-scale` so reduced motion turns it off, and cancel the animation when the reference changes.

<Preview
  title="Animated questions"
  code={`<div style="inline-size:28rem;max-inline-size:100%">
  <tp-questionnaire id="questionnaire-animated" label="Event RSVP"></tp-questionnaire>
</div>`}
  script={`const questionnaire = document.querySelector('#questionnaire-animated');
let current;
let animation;
questionnaire.partContracts = {
  'questionnaire-question': {
    elementReference: (element) => {
      if (element === current) return;
      animation?.cancel();
      current = element;
      if (!element) return;
      queueMicrotask(() => {
        if (current !== element || !element.isConnected) return;
        const style = getComputedStyle(element);
        const scale = Number(style.getPropertyValue('--tp-motion-scale').trim() || 1);
        const duration = parseFloat(style.getPropertyValue('--tp-duration-normal')) * 1000;
        if (!scale || !duration) return;
        animation = element.animate(
          [{ opacity: 0, transform: 'translateY(0.5rem)' }, { opacity: 1, transform: 'none' }],
          { duration: duration * scale, easing: style.getPropertyValue('--tp-easing-enter') },
        );
      });
    },
  },
};
questionnaire.questions = [
  {
    name: 'attending',
    title: 'Will you join the offsite in Lisbon?',
    required: true,
    choices: [
      { value: 'yes', label: 'Yes, I will be there' },
      { value: 'remote', label: 'I will join remotely' },
      { value: 'no', label: 'I cannot make it' },
    ],
  },
  {
    name: 'diet',
    title: 'Any dietary requirements?',
    skippable: true,
    choices: [
      { value: 'vegetarian', label: 'Vegetarian' },
      { value: 'vegan', label: 'Vegan' },
      { value: 'gluten-free', label: 'Gluten-free' },
    ],
  },
];
questionnaire.actions = { submit: { label: 'Send RSVP' } };
questionnaire.addEventListener('tp-submit', (event) => event.preventDefault());`}
/>

### Card layout

Delegates can rearrange the parts Questionnaire has already rendered. Each part's `state.regions` holds them, so a Card can take the title, description and progress in its header slots, the choices in its body and the buttons in its footer, with the fieldset naming and native form untouched. Render each region once.

<Preview
  title="Inside a Card"
  code={`<div style="inline-size:28rem;max-inline-size:100%">
  <tp-questionnaire id="questionnaire-card" label="Plan upgrade" shortcut-mode="numbers"></tp-questionnaire>
</div>`}
  script={`import { html } from 'lit';
const questionnaire = document.querySelector('#questionnaire-card');
questionnaire.partContracts = {
  questionnaire: {
    renderDelegate: ({ bind, state }) => html\`<form \${bind}>\${state.regions.answers}\${state.regions.question}</form>\`,
  },
  'questionnaire-question': {
    renderDelegate: ({ bind, state }) => html\`<fieldset \${bind}>
      <tp-card>
        \${state.regions.title}\${state.regions.description}\${state.regions.progress}
        \${state.regions.choices}\${state.regions.error}\${state.regions.actions}
      </tp-card>

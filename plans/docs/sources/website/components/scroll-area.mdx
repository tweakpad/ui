## Usage

A Scroll Area keeps the browser's own scrolling (wheel, touch, keyboard, focus and scroll anchoring) and replaces only the visible scrollbars. Constrain its height or width; its content decides how far it scrolls. A `label` names the viewport as a region, which helps when it holds a lot of content.

### Horizontal

`orientation="horizontal"` shows the horizontal track. The content needs an intrinsic width wider than the area, such as a row that does not wrap.

### Scrollbar visibility

`scrollbar-visibility` decides when tracks appear. The default, `automatic`, shows each overflowing axis; `on-hover` and `while-scrolling` keep quiet surfaces clean, and `always` keeps the track visible as a cue that more content exists.

### Overflow markers

The host exposes `data-overflow-y-start` and `data-overflow-y-end` while content is hidden past an edge. Use them for fades or shadows that tell people there is more to scroll. Scroll the viewport itself with the standard `scrollTo` and `scrollTop` APIs on `viewportElement`.

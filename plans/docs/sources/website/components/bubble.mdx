## Usage

`tp-bubble` renders one message; `tp-bubble-group` stacks consecutive messages from the same sender. Your application owns delivery, sender names and reaction counts; the Bubble only presents them.

### Treatments

<Preview
  title="Variants"
  align="stretch"
  code={`<div style="display:grid;gap:var(--tp-space-3);max-inline-size:32rem;margin-inline:auto">
  <tp-bubble variant="default">Default</tp-bubble>
  <tp-bubble>Secondary</tp-bubble>
  <tp-bubble variant="subdued">Subdued</tp-bubble>
  <tp-bubble variant="tinted">Tinted</tp-bubble>
  <tp-bubble variant="outline">Outline</tp-bubble>
  <tp-bubble variant="ghost">Ghost</tp-bubble>
  <tp-bubble variant="destructive">Message failed to send. Tap to retry.</tp-bubble>
</div>`}
/>

`secondary` is the default. Use one treatment per sender so the conversation reads at a glance, `ghost` for unframed assistant text that should take the full row, and `destructive` for delivery failures.

### Sender alignment

`align` is logical: `end` sits on the inline end and follows writing direction. Group consecutive messages so spacing reflects who is speaking, not each message.

<Preview
  title="Alignment"

  <tp-bubble-group>

### Reactions

The `reactions` slot accepts plain counts or real controls. `reaction-side` picks the top or bottom edge and `reactions-align` the inline edge; the two are independent. Give every reaction an accessible name.

### Rich content

The default slot takes any content: paragraphs and links keep their own semantics. The message container is a named group (`label`, default "Message"); `label=""` removes the role.

### Long messages

<Preview
  title="Expandable message"
  align="stretch"
  code={`<div style="display:grid;gap:var(--tp-space-3);max-inline-size:32rem;margin-inline:auto">
  <tp-bubble variant="subdued" label="Message from Priya">
    <p style="margin:0">Here's the summary from this morning's incident review.</p>
    <tp-collapsible id="bubble-expand">
      <span slot="label">Show more</span>
      <p style="margin:0">Checkout errors started at 09:12 when the payments provider rotated its signing keys. Our webhook verifier cached the old key for up to an hour.</p>
      <p style="margin-block:var(--tp-space-2) 0">We shortened the cache to five minutes and added an alert on signature failures. No orders were lost; 41 customers saw a retry prompt.</p>
    </tp-collapsible>
  </tp-bubble>
</div>`}
  script={`await customElements.whenDefined('tp-collapsible');
const disclosure = document.querySelector('#bubble-expand');
disclosure.partContracts = {
  'collapsible-label': { content: ({ open }) => (open ? 'Show less' : 'Show more') },
};
disclosure.partPresentation = {
  'collapsible-trigger': { styleHook: { 'padding-inline': '0', 'inline-size': 'fit-content' } },
  'collapsible-content-body': { styleHook: { 'padding-inline': '0' } },
};`}
/>

Put a Collapsible inside the bubble to keep long replies short in the thread. The Collapsible owns expansion and its native button; `partContracts` swaps the label as it opens, and `partPresentation` trims the trigger to fit the bubble's padding.

### Buttons and links

<Preview
  title="Quick replies"
  align="stretch"
  code={`<div id="bubble-replies" style="display:grid;gap:var(--tp-space-3);max-inline-size:32rem;margin-inline:auto">
  <tp-bubble variant="default">Hi Sam, your order #10482 is out for delivery. Anything I can help with?</tp-bubble>
  <tp-bubble variant="outline" data-link>Track your package</tp-bubble>
  <tp-bubble-group data-suggestions>
    <tp-bubble variant="outline" align="end" data-reply>Change the delivery address</tp-bubble>
    <tp-bubble variant="outline" align="end" data-reply>Leave it with a neighbor</tp-bubble>
    <tp-bubble variant="outline" align="end" data-reply>Talk to a person</tp-bubble>
  </tp-bubble-group>
</div>`}
  script={`import { html } from 'lit';

await customElements.whenDefined('tp-bubble');
const thread = document.querySelector('#bubble-replies');
thread.querySelector('[data-link]').partContracts = {
  'bubble-content': {
    renderDelegate: ({ bind, content }) => html\`<a href="#buttons-and-links" \${bind}>\${content}</a>\`,
  },
};
for (const reply of thread.querySelectorAll('[data-reply]')) {
  reply.partContracts = {
    'bubble-content': {
      renderDelegate: ({ bind, content }) => html\`<button type="button" \${bind}>\${content}</button>\`,
    },
  };
  reply.addEventListener('click', () => {
    const sent = document.createElement('tp-bubble');
    sent.align = 'end';
    sent.variant = 'tinted';
    sent.textContent = reply.textContent;
    thread.querySelector('[data-suggestions]').replaceWith(sent);
  });
}`}
/>

A whole bubble can be a link or a button. `partContracts` renders the `bubble-content` part as a native `a` or `button`, which keeps the bubble's look and gives it real link or button behavior. Here the suggested replies send themselves when picked.

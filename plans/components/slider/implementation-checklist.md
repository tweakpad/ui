## Architecture and reuse

- Folder boundaries: slider/index.ts, types.ts, slider.ts Root owner, slider-thumb.ts thin constituent, styles.ts structural geometry; necessary existing foundation/slider.ts policy/math repair and focused tests. Avoid empty imitation layers.
- Root sole commit and form serialization authority; Thumb does not independently own a numeric value, reset or successful form value. It inherits existing same-shadow native reference/ARIA/focus/fieldset infrastructure and always writes null form value.
- Root owns register/export/definitions/recipe removal and grouped legacy extraction; preserve TpSlider and SliderValue public exports, add constituent export/registration without catalog identity.
- Public parts remain slider, slider-track, slider-range, slider-thumb, slider-label, slider-output; transparent Control/native-input binding introduces no catalog/presentation keys. Native input uses the established focusable infrastructure.
- Bounds canonical minimum/maximum retain min/max aliases on the same underlying values. Optional Output is explicit composition through its part contract; Label requires consumer content. Source wrapper's edge choice can be explicit in the curated example while API default remains Foundation center.

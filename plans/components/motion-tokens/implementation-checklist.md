## Architecture and reuse

- Component folder and responsibility boundaries: no new component; token values in `src/styles.css`; registry in `src/presentation/tokens.ts`; CSS timing helpers in `src/presentation/motion.ts`; JS timing resolution in the existing motion owner `src/foundation/motion.ts`; JS easing functions from `src/foundation/motion-easing.ts` (`parseEasing`).
- Supported exports / registration / constituent API impact: `TOKEN_FAMILIES`/`REQUIRED_TOKEN_ROLES` (public via `presentation/index.ts`) gain the motion family; `resolveMotionTiming` stays internal; no element registration changes.
- Public vocabulary / tokens / parts / presentation review: role names follow the existing `duration-*`/`easing-*` prefixes already in `styles.css` and docs; new names `duration-slow`, `easing-enter`, `easing-exit` checked against live vocabulary (no conflicting terms) and peer families (size scales use xs…lg; motion already uses fast/normal).

## Usage

Use a Checkbox for a yes-or-no choice that applies when the form is submitted, or for picking any number of options from a short list. For a setting that takes effect the moment it flips, use a Switch. The default slot is the inline label, and a press on it toggles the box; Enter never toggles, so a Checkbox does not compete with a form's submit key.

### Marketing consent

<Preview
  code={`<tp-field label="Email me product updates" description="About one email a month. Unsubscribe anytime.">
  <tp-checkbox name="updates" value="monthly"></tp-checkbox>
</tp-field>`}
/>

A Field names the Checkbox and carries its description and errors. With `required`, the box counts as filled only when it is checked, so a Field reports an unchecked consent box like any missing value.

### Notification channels

<Preview
  code={`<form id="checkbox-channels" style="display:grid;gap:var(--tp-space-3)">
  <tp-checkbox name="channels" value="email" default-checked>Email</tp-checkbox>
  <tp-checkbox name="channels" value="push">Push notifications</tp-checkbox>
  <tp-checkbox name="channels" value="sms" disabled>SMS (add a phone number first)</tp-checkbox>
  <tp-checkbox name="digest" value="weekly" unchecked-value="off">Weekly digest</tp-checkbox>
  <div style="display:flex;gap:var(--tp-space-2)">
    <tp-button type="submit" size="sm">Save</tp-button>
    <tp-button type="reset" size="sm" variant="outline">Reset</tp-button>
  </div>
  <output id="checkbox-channels-output" style="font-size:var(--tp-text-sm);color:var(--tp-muted-foreground)">Submit to see the form data.</output>
</form>`}
  script={`const form = document.getElementById('checkbox-channels');
form.addEventListener('submit', (event) => {
  event.preventDefault();
  const entries = [...new FormData(form)].map(([key, value]) => key + '=' + value);
  document.getElementById('checkbox-channels-output').textContent = entries.join(' · ') || 'Nothing submitted';
});`}
/>

Boxes that share a `name` submit one entry per checked box, so the server receives the list of chosen values. An unchecked box submits nothing unless it has an `unchecked-value`, for a server that expects an explicit off value. A disabled box leaves the tab order and the form data, and Reset restores each box's `default-checked`.

### Select all

<Preview
  code={`<fieldset id="checkbox-select-all" style="display:grid;gap:var(--tp-space-3);margin:0;padding:0;border:0">
  <legend style="padding:0;margin-block-end:var(--tp-space-3);font-weight:var(--tp-font-medium)">Export columns</legend>
  <tp-checkbox parent>All columns</tp-checkbox>
  <div style="display:grid;gap:var(--tp-space-3);padding-inline-start:var(--tp-space-6)">
    <tp-checkbox name="columns" value="name">Customer name</tp-checkbox>
    <tp-checkbox name="columns" value="email">Email</tp-checkbox>
    <tp-checkbox name="columns" value="plan">Plan</tp-checkbox>
    <tp-checkbox name="columns" value="revenue">Monthly revenue</tp-checkbox>
  </div>
</fieldset>`}
  script={`import { CheckboxGroupController } from '@tweakpad/ui';

await customElements.whenDefined('tp-checkbox');
new CheckboxGroupController(document.getElementById('checkbox-select-all'), {
  defaultValue: ['name', 'email'],
  allValues: ['name', 'email', 'plan', 'revenue'],
});`}
/>

A `CheckboxGroupController` bound to the fieldset keeps the group's value as a list: it shows the `parent` box as checked or mixed, and a press on it checks or clears every enabled child. Each child still submits under its own `name`; call `disconnect()` on the controller when the fieldset goes away. To manage a mixed box yourself, set `indeterminate`: a press then proposes checked, and your code clears the mixed state, because only it knows what the children hold. The mixed state is presentation only; the submitted value stays checked or unchecked.

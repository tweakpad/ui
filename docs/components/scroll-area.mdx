## Usage

A Scroll area keeps the browser's own scrolling (wheel, touch, keyboard, focus and scroll anchoring) and replaces only the visible scrollbars, so a panel, a sidebar list or a popover body scrolls like the page does while its tracks match the theme. Constrain its height or width; its content decides how far it scrolls. A `label` names the viewport as a region, which helps when it holds a lot of content.

`axis="both"` shows a track for each direction when content overflows both ways, like an image at full resolution or a wide document. The corner fills the square where the two tracks meet.

### Fading the edges

  script={`await customElements.whenDefined('tp-scroll-area');

document.getElementById('scroll-area-terms-top').addEventListener('click', () => {
  area.viewportElement?.scrollTo({ top: 0, behavior: 'smooth' });
});`}
/>

The host marks each edge past which content is hidden, so a style can fade or shadow exactly the edges that have more to show. Scrolling from code goes through the native viewport, `viewportElement`, with the standard `scrollTo` and `scrollTop`; there is no second scroll position to keep in sync.

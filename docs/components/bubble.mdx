## Usage

A Bubble presents one message; a Bubble group stacks consecutive messages from the same sender, so spacing follows who is speaking rather than each message. The application owns delivery, sender names and reaction counts. `align` is logical: `end` sits on the inline end and follows the writing direction. For a message with its author, avatar and timestamp around it, use Message.

### Reactions

<Preview
  align="stretch"
  code={`<div style="display:grid;gap:var(--tp-space-10);max-inline-size:36rem;padding-block:var(--tp-space-4)">
  <tp-bubble variant="default">
    The new onboarding flow is live for 10% of signups.
    <span slot="reactions" role="img" aria-label="Reactions: party popper and fire">🎉 🔥</span>
  </tp-bubble>
  <tp-bubble align="end" variant="tinted" reaction-side="block-start" reactions-align="start">
    Nice. Let's review conversion on Friday.
    <span slot="reactions" role="img" aria-label="Reaction: eyes">👀</span>
  </tp-bubble>
  <tp-bubble>
    Can someone own the follow-up survey?
    <tp-button slot="reactions" size="xs" variant="outline" aria-label="Like this message; 3 likes">Like · 3</tp-button>
  </tp-bubble>
</div>`}
/>

Reactions overlap the bubble's edge, so leave room around a message that has them. A summary is a named image; a reaction people can add is a Button whose name includes the count. `reaction-side` and `reactions-align` place the row independently of the message's own alignment.

### Long replies

<Preview
  align="stretch"
  code={`<div style="max-inline-size:36rem">
  <tp-bubble variant="subdued" label="Message from Priya">
    <p style="margin:0">Here's the summary from this morning's incident review. <a href="#long-replies">Open the full report</a></p>
    <tp-collapsible id="bubble-expand">
      <span slot="label">Show more</span>
      <p style="margin:0">Checkout errors started at 09:12 when the payments provider rotated its signing keys. Our webhook verifier cached the old key for up to an hour.</p>
      <p style="margin-block:var(--tp-space-2) 0">We shortened the cache to five minutes and added an alert on signature failures. No orders were lost; 41 customers saw a retry prompt.</p>
    </tp-collapsible>
  </tp-bubble>
</div>`}
  script={`await customElements.whenDefined('tp-collapsible');
const disclosure = document.getElementById('bubble-expand');
disclosure.partContracts = {
  'collapsible-label': { content: ({ open }) => (open ? 'Show less' : 'Show more') },
};
disclosure.partPresentation = {
  'collapsible-trigger': { styleHook: { 'padding-inline': '0', 'inline-size': 'fit-content' } },
  'collapsible-content-body': { styleHook: { 'padding-inline': '0' } },
};`}
/>

The content keeps its own semantics, so paragraphs and links work as anywhere else, and `label` names the message for assistive technology. A Collapsible inside the bubble keeps a long reply short in the thread; it owns the expansion and its button, and its label follows its state.

### Suggested replies

<Preview
  align="stretch"
  code={`<div id="bubble-replies" style="display:grid;gap:var(--tp-space-3);max-inline-size:36rem">
  <tp-bubble variant="default">Hi Sam, your order #10482 is out for delivery. Anything I can help with?</tp-bubble>
  <tp-bubble variant="outline" data-link>Track your package</tp-bubble>
  <tp-bubble-group data-suggestions>
    <tp-bubble variant="outline" align="end" data-reply>Change the delivery address</tp-bubble>
    <tp-bubble variant="outline" align="end" data-reply>Leave it with a neighbor</tp-bubble>
    <tp-bubble variant="outline" align="end" data-reply>Talk to a person</tp-bubble>
  </tp-bubble-group>
</div>`}
  script={`import { html } from 'lit';

await customElements.whenDefined('tp-bubble');
const thread = document.getElementById('bubble-replies');
thread.querySelector('[data-link]').partContracts = {
  'bubble-content': {
    renderDelegate: ({ bind, content }) => html\`<a href="#suggested-replies" \${bind}>\${content}</a>\`,
  },
};
for (const reply of thread.querySelectorAll('[data-reply]')) {
  reply.partContracts = {
    'bubble-content': {
      renderDelegate: ({ bind, content }) => html\`<button type="button" \${bind}>\${content}</button>\`,
    },
  };
  reply.addEventListener('click', () => {
    const sent = document.createElement('tp-bubble');
    sent.align = 'end';
    sent.variant = 'tinted';
    sent.textContent = reply.textContent;
    thread.querySelector('[data-suggestions]').replaceWith(sent);
  });
}`}
/>

A whole bubble can act: the `bubble-content` part contract renders the content as a native link or button, with `bind` on that element, so the bubble keeps its look and gains real link or button behavior. Here a picked reply is sent as the user's own message.

### Variants

<Preview
  align="stretch"
  code={`<div style="display:grid;gap:var(--tp-space-3);max-inline-size:36rem">
  <tp-bubble variant="default">Default</tp-bubble>
  <tp-bubble>Secondary</tp-bubble>
  <tp-bubble variant="subdued">Subdued</tp-bubble>
  <tp-bubble variant="tinted">Tinted</tp-bubble>
  <tp-bubble variant="outline">Outline</tp-bubble>
  <tp-bubble variant="ghost">Ghost</tp-bubble>
  <tp-bubble variant="destructive">Message failed to send. Tap to retry.</tp-bubble>
</div>`}
/>

Give each sender one treatment so the conversation reads at a glance: `ghost` for unframed assistant text that takes the full row, `destructive` for a delivery failure.

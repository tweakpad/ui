## Usage

Items are plain data, so the list is fed from script: set `defaultValue` (uncontrolled) or `value` (controlled) before the first render, with each item's `id` and `label`. Each drag hovers a preview order; a drop commits a new array, and Escape or a drop outside restores the committed order. Numeric and string item IDs remain distinct, including `0`, `''`, `1` and `'1'`. IDs must remain stable across reordering; an index is unsuitable as an identity.

### Keyboard

Every row has a named handle Button. Focus it, press Space or Enter to pick the item up, move it with the arrow keys, and press Space or Enter again to drop it; Escape cancels. A live region announces each step. Arrow keys choose a directional sortable destination. Tab/Shift+Tab finishes and continues normal traversal without delayed focus theft.

### Reading the value

`tp-value-change` fires with each proposed order and can be cancelled; `tp-value-commit` fires once the drop has settled. Read `value` then to save the order. A same-list change emits one change/commit pair; transfer emits one pair per changed lane. Hover, no-op and canceled/rejected drops emit no commit.

### Activation and feedback

By default only the handle starts a pointer drag, which keeps text in the row selectable. `activation="item"` lets the whole row start one, after a short delay or movement so clicks still work. The `feedback` property picks the drag feedback; `'clone'`, used here, leaves a translucent copy in the row's layout position while the item moves. Mouse handles activate immediately; touch waits 250 ms with 5 px tolerance. Ordinary item activation uses a 200 ms/10 px delay or distance strictly greater than 5 px. Nested controls retain their own interaction.

### Rich rows

`renderItem` returns the content of each row from its item and a context, so rows can carry Badges and their own actions; a control in the `actions` slot stays separately operable. The context's `preview` flag marks the copy shown while dragging. `renderOverlay` draws the row that follows the pointer. Preview content must not create live drag registrations. Use a custom overlay for opaque shadow components.

### Connected lists

Lists that share one `DragDropManager` from `@tweakpad/ui/drag-drop`, each with a unique `group`, can pass items between them, such as columns on a board. `moveItem()` performs the same atomic move from code, for example from a "Move to Ready" menu action. Configure each list before it first renders; here the script creates them. An empty list stays a drop target, and keyboard users can move an item into it with the arrow keys. A list without `manager` owns its manager. A supplied manager remains application-owned when a list disconnects. Dispose bindings and managers when their owning application is removed.

### One controlled owner

With `value` instead of `defaultValue`, the lists propose and your code decides. A move between lanes proposes one `tp-value-change` per lane, sharing `metadata.operationId`; stage both, then assign both values synchronously to accept the move. Leaving them unassigned rejects it. The exact typed ID order must match each proposal; fresh item objects with those IDs are accepted. Missing acknowledgment, veto, duplicates or incompatible normalization reject every lane. Library atomicity covers committed component values and commit notifications. Application stores must stage their own connected update; unrelated external side effects in listeners cannot be rolled back by the component.

Direct Foundation callbacks and `onValueChange` exceptions are observed and cancel the default action. Native DOM listener exceptions follow browser dispatch semantics and cannot reliably become vetoes; use `preventDefault()`, the common event cancellation API or a caught suspension rejection.

<Preview
  width="7"
  title="Controlled lanes"
  align="stretch"
  code={`<section
  id="drag-drop-list-owner">
  <tp-stack gap="4">
    <div
      data-lanes
      style="
        display: grid;
        grid-template-columns: repeat(auto-fit, minmax(min(100%, 16rem), 1fr));
        gap: var(--tp-space-4);
      "></div>
    <output
      data-status
      role="status"
      style="
        color: var(--tp-muted-foreground);
        font-size: var(--tp-text-sm);
        font-family: var(--tp-font-mono);
      "></output>
  </tp-stack>
</section>`}
  script={`import { DragDropManager } from '@tweakpad/ui/drag-drop';

const root = document.querySelector('#drag-drop-list-owner');
const status = root.querySelector('[data-status]');
const manager = new DragDropManager();
// The application's state; the lists only render it.
let state = {
  todo: [{ id: 'copy', label: 'Write launch copy' }, { id: 'qa', label: 'Regression pass' }],
  done: [{ id: 'pricing', label: 'Pricing page' }],
};
const show = () => (status.textContent = JSON.stringify({ todo: state.todo.map((i) => i.id), done: state.done.map((i) => i.id) }));
const staged = new Map();
const lists = Object.keys(state).map((group) => {
  const list = document.createElement('tp-drag-drop-list');
  Object.assign(list, { manager, group, label: group === 'todo' ? 'To do' : 'Done', variant: 'outline', value: state[group] });
  list.addEventListener('tp-value-change', (event) => {
    if (event.target !== list || event.defaultPrevented || event.detail.cancelled) return;
    const { operationId, sourceGroup, destinationGroup } = event.detail.metadata;
    const proposal = staged.get(operationId) ?? new Map();
    staged.set(operationId, proposal.set(group, event.detail.value));
    if ([sourceGroup, destinationGroup].every((lane) => proposal.has(lane))) {
      for (const member of lists) if (proposal.has(member.group)) member.value = proposal.get(member.group);
      staged.delete(operationId);
    }
  });
  list.addEventListener('tp-value-commit', (event) => {
    if (event.target !== list) return;
    state = Object.fromEntries(lists.map((member) => [member.group, member.value]));
    show();
  });
  root.querySelector('[data-lanes]').append(list);
  return list;
});
show();`}
/>

### Authorizing a drop

The manager's `monitor` reports each operation. Call `event.suspend()` inside `dragend` to hold the drop: the feedback stays where it was dropped and no value changes until you call `resume()` or `abort()` on the returned handle, for example after a permission check or a server call. `settled` reports the outcome. Repeated calls return one handle; the first result wins. Explicit cancellation, disconnect or manager destruction aborts the decision; no timer silently accepts it. Use `try/catch` around application work and abort on failure.

<Preview
  width="7"
  title="Approve before committing"
  align="stretch"
  code={`<section
  id="drag-drop-list-approve">
  <tp-stack gap="4">
    <div
      data-lanes
      style="
        display: grid;
        grid-template-columns: repeat(auto-fit, minmax(min(100%, 16rem), 1fr));
        gap: var(--tp-space-4);
      "></div>
    <div data-decision hidden>
      <tp-stack direction="row" gap="2" wrap="wrap">
        <tp-button data-approve size="sm">Approve move</tp-button>
        <tp-button data-reject size="sm" variant="outline">Reject</tp-button>
      </tp-stack>
    </div>
    <output
      data-status
      role="status"
      style="color: var(--tp-muted-foreground); font-size: var(--tp-text-sm)">Moving a teammate between teams needs approval.</output
    >
  </tp-stack>
</section>`}
  script={`import { DragDropManager } from '@tweakpad/ui/drag-drop';

const root = document.querySelector('#drag-drop-list-approve');
const status = root.querySelector('[data-status]');
const controls = root.querySelector('[data-decision]');
const manager = new DragDropManager();
for (const [group, label, items] of [
  ['design', 'Design team', [{ id: 'maya', label: 'Maya Chen' }, { id: 'omar', label: 'Omar Haddad' }]],
  ['platform', 'Platform team', [{ id: 'grace', label: 'Grace Kim' }]],
]) {
  const list = document.createElement('tp-drag-drop-list');
  Object.assign(list, { manager, group, label, variant: 'outline', defaultValue: items });
  root.querySelector('[data-lanes]').append(list);
}
let decision;
manager.monitor.addEventListener('dragend', (event) => {
  if (event.canceled) return;
  decision = event.suspend();
  controls.hidden = false;
  status.textContent = 'Waiting for approval…';
});
manager.monitor.addEventListener('settled', (event) => {
  decision = undefined;
  controls.hidden = true;
  status.textContent = 'Drop ' + event.outcome + '.';
});
root.querySelector('[data-approve]').addEventListener('click', () => decision?.resume());
root.querySelector('[data-reject]').addEventListener('click', () => decision?.abort());`}
/>

### Selection

The list keeps no selection of its own. `isItemSelected` tells it which rows show as selected, from the item and its index, and the context's `selected` flag carries the answer to `renderItem`. Call `requestUpdate()` on the list when your selection changes. A selected row keeps its place in drags and keyboard moves like any other.

### Landing line

`drop-indicator="line"` keeps the items still while a row is dragged: a line between two items marks where it lands, and the items make room only on the drop. Keyboard moves still show the new order at each step. `--tp-drag-drop-list-drop-indicator-color` and `--tp-drag-drop-list-drop-indicator-size` restyle the line.

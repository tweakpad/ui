## Usage

Each child is a full Menu with a `value`, so items, checks, radio choices and submenus work exactly as they do in a single Menu. The bar adds one shared open menu: opening one closes the other, and once a menu is open, hovering another trigger switches to it. Name the bar with `aria-label`. Use it for application commands, as in an editor; site links belong in a Navigation menu.

A dense editing surface takes small triggers. Whatever their size, the bar is a single stop in the tab order: the arrow keys move between its triggers, and the arrow down opens the focused menu.

### Following the open menu

<Preview
  code={`<div style="display:grid;gap:var(--tp-space-3);justify-items:start">
  <tp-menubar id="menubar-mail" aria-label="Mail">
    <tp-menu value="message" label="Message">
      <tp-button slot="trigger" variant="ghost">Message</tp-button>
      <tp-menu-item value="reply">Reply</tp-menu-item>
      <tp-menu-item value="forward">Forward</tp-menu-item>
    </tp-menu>
    <tp-menu value="mailbox" label="Mailbox">
      <tp-button slot="trigger" variant="ghost">Mailbox</tp-button>
      <tp-menu-item value="archive">Archive</tp-menu-item>
      <tp-menu-item value="junk">Move to junk</tp-menu-item>
    </tp-menu>
  </tp-menubar>
  <output id="menubar-mail-output" style="color:var(--tp-muted-foreground);font-size:var(--tp-text-sm)">No menu open</output>
</div>`}
  script={`const bar = document.getElementById('menubar-mail');
const output = document.getElementById('menubar-mail-output');
bar.addEventListener('tp-value-change', (event) => {
  if (event.target !== bar) return;
  output.textContent = event.detail.value ? \`Open: \${event.detail.value}\` : 'No menu open';
});`}
/>

Each change of the open menu is proposed with a cancelable `tp-value-change` carrying the menu's `value`, or an empty string when everything closes. The menus' own items send their change events through the bar too, so check the event's target.

A menu that does not apply yet, such as review tools before a document is shared, is disabled on its own and keeps its place in the bar. `disabled` on the bar disables every trigger without overwriting each menu's own state.

## Keyboard

| Key | Action |
| --- | --- |
| <Keys keys="right" /> <Keys keys="left" /> | Moves to the next or previous trigger, following the writing direction; with a menu open, opens that trigger's menu instead. |
| <Keys keys="home" /> <Keys keys="end" /> | Moves to the first or the last trigger. |
| <Keys keys="down" /> <Keys keys="enter" /> <Keys keys="space" /> | Opens the focused trigger's menu. |
| <Keys keys="esc" /> | Closes the open menu and returns focus to its trigger. |

## Usage

`tp-form` renders a native `form` in light DOM and coordinates the Fields and form-associated controls inside it. Submitting validates every Field, focuses the first invalid control and blocks submission until the errors are fixed. A valid submission calls `onFormSubmit` with the named values and prevents navigation; without a callback the native submission proceeds. The Form does not send anything itself, so transport and persistence stay in your code.

Put submit and reset Buttons in an element with `slot="actions"` to get the footer layout. Native attributes such as `action`, `method` and `name` are forwarded to the inner form.

`no-autofill` opts every contained text-entry control (Input, Text area, Select and its query, One-time code field) out of browser and password-manager autofill. Use it for forms about other people or for app data, not for the user's own sign-in, address or payment details.

An optional container with `slot="actions"` receives the actions part; `slot="error-summary"` receives the summary part. Summary text and links remain application content. Unnamed fields validate without entering `values`; duplicate names aggregate in DOM registration order.

### Control types

Every form-associated control takes part the same way: Select, Checkbox, Radio group and Switch validate `required` through their Field and submit under their `name`. A horizontal Field suits the Switch.

### Validation timing

By default errors appear on submit. Set `validationTiming` to `on-blur` or `on-change` to validate earlier for every Field in the form; a Field's own `validation-mode` still wins.

### Server errors

Assign `errors`, a record of field name to message, to show results from your server. They stay until you replace them, so clear them when the user edits the value.

<Preview
  title="External errors"
  align="stretch"
  code={`<tp-form id="form-demo-errors" aria-label="Claim workspace URL" style="max-inline-size:24rem">
  <tp-field label="Workspace URL" description="acme.app/your-team">
    <tp-input name="slug" required default-value="design"></tp-input>
  </tp-field>
  <div slot="actions"><tp-button type="submit">Claim URL</tp-button></div>
</tp-form>`}
  script={`const form = document.querySelector('#form-demo-errors');
form.errors = { slug: 'design is already taken. Try design-team.' };
form.addEventListener('tp-value-change', () => { form.errors = {}; });
form.onFormSubmit = (values) => {
  if (values.slug === 'design') form.errors = { slug: 'design is already taken. Try design-team.' };
};`}
/>

### Cross-field validation

A Field's `validator` receives its value and every named value in the form, which covers rules that compare two fields.

<Preview
  title="Matching passwords"
  align="stretch"
  code={`<tp-form id="form-demo-match" aria-label="Change password" style="max-inline-size:24rem">
  <tp-field label="New password">
    <tp-input name="password" type="password" required autocomplete="new-password"></tp-input>
  </tp-field>
  <tp-field id="form-demo-match-confirm" label="Confirm password">
    <tp-input name="confirm" type="password" required autocomplete="new-password"></tp-input>
  </tp-field>
  <div slot="actions"><tp-button type="submit">Update password</tp-button></div>
  <output id="form-demo-match-output" style="color:var(--tp-muted-foreground)"></output>
</tp-form>`}
  script={`const form = document.querySelector('#form-demo-match');
document.querySelector('#form-demo-match-confirm').validator = (value, values) =>
  value === values.password ? null : 'Passwords must match.';
form.onFormSubmit = () => {
  document.querySelector('#form-demo-match-output').textContent = 'Password updated.';
};`}
/>

### Async validation

A `validator` may return a promise, but submission does not wait for it. To wait, cancel `tp-submit` and await `event.detail.validationRun.completion` before saving.

<Preview
  title="Wait for async checks"
  align="stretch"
  code={`<tp-form id="form-demo-async" aria-label="Choose a username" style="max-inline-size:24rem">
  <tp-field id="form-demo-async-field" label="Username" description="Try maya, which is already taken.">
    <tp-input name="username" required default-value="maya"></tp-input>
  </tp-field>
  <div slot="actions"><tp-button type="submit">Save username</tp-button></div>
  <output id="form-demo-async-output" style="color:var(--tp-muted-foreground);font-size:var(--tp-text-sm)"></output>
</tp-form>`}
  script={`const form = document.querySelector('#form-demo-async');
const output = document.querySelector('#form-demo-async-output');
// Stands in for a request to your server.
document.querySelector('#form-demo-async-field').validator = (value) =>
  new Promise((resolve) => {
    setTimeout(() => resolve(value === 'maya' ? 'maya is already taken.' : null), 600);
  });
form.addEventListener('tp-submit', async (event) => {
  event.preventDefault();
  output.textContent = 'Checking availability…';
  const { validationRun, values } = event.detail;
  const result = await validationRun.completion;
  output.textContent = result.status === 'valid' ? \`Saved @\${values.username}.\` : '';
});`}
/>

### Repeated fields

Fields can be added and removed while the form is open; each registers as it connects. Controls that share a `name` submit together, in document order.

<Preview
  title="Repeated emails"
  align="stretch"
  code={`<tp-form id="form-demo-repeat" aria-label="Invite teammates" style="max-inline-size:28rem">
  <div id="form-demo-repeat-list" style="display:grid;gap:var(--tp-space-4)">
    <tp-field label="Email 1">
      <tp-input-group>
        <tp-input name="email" type="email" required placeholder="jordan@acme.com"></tp-input>
        <tp-button slot="action" type="button" variant="ghost" data-remove disabled>Remove</tp-button>
      </tp-input-group>
    </tp-field>
  </div>
  <tp-button id="form-demo-repeat-add" type="button" variant="outline" style="justify-self:start">Add another email</tp-button>
  <div slot="actions"><tp-button type="submit">Send invites</tp-button></div>
  <output id="form-demo-repeat-output" style="color:var(--tp-muted-foreground);font-family:var(--tp-font-mono);font-size:var(--tp-text-sm)"></output>
</tp-form>`}
  script={`const form = document.querySelector('#form-demo-repeat');
const list = document.querySelector('#form-demo-repeat-list');
const add = document.querySelector('#form-demo-repeat-add');
const sync = () => {
  const fields = [...list.querySelectorAll('tp-field')];
  fields.forEach((field, index) => {
    field.label = 'Email ' + (index + 1);
    field.querySelector('[data-remove]').disabled = fields.length === 1;
  });
  add.disabled = fields.length >= 5;
};
add.addEventListener('click', () => {
  const field = document.createElement('tp-field');
  field.innerHTML = \`<tp-input-group>
    <tp-input name="email" type="email" required></tp-input>
    <tp-button slot="action" type="button" variant="ghost" data-remove>Remove</tp-button>
  </tp-input-group>\`;
  list.append(field);
  sync();
});
list.addEventListener('click', (event) => {
  const remove = event.target.closest('[data-remove]');
  if (remove) (remove.closest('tp-field').remove(), sync());
});
form.onFormSubmit = (values, { data }) => {
  document.querySelector('#form-demo-repeat-output').textContent = JSON.stringify(data.getAll('email'));
};`}
/>

### Submission policy

`submissionPolicy` can disable the submit Buttons while the form is invalid or while async validation is pending. Disabled actions are hard to discover, so prefer the default `always-enabled` unless the form is short and the requirements are obvious.

Pending policy disables only submit controls and restores only the disabled state that the policy applied. An authored disabled action stays disabled.

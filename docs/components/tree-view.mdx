## Usage

Nest `tp-tree-item` elements: text forms the label, `slot="leading"` and `slot="trailing"` hold marks and actions, and nested items are the children. `default-expanded` and `default-value` take JSON arrays of item values and apply before the first render, so the tree appears already open without change events. The tree is one tab stop; arrow keys move, Right expands and Left collapses or returns to the parent.

The tab stop starts on the first visible selected item. A virtualized tree scrolls its first window to that item.

Forms: with `name`, each selected identifier is submitted as one entry, in tree order. Reset restores the default selection; `required` is invalid while nothing is selected.

### Multiple selection with checkboxes

`selection-mode="multiple"` with `checkbox-selection` shows a checked indicator in every row. `selection-propagation` cascades a parent's selection to its descendants and derives mixed parents.

Multiple: pressing or Space toggles; Shift extends from the anchor; Control/Command toggles without moving the anchor; Shift+Arrow extends while moving; Shift+Space selects the range; Control+Shift+Home/End selects to an end; Control+A selects every visible enabled item.

Enter or a press fires a cancelable `tp-action` with the item's value, separately from selection. Use it to open a file or navigate; canceling it keeps the press from selecting or expanding.

### Records

For large or data-driven trees, set `defaultItems` (or controlled `items`) to records of `{ id, label, children }`. Records mode renders flat rows, which enables `virtualized` and `reorderable`; give a virtualized tree a block size.

The default record shape is `{ id, label, children?, hasChildren?, disabled? }`; any other shape works through `getItemId`, `getItemLabel`, `getItemChildren`, `isItemDisabled` and `itemHasChildren`. Identifiers are strings, unique within the tree. A repeated identifier keeps its first item and raises one `tp-diagnostic` (`tree-view-duplicate:<id>`).

Drag a handle, or press Control+Enter (Command+Enter) on an item and move it with the arrow keys. Each move is proposed through a cancelable `tp-items-change`.

- Pointer: drag the handle. Rows move as you drag; moving sideways changes the level by one indentation step per `--tp-tree-view-indent`.
- Keyboard: on a focused item press Control+Enter (Command+Enter). Up/Down move it, Left/Right change its level, Space or Enter drop, Escape cancels. Each step is announced with the level and parent.

An item can land before, after or inside any item, never inside itself. Every move is proposed through the cancelable `tp-items-change` with `detail.metadata.move = { itemId, fromParentId, fromIndex, toParentId, toIndex }` and the next records in `detail.value`; with `items` controlled, apply them yourself. Parents whose children change are rebuilt with `withItemChildren(record, children)` (default: `{ ...record, children }`); every other record keeps its identity. `moveItem(id, { parentId, index })` proposes a move from code.

A tree you drag yourself can reuse the level rule. `projectDepth(rows, index, requestedDepth, canNest)` from `@tweakpad/ui` takes the visible rows in order as `{ id, depth, parentId }` (the dragged row's descendants removed), the dragged row's index and the depth the pointer asks for. It returns `{ depth, minDepth, maxDepth, parentId, vetoed }`: the depth clamped between the next row's depth and one more than the previous row's, and the parent at that depth. The optional `canNest(parent, source)` decides whether a projected parent accepts the dragged row; the depth is then lowered to the deepest level whose parent accepts it, the top level is always accepted, and `vetoed` is true when no level within the clamp is. `dragDepth(offset, indentation, rtl)` turns an inline pointer offset into depth steps, mirrored for right-to-left.

### Large trees

`virtualized` mounts only the rows near the viewport, so tens of thousands of records stay fast. Keyboard navigation, typeahead and `focusItem()` mount a row before focusing it. Give the tree a block size so it has a viewport to fill.

Give the tree a height (`block-size`, or a flex/grid track); without one it uses the nearest scrolling ancestor. `item-size` is the row estimate in pixels (default: the first measured row, which includes the separation between rows); rows are measured as they mount, so variable heights work. The focused row stays mounted.

### Controlled

To own selection and expansion yourself, set `items`, `value` and `expanded` and write back each accepted proposal from `tp-value-change` and `tp-expanded-change`. The tree then shows exactly your state; the methods still work and go through the same events.

### Loading children on demand

A record with `hasChildren: true` shows a chevron before its children exist. On first expansion the tree calls `loadChildren(item, { signal })`, shows a loading row while it waits, and inserts the records it returns. The signal aborts if the item is removed or the tree disconnects first, and a failed load offers a retry.

<Preview
  title="Lazy folders"
  code={`<tp-tree-view id="tree-view-lazy" label="Shared drive" size="sm" style="inline-size:18rem"></tp-tree-view>`}
  script={`await customElements.whenDefined('tp-tree-view');
const tree = document.querySelector('#tree-view-lazy');
const folders = {
  contracts: ['Northwind MSA 2026.pdf', 'Contoso NDA.pdf', 'Fabrikam renewal.pdf'],
  invoices: ['September.xlsx', 'August.xlsx'],
};
tree.defaultItems = [
  { id: 'contracts', label: 'Contracts', hasChildren: true },
  { id: 'invoices', label: 'Invoices', hasChildren: true },
  { id: 'budget', label: 'Budget 2027.xlsx' },
];
tree.loadChildren = async (item, { signal }) => {
  await new Promise((resolve) => setTimeout(resolve, 800));
  if (signal.aborted) return [];
  return folders[item.id].map((name) => ({ id: \`\${item.id}/\${name}\`, label: name }));

`reloadChildren(id)` discards loaded children so the next expansion fetches them again.

Mark items with `hasChildren` (records) or `has-children` (markup) and set `loadChildren`:

<Code code={`tree.loadChildren = async (item, { signal }) => {

### Expanding from code

`expandAll()`, `collapseAll()`, `expandItem(id)` and `collapseItem(id)` change expansion through the same `tp-expanded-change` as the keyboard. `revealItem(id, { focus: true })` opens the item's ancestors, scrolls it into view and focuses it.

`expandAll({ load: true })` also loads and expands their descendants, breadth-first. Identifiers of items that do not exist yet are kept and take effect when the items appear, so a default can name items that load lazily.

### Keyboard

| Key        | Action                                             |
| ---------- | -------------------------------------------------- |
| Down / Up  | Next / previous visible item                       |
| Right      | Expand; on an expanded item, go to its first child |
| Left       | Collapse; otherwise go to the parent               |
| Home / End | First / last visible item                          |
| `*`        | Expand all siblings                                |
| Enter      | Activate (`tp-action`); selects in single mode     |
| Space      | Select (single) or toggle (multiple)               |
| Letters    | Typeahead over visible labels                      |

Right and Left swap in right-to-left documents. Keys typed into editable content inside an item are left alone, and controls placed in an item (a Button in `trailing`, for example) keep their own presses, Enter and Space.

The tree is one tab stop: the last focused item, else the first selected item, else the first enabled item. When the focused item is hidden by a collapse, focus moves to the collapsed ancestor; when it is removed, focus moves to the next visible item, else the previous one.

### Accessibility

The root is a `tree` named by `label` (or `aria-label`), multiselectable in multiple mode. Each item is a `treeitem` with level, position, set size, expanded, selected, checked and busy states. There is one tab stop; arrows move focus. Indent, chevron and checked indicator are hidden from assistive technology. Loading, errors and reorder steps are announced politely. Reorderable items describe their keyboard shortcut.

### Motion

Rapid reversal turns around from the current height; bulk changes (`expandAll`, controlled updates with several items) and very large expansions apply instantly.

## Usage

Use a Tree view for a hierarchy people explore: files and folders, a document outline, nested categories or permissions. Nest `tp-tree-item` elements: text forms the label, the `leading` and `trailing` slots hold marks and actions, and nested items are the children. The whole tree is one tab stop and the arrow keys move between items, so it behaves as a single widget rather than a long run of links. For site navigation with a few levels of links, prefer Navigation panel; for a single level of options, a list or a Select.

  <tp-tree-item value="billing">
    Billing
    <tp-tree-item value="invoices">View invoices</tp-tree-item>
    <tp-tree-item value="payment">Manage payment methods</tp-tree-item>
  </tp-tree-item>
  <tp-tree-item value="projects">
    Projects
    <tp-tree-item value="create">Create projects</tp-tree-item>
    <tp-tree-item value="archive">Archive projects</tp-tree-item>
  </tp-tree-item>
  <tp-tree-item value="admin" disabled>Workspace admin</tp-tree-item>
</tp-tree-view>`}
/>

Multiple selection with a checkbox on each row makes the selection visible at a glance, and propagation lets a parent grant or revoke a whole group: Projects shows checked because both of its children are, Billing mixed because only one is. A disabled item stays focusable, so people can still read it, but input never selects it.

### Opening documents

<Preview
  code={`<div style="display:grid;gap:var(--tp-space-3);justify-items:start">
  <tp-tree-view id="tree-view-handbook" label="Handbook" expansion-trigger="indicator" default-expanded='["engineering"]' style="inline-size:16rem">
    <tp-tree-item value="engineering">
      Engineering
      <tp-tree-item value="on-call">On-call rotation</tp-tree-item>
      <tp-tree-item value="code-review">Code review</tp-tree-item>
    </tp-tree-item>
    <tp-tree-item value="people">People</tp-tree-item>
  </tp-tree-view>
  <span id="tree-view-handbook-status" style="color:var(--tp-muted-foreground);font-size:var(--tp-text-sm)">Nothing opened yet</span>
</div>`}
  script={`const tree = document.getElementById('tree-view-handbook');
const status = document.getElementById('tree-view-handbook-status');
tree.addEventListener('tp-action', (event) => {
  status.textContent = 'Opened ' + event.detail.item.labelText;
});`}
/>

A press or Enter on an item dispatches a cancelable `tp-action`, separate from selection: open the document, navigate or start an edit there, and cancel the event to keep the press from selecting or expanding. Here Engineering is a section with its own page, so `expansion-trigger="indicator"` reserves the row for opening it and expands only from the chevron.

### Rows from records

<Preview
  code={`<div id="tree-view-design-system" style="display:grid;gap:var(--tp-space-3);justify-items:start">
  <span id="tree-view-design-system-status" style="color:var(--tp-muted-foreground);font-size:var(--tp-text-sm)">Press a file to open it</span>
</div>`}
  script={`import { html } from 'lit';
import { folderIcon } from '@tweakpad/ui/icons/folder';
import { folderOpenIcon } from '@tweakpad/ui/icons/folder-open';
import { fileTextIcon } from '@tweakpad/ui/icons/file-text';

// Records apply before the tree first renders, so it is configured before it connects.
const tree = document.createElement('tp-tree-view');
tree.label = 'Design system';
tree.size = 'sm';
tree.reorderable = true;
tree.style.inlineSize = '18rem';
tree.defaultExpanded = ['tokens', 'components'];
tree.defaultItems = [
  { id: 'tokens', label: 'tokens', children: [
    { id: 'color.json', label: 'color.json' },
    { id: 'spacing.json', label: 'spacing.json' },
  ] },
  { id: 'components', label: 'components', children: [
    { id: 'button.tsx', label: 'button.tsx' },
    { id: 'dialog.tsx', label: 'dialog.tsx' },
    { id: 'select.tsx', label: 'select.tsx' },
  ] },
  { id: 'changelog.md', label: 'changelog.md' },
];
tree.renderItem = (item, state) => html\`<tp-icon slot="leading" .icon=\${state.expandable ? (state.expanded ? folderOpenIcon : folderIcon) : fileTextIcon}></tp-icon>\${item.label}\${
  item.children ? html\`<tp-badge slot="trailing" variant="secondary">\${item.children.length}</tp-badge>\` : ''
}\`;
tree.canDrop = (move) => move.toParentId === null || !/\\.\\w+$/.test(move.toParentId);
const status = document.getElementById('tree-view-design-system-status');
tree.addEventListener('tp-action', (event) => {
  status.textContent = 'Opened ' + event.detail.value;
});
document.getElementById('tree-view-design-system').prepend(tree);`}
/>

When the hierarchy comes from data, give the tree records with an id, a label and children, and `renderItem` draws each row from the record and its state: the folder icon opens while expanded, and a Badge counts the children. Records also make the tree `reorderable`: people drag the handle, or pick an item up from the keyboard, and each move is proposed through a cancelable `tp-items-change`. `canDrop` vetoes moves before they are offered, here any move into a file.

### Large trees

<Preview
  code={`<div id="tree-view-logs"></div>`}
  script={`// Records apply before the tree first renders, so it is configured before it connects.
const tree = document.createElement('tp-tree-view');
tree.label = 'Log archive';
tree.virtualized = true;
tree.size = 'sm';
tree.style.cssText = 'inline-size:18rem;block-size:16rem';
const months = ['January', 'February', 'March', 'April', 'May', 'June', 'July', 'August', 'September', 'October', 'November', 'December'];
tree.defaultItems = [2024, 2025, 2026].map((year) => ({
  id: String(year),
  label: String(year),
  children: months.map((month, m) => ({
    id: year + '-' + (m + 1),
    label: month,
    children: Array.from({ length: 28 }, (_, d) => ({
      id: year + '-' + (m + 1) + '-' + (d + 1),
      label: month + ' ' + (d + 1) + ' · 24 log files',
      children: Array.from({ length: 24 }, (_, h) => ({
        id: year + '-' + (m + 1) + '-' + (d + 1) + '-' + h,
        label: String(h).padStart(2, '0') + ':00.log',
      })),
    })),
  })),
}));
tree.defaultExpanded = ['2026', '2026-10', '2026-10-14'];
document.getElementById('tree-view-logs').append(tree);`}
/>

`virtualized` keeps only the rows near the viewport in the document, so this archive of about 25,000 records stays fast; give the tree a block size so it has a viewport. Keyboard navigation and typeahead mount a row before focusing it, so nothing feels different to the reader.

### Loading children on demand

<Preview
  code={`<div id="tree-view-drive"></div>`}
  script={`const tree = document.createElement('tp-tree-view');
tree.label = 'Shared drive';
tree.size = 'sm';
tree.style.inlineSize = '18rem';
const folders = {
  contracts: ['Northwind MSA 2026.pdf', 'Contoso NDA.pdf', 'Fabrikam renewal.pdf'],
  invoices: ['September.xlsx', 'August.xlsx'],
};
tree.defaultItems = [
  { id: 'contracts', label: 'Contracts', hasChildren: true },
  { id: 'invoices', label: 'Invoices', hasChildren: true },
  { id: 'budget', label: 'Budget 2027.xlsx' },
];
tree.loadChildren = async (item, { signal }) => {
  await new Promise((resolve) => setTimeout(resolve, 800));
  if (signal.aborted) return [];
  return folders[item.id].map((name) => ({ id: item.id + '/' + name, label: name }));
};
document.getElementById('tree-view-drive').append(tree);`}
/>

An item that declares children shows a chevron before they exist. On its first expansion the tree calls `loadChildren`, shows a loading row while it waits and inserts what it returns; a failure shows a retry. `reloadChildren` discards loaded children so the next expansion fetches them again.

### State owned by the application

<Preview
  code={`<div style="display:grid;gap:var(--tp-space-3);justify-items:start">
  <div id="tree-view-help"></div>
  <div style="display:flex;align-items:center;gap:var(--tp-space-3)">
    <tp-button id="tree-view-help-reveal" variant="outline" size="sm">Reveal selection</tp-button>
    <span id="tree-view-help-status" style="color:var(--tp-muted-foreground);font-size:var(--tp-text-sm)">Selected: Refund policy</span>
  </div>
</div>`}
  script={`// Controlled state is set before the tree first renders, so it is configured before it connects.
const tree = document.createElement('tp-tree-view');
tree.label = 'Help center';
tree.size = 'sm';
tree.style.inlineSize = '18rem';
const status = document.getElementById('tree-view-help-status');
const state = { value: ['refunds'], expanded: [] };
tree.items = [
  { id: 'account', label: 'Account', children: [
    { id: 'password', label: 'Reset your password' },
    { id: 'two-factor', label: 'Two-factor authentication' },
  ] },
  { id: 'billing', label: 'Billing', children: [
    { id: 'invoices', label: 'Download invoices' },
    { id: 'policies', label: 'Policies', children: [
      { id: 'refunds', label: 'Refund policy' },
      { id: 'cancellation', label: 'Cancellation' },
    ] },
  ] },
];
const labels = {};
const index = (items) => items.forEach((item) => {
  labels[item.id] = item.label;
  if (item.children) index(item.children);
});
index(tree.items);
tree.value = state.value;
tree.expanded = state.expanded;
tree.addEventListener('tp-value-change', (event) => {
  state.value = event.detail.value;
  tree.value = state.value;
  const [id] = state.value;
  status.textContent = id ? 'Selected: ' + labels[id] : 'Nothing selected';
});
tree.addEventListener('tp-expanded-change', (event) => {
  state.expanded = event.detail.value;
  tree.expanded = state.expanded;
});
document.getElementById('tree-view-help').append(tree);
document.getElementById('tree-view-help-reveal').addEventListener('click', () => {
  tree.revealItem(state.value[0] ?? 'refunds', { focus: true });
});`}
/>

When a router or a store owns the selection and the open groups, set `value` and `expanded` (and `items`, for records) and publish back each proposal you accept from `tp-value-change` and `tp-expanded-change`; the tree then shows exactly your state. The methods go through the same proposals: the selected article starts hidden inside collapsed groups, and `revealItem` expands its ancestors, scrolls it into view and focuses it, while `expandAll` and `collapseAll` open or close everything at once.

## Keyboard

| Key | Action |
| --- | --- |
| <Keys keys="down" /> <Keys keys="up" /> | Focus the next or previous visible item; with <Keys keys="shift" /> in multiple selection, extend the selection |
| <Keys keys="right" /> | Expand a collapsed parent, or focus its first child |
| <Keys keys="left" /> | Collapse an expanded parent, or focus the parent item |
| <Keys keys="home" /> <Keys keys="end" /> | Focus the first or last visible item |
| <Keys keys="enter" /> | Activate the item |
| <Keys keys="space" /> | Toggle the item's selection; with <Keys keys="shift" />, select the range from the last toggled item |
| <Keys keys="*" /> | Expand every sibling of the focused item |
| <Keys keys="mod+a" /> | Select every item, in multiple selection |
| <Keys keys="mod+enter" /> | Pick up the item to move it in a reorderable tree; the arrows then move it, Enter or Space drops it and Escape cancels |
| Typing | Focus the next item whose label starts with the typed text |

## Usage

Each value is a native range input inside a visual thumb, so keyboard, form and assistive-technology behavior come from the platform. `label` shows a visible label and names the control. A live readout is opt-in: give the `slider-output` part a `content` resolver, as above, and it shares the header with the label. A `label` string, `slot="label"` content or a `slider-label` part contract enables the Label. A `slot="value"` or a `slider-output` part contract enables Output. Output has `aria-live="off"` and references every Thumb input ID.

A space-separated `default-value` creates one thumb per value. `min-steps-between-values` keeps thumbs apart, and `thumb-collision-behavior` chooses whether a thumb pushes, swaps with or stops at its neighbor. `format` takes `Intl.NumberFormatOptions` for the readout and the spoken value; the submitted value stays numeric. Use distinct names such as “Minimum budget” and “Maximum budget” for ranges.

### Multiple thumbs and collisions

Any number of values gives one thumb each, and every thumb is its own tab stop. When a moving thumb meets its neighbor, `thumb-collision-behavior="push"` moves the neighbor along, `swap` lets it pass and trade places, and `none` stops it at the `min-steps-between-values` gap. `push` moves adjacent enabled Thumbs while preserving separation; reversing the active Thumb retains values already pushed. `swap` exchanges logical Thumb identities and retains focus/drag ownership.

### Controlled

Set `value` to own the values and accept each proposal in `onValueChange`. Your code can then change the value from outside, such as restoring a preset; `step` and `large-step` work in the same fractional units. The mode stays fixed for the lifetime of the element.

<Preview
  title="Controlled range"
  align="stretch"
  script={`const sampling = document.querySelector('#slider-demo-sampling');
sampling.onValueChange = (event) => {
  if (!event.defaultPrevented && !event.detail.cancelled) sampling.value = event.detail.value;
};
sampling.partContracts = {
  'slider-output': { content: (state) => state.formattedValues.join(' – ') },
};
document.querySelector('#slider-demo-sampling-reset').addEventListener('click', () => {
  sampling.value = [0.3, 0.7];
});`}
  code={`<div style="display:grid;gap:var(--tp-space-4);justify-items:start;max-inline-size:22rem;margin-inline:auto">
  <tp-slider id="slider-demo-sampling" label="Temperature window" value="0.3 0.7" minimum="0" maximum="1" step="0.1" large-step="0.2" style="inline-size:100%"></tp-slider>
  <tp-button id="slider-demo-sampling-reset" variant="outline" size="sm">Restore defaults</tp-button>
</div>`}
/>

For controlled sliders, accept proposals synchronously through `value`, as shown above. Debouncing that acceptance introduces an actual delay; defer expensive work separately or use `tp-value-commit` for work needed only after release.

### Steps

<Preview
  title="Step and large step"
  align="stretch"
  code={`<div style="display:grid;gap:var(--tp-space-6);max-inline-size:22rem;margin-inline:auto">
  <tp-slider label="Team size" default-value="20" minimum="0" maximum="100" step="10"></tp-slider>
  <tp-slider label="Opacity" default-value="0.8" minimum="0" maximum="1" step="0.01" large-step="0.1"></tp-slider>

/>

Values snap to `step` from `minimum`. Arrow keys move one step; Page Up, Page Down and Shift with an arrow move by `large-step`. On wide tracks a smaller step makes dragging feel continuous. The numeric value, Output and Thumb remain synchronized. Slider does not animate between discrete values or accept `step="any"`. Invalid or infeasible configuration emits `tp-diagnostic` and disables adjustment. Shift, Control or Command use `largeStep`. Page Up/Down use `largeStep`; Home/End request the bounds under the collision policy.

### Thumbs

<Preview
  title="Authored thumbs"
  align="stretch"
  code={`<tp-slider label="Working hours" default-value="9 17" minimum="0" maximum="24" style="max-inline-size:22rem;margin-inline:auto">

Author `tp-slider-thumb` children when a thumb needs its own spoken text, a disabled state or a native input reference. Each needs a unique `index`; values still live on the Slider.

A disabled thumb becomes a fixed barrier the others can't cross. Thumbs can also be added and removed at runtime: append one with the next `index` and call `setValue()` with the new list, or remove one and the Slider trims its values. A controlled list/Thumb count mismatch preserves owner values and disables ambiguous interaction. Once an explicit composition is authored, removing its last Thumb does not silently generate replacement Thumbs.

### Endpoints and direction

`thumb-alignment` sets where a thumb sits at the ends of the track: `center` (the default) lets half the thumb overhang, `edge` keeps it inside the track, and `delayed-edge` starts centered and switches to edge once the slider is used. In a right-to-left context the track, fill and Left/Right keys follow the reading direction. Structural hit-target expansion preserves the shared `target-size-min` even when the visible Thumb is smaller.

The Slider is the one form participant: a range submits each value under the same `name`, and Reset restores `default-value`. A wrapping Field supplies the label and description. Named enabled Thumb values serialize under the same name in logical index order. Disabled Thumb values are omitted. Uncontrolled reset restores the declared default; controlled reset leaves the owner authoritative. Restoration updates only uncontrolled state. Moving focus between Thumbs keeps the slider focused; leaving the entire control marks it touched.

`tp-value-change` fires on every proposed value while dragging and can be canceled. `tp-value-commit` fires once on release, or immediately for keyboard changes; use it for saving or other expensive work. Click the track to choose the nearest eligible Thumb. Dragging preserves the grab offset and commits once on release. Pointer cancellation, lost capture, removal and disconnect release the interaction without a delayed commit. No-op or canceled proposals produce no commit notification.

Call `preventDefault()` on `tp-value-change` to reject a value. The thumb stays where it was and nothing is committed.

### Media extensions

Slider carries optional media capabilities. Media sliders compose `tp-slider` with these APIs.

**Buffer ranges.** `buffered` accepts `readonly [start, end][]` in value units (property only). Ranges are clamped to the domain, ordered and merged; empty, inverted and non-finite ranges are dropped. Each remaining range renders one `slider-buffer` part inside the aria-hidden Track, below the Range. The Root publishes `--tp-slider-buffer`: the percentage position of the end of the range containing the current value (the last value of a range slider), or else of the last range; `0%` when nothing is buffered. Draw a single buffer bar from that variable, or style the per-range parts.

**Chapter segments.** `segments` accepts `readonly { start, end, label? }[]` (property only). Segments are clamped, ordered and empty ones dropped; the media layer owns gap filling and overlap trimming. Each chapter publishes `--tp-slider-segment-start`, `--tp-slider-segment-width` (domain percentages), `--tp-slider-segment-fill` and `--tp-slider-segment-buffer` (percent of that segment below the value or buffer end). The part state contains the segment's `label`.

**Hover pointer.** While a pointer is over the Control without a drag, `pointing` is true, `pointerRatio` is the 0–1 domain position and `pointerValue` is the corresponding unsnapped value. Horizontal RTL mirrors the axis; vertical grows upward; measured edge alignment of the first Thumb is respected. Movement publishes at most once per animation frame. Leaving the Control, starting a drag, disabling the Slider or entering the indeterminate state clears pointing immediately. Each change dispatches the non-cancelable, bubbling, composed `tp-slider-pointer-change` event with `detail: { value, ratio }` (`null` when cleared). Pointer values are presentation input, not value proposals; they never produce `tp-value-change`.

**Silent bounds.** Changing `minimum`, `maximum`, `step`, `minStepsBetweenValues`, `buffered` or `segments` never emits `tp-value-change`, `tp-value-commit` or their callbacks. An uncontrolled value outside new bounds is reconciled silently; Field still observes the new form value. Controlled values remain owner-normalized as before.

**Form opt-out.** `formAssociatedValue = false` (or `form-associated-value="false"`) makes the Slider submit and restore no value, report no validity, ignore form reset and emit no `tp-field-value`. Value-change and commit events are unchanged. The element class stays form-associated for platform purposes, so an ancestor disabled fieldset still disables it.

### Ticks

<Preview
  title="Ticks"
  align="stretch"
  code={`<div style="display:grid;gap:var(--tp-space-6);max-inline-size:22rem;margin-inline:auto">
  <tp-slider label="Stereo balance" default-value="-20" minimum="-50" maximum="50" ticks="10"></tp-slider>

`ticks` draws a mark every so many value units from `minimum`, and the midpoint gets a longer center mark. Values still move freely on `step`, and a drag that passes close to the center stops on it. With `snap-to-ticks` the ticks become the steps: dragging, the arrow keys and form values all land on a tick. When ticks would crowd a short track, some are left out; the center mark always stays.

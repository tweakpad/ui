## Usage

Use a One-time code field for a short code people copy from a message or an authenticator, such as a sign-in or verification code. The slots are drawn over a single native input, so typing, deletion, selection, paste and autofill from a text message behave as in one field; assistive technology hears one field with one name, and the form receives one value. Name it with a Field. For a password or any value without a fixed length, use an Input.

### SMS code

<Preview
  code={`<tp-field label="SMS code" description="Enter the six digits from the text message.">
  <tp-one-time-code-field length="6" name="sms-code" validation-type="numeric"></tp-one-time-code-field>
</tp-field>`}
/>

`validation-type="numeric"` accepts digits only and brings up the number pad on touch devices. Other characters are filtered out as they are typed or pasted, so a code pasted with spaces or dashes still lands whole.

### Recovery and pairing codes

<Preview
  code={`<tp-field label="Recovery code" description="Letters and numbers are accepted.">

<tp-field label="Device pairing code">
  <tp-one-time-code-field length="6" name="pairing-code" group-lengths="[2,2,2]" default-value="K7Q2M9"></tp-one-time-code-field>
</tp-field>`}
/>

`group-lengths` splits a longer code into the groups it is printed in, which makes it easier to compare against the source. The separator between groups never enters the value or the accessibility tree.

### Card PIN

<Preview
  code={`<tp-field label="Card PIN">
  <tp-one-time-code-field length="4" name="pin" validation-type="numeric" mask></tp-one-time-code-field>
</tp-field>`}
/>

`mask` hides the entered characters on screen while the value stays intact, for a PIN entered where others can see it.

### Verify on completion

<Preview
  code={`<form id="one-time-code-field-form" style="display:grid;gap:var(--tp-space-3);justify-items:start">
  <tp-field label="Email verification code" description="Use the code from your email.">
    <tp-one-time-code-field length="6" name="code" group-lengths="[3,3]" validation-type="numeric" auto-submit></tp-one-time-code-field>
  </tp-field>
  <output id="one-time-code-field-output" style="color:var(--tp-muted-foreground);font-size:var(--tp-text-sm)">Waiting for 6 digits</output>
</form>`}
  script={`const form = document.getElementById('one-time-code-field-form');
const output = document.getElementById('one-time-code-field-output');
form.addEventListener('submit', (event) => {
  event.preventDefault();
  output.textContent = 'Submitted code ' + new FormData(form).get('code');
});`}
/>

The moment the last slot is filled is the moment to verify: `tp-complete` fires then, and `auto-submit` submits the owning form without waiting for a button press. Keep a submit Button anyway when the code is part of a longer form.

### Request a new code

<Preview
  code={`<div id="one-time-code-field-resend" style="display:grid;gap:var(--tp-space-3);justify-items:start">
  <tp-field label="Two-factor code">
    <tp-one-time-code-field length="6" validation-type="numeric" group-lengths="[3,3]" value=""></tp-one-time-code-field>
  </tp-field>
  <div style="display:flex;gap:var(--tp-space-3);align-items:center">
    <tp-button variant="outline" size="sm">Send a new code</tp-button>
    <output aria-live="polite" style="color:var(--tp-muted-foreground);font-size:var(--tp-text-sm)">0 of 6 digits</output>
  </div>
</div>`}
  script={`const root = document.getElementById('one-time-code-field-resend');
const field = root.querySelector('tp-one-time-code-field');
const output = root.querySelector('output');
field.addEventListener('tp-value-change', (event) => {
  if (event.defaultPrevented || event.detail.cancelled) return;
  field.value = event.detail.value;
  output.textContent = field.value.length + ' of 6 digits';
});
root.querySelector('tp-button').addEventListener('click', () => {
  field.value = '';
  output.textContent = 'New code sent. The old one no longer works.';
  field.focus();
});`}
/>

Set `value` to own the code and accept each edit by assigning `event.detail.value`; your code can then clear the field when it sends a new code. When the server rejects a code, set the Field's `error` with `invalid`: every slot shows the invalid state, and the error is announced once for the whole code.

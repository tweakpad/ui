## Usage

Place one `tp-toast` per queue, usually once in the app shell, and call `add()` on it with a title and description. It renders the notifications in a labeled landmark: creating one never steals focus, F6 reaches the region, and hover, focus or a blurred window pause the timer. Swipe or the Close button dismisses.

Tab traverses active notification roots and related controls; leaving the region returns to the previous task when entered through the shortcut.

### Types

`type` picks a status icon: `success`, `info`, `warning` or `error`. `loading` shows a Spinner and stays until updated.

<Preview
  title="Types"
  code={`<div style="display:flex;flex-wrap:wrap;gap:var(--tp-space-2);justify-content:center">
  <tp-button variant="outline" data-toast-type="success">Success</tp-button>
  <tp-button variant="outline" data-toast-type="info">Info</tp-button>
  <tp-button variant="outline" data-toast-type="warning">Warning</tp-button>
  <tp-button variant="outline" data-toast-type="error">Error</tp-button>
</div>
<tp-toast id="toast-types"></tp-toast>`}
  script={`const toaster = document.querySelector('#toast-types');
const messages = {
  success: ['Invoice sent', 'INV-2041 was emailed to billing@northwind.io.'],
  info: ['New version available', 'Reload to get the latest dashboard.'],
  warning: ['Storage almost full', 'You have used 92 GB of 100 GB.'],
  error: ['Payment failed', 'The card ending in 4242 was declined.'],
};
for (const button of document.querySelectorAll('[data-toast-type]')) {
  button.addEventListener('click', () => {
    const type = button.dataset.toastType;
    const [title, description] = messages[type];
    toaster.add({ title, description, type });
  });
}`}
/>

### Actions

`actionProperties` adds a Button to the notification. An action does not close the toast by itself; close it from the handler with the `action` cause, as an Undo does.

Calling `close(id,'action')` or configuring `closeOnAction:true` preserves action dismissal as a distinct cause. Application handlers run before optional action dismissal; preventing that action cancels its default dismissal.

<Preview
  title="Undo"
  code={`<tp-button id="toast-undo-trigger" variant="destructive">Delete project</tp-button>
<tp-toast id="toast-undo"></tp-toast>`}
  script={`const toaster = document.querySelector('#toast-undo');
document.querySelector('#toast-undo-trigger').addEventListener('click', () => {
  const id = toaster.add({
    title: 'Project deleted',
    description: 'Marketing site was moved to the trash.',
    actionProperties: {
      label: 'Undo',
      onClick() {
        toaster.close(id, 'action');
        toaster.add({ title: 'Project restored', type: 'success', timeout: 2500 });
      },
    },
  });
});`}
/>

### Promises

`manager.promise()` shows a loading notification for pending work and settles it into success or error content, returning the original result.

Loading is persistent even with an explicit timeout; settlement starts the settled timeout or Provider default. Settlement after close/removal or Provider destruction cannot recreate a notification.

<Preview
  title="Saving"
  code={`<tp-button id="toast-promise-trigger" variant="outline">Publish changes</tp-button>
<tp-toast id="toast-promise"></tp-toast>`}
  script={`const toaster = document.querySelector('#toast-promise');
document.querySelector('#toast-promise-trigger').addEventListener('click', () => {
  const publish = new Promise((resolve) => setTimeout(() => resolve({ pages: 12 }), 1800));
  toaster.manager.promise(publish, {
    loading: 'Publishing changes…',
    success: (result) => ({ title: 'Changes published', description: \`\${result.pages} pages are live.\` }),
    error: 'Could not publish changes',
  });
});`}
/>

### Anchored to a control

`positionerProperties` pins a notification to the element that caused it instead of the stack, which suits short confirmations such as a copied link. `anchor` takes the element; `side` and `showArrow` place it.

Anchor removal begins close with `anchor-removed`.

<Preview
  title="Anchored"
  code={`<tp-button id="toast-anchor-trigger" variant="outline">Copy invite link</tp-button>
<tp-toast id="toast-anchor"></tp-toast>`}
  script={`const toaster = document.querySelector('#toast-anchor');
const button = document.querySelector('#toast-anchor-trigger');
button.addEventListener('click', () => {
  toaster.add({
    identifier: 'invite-link',
    title: 'Invite link copied',
    timeout: 1500,
    positionerProperties: { anchor: button, side: 'top', sideOffset: 8, showArrow: true },
  });
});`}
/>

A fixed `identifier` updates the same notification on repeated presses instead of stacking copies. Use a separate `tp-toast` for anchored notifications when your stacked ones follow a different position or limit.

### A shared manager

`createToastManager()` from `@tweakpad/ui` creates the queue on its own, so any module can raise notifications without a reference to the element. Hand it to the viewport through `toastManager`, usually once in the app shell.

Connect a manager to one Provider host at a time.

The manager service object may be retained across Provider lifetimes. Disconnecting its host destroys that queue lifetime, clears its notifications, and reports `provider-destroyed` through close/removal callbacks. Reconnecting the same host reuses the same service with a fresh queue. Pending operations from the discarded lifetime cannot recreate notifications.

<Preview
  title="Manager"
  code={`<div style="display:flex;flex-wrap:wrap;gap:var(--tp-space-2);justify-content:center">
  <tp-button id="toast-manager-sync" variant="outline">Sync calendar</tp-button>
  <tp-button id="toast-manager-clear" variant="ghost">Dismiss all</tp-button>
</div>
<tp-toast id="toast-manager" label="Calendar notifications"></tp-toast>`}
  script={`import { createToastManager } from '@tweakpad/ui';

const notifications = createToastManager({ timeout: 4000 });
document.querySelector('#toast-manager').toastManager = notifications;

// Elsewhere in the app, only the manager is needed.
let synced = 0;
document.querySelector('#toast-manager-sync').addEventListener('click', () => {
  synced += 3;
  notifications.add({
    title: 'Calendar synced',
    description: \`\${synced} events imported from Google Calendar.\`,
    type: 'success',
  });
});
document.querySelector('#toast-manager-clear').addEventListener('click', () => notifications.close());`}
/>

`close()` without an identifier dismisses every notification in the queue.

### Declarative notification

A `tp-toast` with `open` shows its own content as one notification, with `title` as the heading. `setOpen()` shows or hides it from code, and `duration="persistent"` keeps it until dismissed.

<Preview
  title="Host content"
  code={`<tp-button id="toast-content-trigger" variant="outline">Save draft</tp-button>
<tp-toast id="toast-content" duration="persistent" title="Draft saved">Your post will stay here until you publish it.</tp-toast>`}
  script={`const toaster = document.querySelector('#toast-content');
document.querySelector('#toast-content-trigger').addEventListener('click', () => toaster.setOpen(true));`}
/>

### Position and lifetime

`position` places the stack in one of six logical positions. `timeout` sets the default lifetime in milliseconds (`0` keeps notifications until dismissed), and `limit` caps how many stay visible; older ones wait behind the newest.

<Preview
  title="Top center, persistent"
  code={`<tp-button id="toast-position-trigger" variant="outline">Go offline</tp-button>
<tp-toast id="toast-position" position="block-start center" timeout="0" limit="1"></tp-toast>`}
  script={`const toaster = document.querySelector('#toast-position');
document.querySelector('#toast-position-trigger').addEventListener('click', () => {
  toaster.add({
    title: 'You are offline',
    description: 'Changes are saved locally and will sync when you reconnect.',
    type: 'warning',
  });
});`}
/>

Use `priority: 'high'` in `add()` only for urgent messages: it announces through the assertive channel and interrupts the screen reader.

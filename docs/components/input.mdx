## Usage

An Input edits one line of text. Its native input lives in the page's own tree, so browsers and password managers recognize and fill it, and it submits with its form like any input. Labels, descriptions and errors belong to the Field around it; a standalone Input can take `label` for its accessible name, but a Field is its usual home. For several lines, use a Text area; for text with a unit, an icon or an action inside the border, wrap the Input in an Input group.

### Sign-in

<Preview
  code={`<div style="display:grid;gap:var(--tp-space-4)">
  <tp-field label="Email">
    <tp-input type="email" name="email" autocomplete="username" placeholder="you@example.com"></tp-input>
  </tp-field>
  <tp-field label="Password">
    <tp-input type="password" name="password" autocomplete="current-password"></tp-input>
  </tp-field>
</div>`}
/>

`type` keeps the native keyboard, affordances and validation of every input type, and `autocomplete` tells the browser which saved value belongs where. Name the fields as your server expects; the Inputs submit them natively.

### Order quantity

<Preview
  code={`<tp-field label="Seats" description="Between 1 and 50.">
  <tp-input type="number" name="seats" min="1" max="50" step="1" default-value="5"></tp-input>
</tp-field>`}
/>

A number or date type takes `min`, `max` and `step`, which the Field reports when a value falls outside them.

### Keys and identifiers

<Preview
  code={`<div style="display:grid;gap:var(--tp-space-4)">
  <tp-field label="Webhook secret">
    <tp-input mono name="secret" default-value="whsec_9f2b41c07a"></tp-input>
  </tp-field>
  <tp-field label="Project ID" description="Assigned when the project was created.">
    <tp-input mono readonly name="project" default-value="prj_8f2c41"></tp-input>
  </tp-field>
</div>`}
/>

`mono` shows the value in the mono font and turns off spell checking, autocorrection and autocapitalization, for identifiers, paths and keys where a corrected character is a bug. A value people may copy but not change is `readonly`: it stays focusable, selectable and submitted, where `disabled` would also drop it from the form data.

### Workspace handle

<Preview
  code={`<tp-field label="Workspace handle" description="Lowercase letters, numbers and dashes.">
  <tp-input id="input-handle" mono value="northwind-studio"></tp-input>
</tp-field>`}
  script={`const input = document.getElementById('input-handle');
input.onValueChange = (event) => {
  input.value = event.detail.value.toLowerCase().replace(/[^a-z0-9]+/g, '-');
};`}
/>

`default-value` leaves the text to the Input. Supply `value` instead and every edit becomes a proposal: `onValueChange` receives it, and what you assign back to `value` is what commits, so here each edit is rewritten into a handle that is safe in a URL. Without an assignment the edit is rejected and the text stays as it was.

### Username already taken

<Preview
  code={`<tp-field label="Username" error="That username is taken. Try ada-lovelace." invalid>
  <tp-input name="username" default-value="ada"></tp-input>
</tp-field>`}
/>

Native constraints such as `required`, `pattern` and `minlength` validate through the Field, which shows the message and connects it to the Input. An answer only the server knows, such as a name already in use, goes in the Field's `error` with `invalid`.

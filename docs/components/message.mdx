## Usage

A Message lays out one row of a conversation: the avatar column, a header, the content and a footer. The visible surface is a Bubble; Message neither sends anything nor infers delivery state, so status text comes from the application. `align="end"` marks the current user's messages, and the avatar and footer follow it, including in right-to-left text; give the nested Bubble the same `align`. Alignment alone does not identify a sender: name every row through `aria-label`, the avatar's `alt` or a header.

### Names and times

<Preview
  align="stretch"
  code={`<div style="display:flex;flex-direction:column;gap:var(--tp-space-6);max-inline-size:32rem">
  <tp-message author="Sam Rivera" timestamp="2026-10-09T14:32:00">
    <tp-bubble>The Q3 invoice export is attached to the ticket.</tp-bubble>
  </tp-message>
  <tp-message align="end" author="You" timestamp="2026-10-09T14:35:00">
    <tp-bubble align="end" variant="default">Thanks, forwarding it to finance.</tp-bubble>
    <span slot="footer">Read by Sam</span>
  </tp-message>
</div>`}
/>

In a channel with many participants, `author` and `timestamp` fill the header; Time renders the time, so it reads in the reader's locale. The footer carries read receipts or reactions, and a region with nothing in it takes no space.

### Delivery status

<Preview
  align="stretch"
  code={`<div style="display:flex;flex-direction:column;gap:var(--tp-space-6);max-inline-size:32rem">
  <tp-message align="end" aria-label="You" pending>
    <tp-bubble align="end" variant="default">Can we move the design review to 3pm?</tp-bubble>
  </tp-message>
  <tp-message align="end" aria-label="You" failed>
    <tp-bubble align="end" variant="default">Uploading the updated mockups now.</tp-bubble>
  </tp-message>
</div>`}
/>

`pending` shows Sending in the footer and `failed` shows Failed to send, announced as an alert. The application sets and clears both, and the status appears only while the `footer` slot is empty.

### Consecutive messages

<Preview
  align="stretch"
  code={`<tp-message-group style="max-inline-size:32rem">
  <tp-message aria-label="Sam Rivera">
    <span slot="avatar" aria-hidden="true"></span>
    <tp-bubble>I checked the release checklist.</tp-bubble>
  </tp-message>
  <tp-message aria-label="Sam Rivera">
    <tp-avatar slot="avatar" fallback="SR" alt="Sam Rivera"></tp-avatar>
    <tp-bubble>The remaining items are assigned to the platform team.</tp-bubble>
  </tp-message>
</tp-message-group>`}
/>

A Message group stacks one sender's messages with tighter spacing. An empty avatar slot on the earlier rows keeps their column, so the bubbles line up beside the final avatar.

### Assistant replies with actions

<Preview
  align="stretch"
  code={`<tp-message aria-label="Assistant" style="max-inline-size:32rem">
  <tp-bubble variant="ghost">Your workspace uses 18 of 20 seats. Removing the two inactive guests frees room for the new hires without changing your plan.</tp-bubble>
  <tp-button slot="footer" variant="ghost" size="icon-sm" aria-label="Copy message"><tp-icon slot="icon-start" id="message-copy-icon"></tp-icon></tp-button>
  <tp-toggle slot="footer" size="sm" aria-label="Helpful"><tp-icon id="message-like-icon"></tp-icon></tp-toggle>
  <tp-toggle slot="footer" size="sm" aria-label="Not helpful"><tp-icon id="message-dislike-icon"></tp-icon></tp-toggle>
</tp-message>`}
  script={`import { copyIcon } from '@tweakpad/ui/icons/copy';
import { thumbsUpIcon } from '@tweakpad/ui/icons/thumbs-up';
import { thumbsDownIcon } from '@tweakpad/ui/icons/thumbs-down';

document.getElementById('message-copy-icon').icon = copyIcon;
document.getElementById('message-like-icon').icon = thumbsUpIcon;
document.getElementById('message-dislike-icon').icon = thumbsDownIcon;`}
/>

An assistant's answer reads best as unframed full-width text, with its actions as ordinary named controls in the footer: a Button for a one-off command, Toggles for feedback that stays pressed. Each control is its own tab stop.

### Retrying a failed message

<Preview
  align="stretch"
  code={`<tp-message align="end" aria-label="You" style="max-inline-size:32rem">
  <tp-bubble align="end" variant="default">Sharing the venue contract with legal now.</tp-bubble>
  <span slot="footer" id="message-retry-status" tabindex="-1" role="status" style="color:var(--tp-destructive)">Failed to send</span>
  <tp-button slot="footer" id="message-retry-button" variant="ghost" size="icon-xs" aria-label="Retry sending"><tp-icon slot="icon-start" id="message-retry-icon"></tp-icon></tp-button>
</tp-message>`}
  script={`import { refreshIcon } from '@tweakpad/ui/icons/refresh';

const retry = document.getElementById('message-retry-button');
const status = document.getElementById('message-retry-status');
document.getElementById('message-retry-icon').icon = refreshIcon;
retry.addEventListener('click', () => {
  retry.hidden = true;
  status.style.removeProperty('color');
  status.textContent = 'Sending…';
  status.focus();
  setTimeout(() => {
    if (status.isConnected) status.textContent = 'Delivered';
  }, 1200);
});`}
/>

To offer a retry, put the status and a Retry button in the footer instead of setting `failed`: authored footer content replaces the built-in status. Once the message goes through, move focus to the status, so a keyboard user is not left on a button that has disappeared.

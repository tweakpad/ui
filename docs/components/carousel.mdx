## Usage

Each child of `tp-carousel` is one slide. Previous and next Buttons, arrow keys, swipe and the indicators all move the same numeric selection, and the current position is announced politely. Always give the Carousel a `label`, and size it through CSS: it fills the inline size it is given. Transitions never block interaction by default. A drag can grab a moving carousel and continues from the presented position.

### Several per view

Layout, navigation and indicator settings live in the `options` property. `layout.itemsPerView` accepts fractions, so a partly visible next slide hints that there is more; `items-per-movement` sets how far each step moves. Resolution order is defaults, base `options`, root scalar properties, then the matching breakpoint. `breakpoints` maps nonnegative pixel widths or positive `@ratio` keys to responsive overrides.

### Indicators and placement

`indicators.type` is `fraction` by default, or `bullets` and `progress`. Set `clickable: true` to make bullets real Buttons. `navigation.placement` puts the arrows in the `footer`, `inside` the viewport or `outside` it. `navigation.hideOnClick` and `indicators.hideOnClick` toggle their controls when noninteractive slide content is clicked. Indicator count is snap count, which may differ from item count or mounted virtual count.

### Loop and autoplay

`loop` lets navigation wrap past either end. `autoplay` sets an interval in milliseconds and adds a Pause/Resume Button before the slides; hover, focus, reduced motion and hidden tabs pause the timer automatically. Root loop permits `loopMode='continuous'` (default) or `'rewind'`. Continuous mode permutes owned shells without cloning consumer controls or changing logical source order.

Use autoplay sparingly: moving content is hard to read and easy to miss. Prefer it for decorative or repeated content, never for the only path to information.

### Effects

By default the track slides between items. The `effect` property swaps in a richer transition, built by a factory you import, so pages without one bundle none. `carouselCrossfadeEffect()` fades between slides, `carouselLayeredEffect()` turns media away with perspective, `carouselParallaxEffect()` moves media more slowly than its slide, `carouselFocusEffect()` dims and shrinks slides away from the aligned one, and `carouselShaderEffect()` runs a WebGL transition: `wipe`, `displace`, `chromatic`, `crosswarp` or `glass`.

- **Stack** effects keep every item at the viewport origin and force one item per view
  and per movement. Conflicting layout options are overridden with a `tp-diagnostic`.
- **Track** effects keep the moving track, so any layout, loop or centering works. With several items in view, set `interaction.navigateOnItemClick` so a click on a partly visible item brings it into view.
- Effects need the transform transport. With `transport: 'scroll'` the effect is
  ignored and a diagnostic reports it.

The shader effect draws a WebGL2 transition between the two `data-carousel-media` images: `wipe` sweeps a noise-edged front, `displace` and `chromatic` flow a noise map through the frame, `crosswarp` zooms and morphs across, and `glass` sweeps a refracting ridge. `direction` takes an edge or a corner. Captions stay live text above the canvas. Images need `crossorigin="anonymous"` from a CORS-enabled host; without WebGL2, loaded media or motion, the effect falls back to a crossfade. All shader carousels on a page share one WebGL2 context. Each carousel displays frames in its own canvas, so many carousels never exhaust the browser's context limit.

### Keyboard

Arrow keys follow the active axis and writing direction; Home and End jump to the first and last slide. Keys owned by a control inside a slide, such as a text field or slider, stay with that control. Optional PageUp/PageDown use the same snap navigation. An inner Carousel owns its own navigation.

### Custom effects

`CarouselEffect` objects have:

- `name` and `layout` (`track` or `stack`);
- optional `duration`, `easing`, `easingRole` (`standard`, `enter` or `exit`, the motion
  token used without `easing`) and `constrain(input, diagnose)`;
- `attach(context)`, which returns `{ frame(frame), update?(), detach() }`.

Each frame provides:

- `phase` (`drag`, `animate`, `settle`), `position`, `velocity` (items per second), `direction`;
- `items`, each with `progress`, `shell` and `content`;
- `current`, `next` and `amount`, the pair being transitioned and how far.

The context provides the viewport, track, effect surface, orientation, direction,
`invalidate()` and `diagnose()`. Restore everything you change in `detach()`. Helpers
`stackEffectConstraint`, `carouselItemProgress` and `mergeCarouselOptions` are exported.

Grid/multirow layout, unsnapped free momentum, zoom, linked controllers, thumbnail
controllers, URL routing, raw HTML renderers and a public plugin/module injection
system are not supported. Effects are typed presentation objects,
not installable modules.

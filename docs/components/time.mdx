## Usage

Set `datetime` to an ISO string, an epoch number or a `Date`; without it the element reads its own text, so server-rendered dates upgrade in place. Relative text refreshes on one shared timer when it can next change, and focusing or hovering a value shows the full date and time.

`datetime` accepts a `Date`, an epoch number, text, or a Temporal-like object with `epochMilliseconds` or an ISO `toString()`. The `<time>` element always carries a valid machine-readable `datetime` at that precision. Time does not store values or synchronize clocks.

Absolute presentations do not refresh. The timer stops while the page is hidden and every element refreshes when it becomes visible, after a `languagechange`, or when a `lang` attribute in the document changes. Changes to `lang` inside other shadow roots apply at the next refresh. Updates are never announced through a live region.

Message's `timestamp` renders a Time with defaults; use the Message `header` slot with your own `tp-time` for other options. Use Time inside List item footers, Table cells, Card or Alert text, Preview card content and Tooltip triggers wherever a date is displayed. For strings outside the DOM, such as a Toast description, use the exported `resolveTime` and `formatTime`.

### Modes

`auto` (the default) is relative within 30 days and absolute beyond. `calendar` says "Yesterday at 16:20"; `duration` shows a length of time.

### Presets and patterns

`preset` names a locale-aware format. `pattern` takes Unicode date-field symbols for an exact layout; quote literal words.

Absolute text resolves in this order: `formatter`, then `pattern`, then `format`, then `preset`.

| `preset`             | en-US example                      |
| -------------------- | ---------------------------------- |
| `time`               | 2:30 PM                            |
| `time-seconds`       | 2:30:00 PM                         |
| `date`               | 10/5/26                            |
| `date-medium`        | Oct 5, 2026                        |
| `date-long`          | October 5, 2026                    |
| `datetime` (default) | Oct 5, 2026, 2:30 PM               |
| `datetime-long`      | October 5, 2026 at 2:30 PM         |
| `full`               | Monday, October 5, 2026 at 2:30 PM |
| `iso`                | the machine value                  |

Presets drop fields finer than the value: `datetime` on a date-only value shows only the date.

Write `yyyy-MM-dd`, not Moment-style `YYYY-MM-DD`: unsupported letters render literally and raise a diagnostic instead of silently formatting a different year.

`pattern` uses Unicode date-field symbols, localized through `Intl`: `y`, `yy`, `yyyy`; `M`, `MM`, `MMM`, `MMMM`, `MMMMM` (`L` is equivalent); `d`, `dd`; `E`–`EEE`, `EEEE`, `EEEEE`; `a`; `h`, `hh`, `H`, `HH`, `K`, `k`; `m`, `mm`; `s`, `ss`; `S`–`SSS`; `z`, `zzzz`; `X`–`XXX`, `x`–`xxx`. Quote literal text: `"d MMM 'at' HH:mm"`, with `''` for an apostrophe. Week-year `Y`, day-of-year `D` and other unsupported letters render literally and emit a `tp-diagnostic`.

### Dates and time zones

A date-only value stays on its calendar day in every time zone and compares by days. Instants format in the browser's zone unless `time-zone` names one, and `hour-cycle` forces 12- or 24-hour clocks.

### Calendar phrases

`mode="calendar"` names nearby days, such as "Today at 09:12" or "Last Friday at 16:40", and falls back to an absolute date beyond a week. Month and weekday names come from the locale; the surrounding phrases come from the `messages` property, with `{time}`, `{weekday}` and `{date}` placeholders, so you can translate or reword them.

### Relative style

`relative-style` shortens relative text for dense layouts; the long form stays available to assistive technology. `numeric="always"` replaces phrases like "yesterday" with counts.

Relative text uses `Intl.RelativeTimeFormat` with one unit. Boundaries are 60 seconds, 60 minutes, 24 hours, 7 days, 30 days and 365 days. `rounding="floor"` (default) shows "1 hour ago" until two hours have passed; `round` rounds to the nearest count and promotes to the next unit at a boundary. Distances below `now-threshold` (default `PT10S`) or below one `precision` unit read "now". With `numeric="auto"` (default) the locale may say "yesterday" or "last week".

### Countdowns and elapsed time

`mode="duration"` on an instant shows the time until or since it as a ticking length, such as a call timer or a sale countdown. `precision` sets the smallest unit shown, which also slows the updates. `tense="past"` shows a slightly future instant, for example from a server clock that runs ahead, as "now" instead of "in 3 seconds".

### Description

The tooltip shows `tooltip-pattern` (default `dd/MM/yy HH:mm`) and makes the value focusable. It is skipped when it would repeat the visible text; `tooltip="false"` removes it and the tab stop.

The default pattern is reduced to the value's precision: `dd/MM/yy` for dates, `HH:mm` for times, `MM/yy` for months. No description or tab stop is added when it would repeat the visible text, or for durations and weeks. Use `tooltipFormatter` for full control.

### Unreadable input

Input that cannot be read as a date, time or duration keeps the authored content and exposes `data-invalid`, so a server-rendered label never turns into a wrong date.

Resolution order:

1. `Date` and objects with `epochMilliseconds`.
2. Numbers, and text of 9–13 digits optionally prefixed with `@`: epoch seconds below `100000000000`, milliseconds otherwise.
3. Time-element microsyntaxes: `2026` (year), `2026-10` (month), `2026-10-05` (date), `--10-05` or `10-05` (yearless), `2026-W40` (week), `14:30[:05[.123]]` (time), `2026-10-05T14:30` or with a space (local date-time), and the same with `Z` or `±HH:MM` (instant).
4. Durations: `PT1H30M`, `P1DT2H`, `P1Y2M`, or `1h 30m`, `3w 2d`.
5. Internet message dates: `Mon, 05 Oct 2026 14:30:00 GMT`.
6. The browser's best-effort parser, marked loose. Set `strict` to reject it.

A local date-time without an offset is a wall-clock value in the resolved time zone.

### Message timestamp

Message renders its timestamp through Time.

<Preview
  title="Message timestamp"
  code={`<div id="time-message"><tp-message author="Ada" data-offset="-120">The build is green again.</tp-message></div>`}
  script={`/** Assign live datetimes so relative examples stay current. */
export function setupTimeExample(root) {
  const now = Date.now();
  for (const time of root.querySelectorAll('tp-time[data-offset]'))
    time.datetime = new Date(now + Number(time.dataset.offset) * 1000);
  for (const time of root.querySelectorAll('tp-time[data-days]')) {
    const date = new Date(now + Number(time.dataset.days) * 86_400_000);
    time.datetime = \`\${date.getFullYear()}-\${String(date.getMonth() + 1).padStart(2, '0')}-\${String(date.getDate()).padStart(2, '0')}\`;
  }
  for (const message of root.querySelectorAll('tp-message[data-offset]'))
    message.timestamp = new Date(now + Number(message.dataset.offset) * 1000);
  const calendar = root.querySelector('tp-time[data-messages]');
  if (calendar) calendar.messages = { today: 'Hoy a las {time}', yesterday: 'Ayer a las {time}' };
  return () => {};
}

setupTimeExample(document.getElementById('time-message'));`}
/>

## Usage

Each `tp-accordion-item` renders a heading with a native button trigger and a content panel. Put the trigger text in `slot="label"`; everything unslotted becomes the panel. Give every item a stable, unique `value`, which is what `value` and `default-value` refer to. Headings default to `h2`; set `heading-level` on each item to fit the page outline. The `value` HTML attribute is a whitespace-separated list; in JavaScript, `accordion.value` is an ordered `string[]`. The component derives selected items in registration order. In non-collapsible single mode, it opens the first available item when none is selected. Only direct `<tp-accordion-item>` children register as Items; a bare `<div>` directly inside the Root is not an Item.

`variant` describes how items relate visually: `plain` adds no chrome, `line` separates items, `outline` wraps them in one container and `separated` gives each its own surface. It never changes behavior.

Single mode keeps one item open, so the last open item can't close unless you add `collapsible`. Use `selection-mode="multiple"` when readers compare sections side by side.

### Leading and trailing content

<Preview
  title="Positional content"
  align="stretch"
  code={`<tp-accordion variant="separated" content-alignment="label" default-value="profile" style="max-inline-size:34rem">
  <tp-accordion-item value="profile">
    <span slot="leading" aria-hidden="true">01</span>
    <span slot="label">Complete your profile</span>
    <tp-badge slot="trailing" variant="secondary">Done</tp-badge>
    <p>Add a photo and job title so teammates recognize you.</p>
  </tp-accordion-item>
  <tp-accordion-item value="invite">
    <span slot="leading" aria-hidden="true">02</span>
    <span slot="label">Invite teammates</span>
    <p>Send invites by email or share a link that expires in 7 days.</p>
  </tp-accordion-item>
  <tp-accordion-item value="connect" indicator-position="leading">
    <span slot="label">Connect GitHub</span>
    <tp-badge slot="trailing" variant="outline">Optional</tp-badge>
    <p>Link pull requests to tasks and close them automatically on merge.</p>
  </tp-accordion-item>
</tp-accordion>`}
/>

The `leading` and `trailing` slots take numbers, icons, badges or status text, but nothing interactive: they live inside the trigger button. `content-alignment="label"` lines the panel up with the label, whatever the leading content's width. `indicator-position` moves the chevron. `leading` and `trailing` follow writing direction, so Leading is on the right in RTL. Decorative content should be `aria-hidden="true"`; meaningful status text may remain in the accessibility tree when it should augment the Trigger's name.

`disabled` on one item locks only that item; on the root it locks all of them. Triggers are native buttons, so Enter and Space toggle, and Tab moves between items.

### Content motion

<Preview
  title="Line-by-line reveal"
  align="stretch"
  code={`<tp-accordion variant="outline" collapsible style="max-inline-size:34rem">
  <tp-accordion-item value="setup">
    <span slot="label">Set up your workspace</span>
    <tp-scroll-trigger reveal="up" stagger="80" reveal-repeat>
      <p><tp-text-motion split="lines" mask="lines">Pick a name and URL. You can change both later in workspace settings.</tp-text-motion></p>
      <p><tp-text-motion split="lines" mask="lines">Invite the people you work with most; they get an email with a link that expires in 7 days.</tp-text-motion></p>
      <p><tp-text-motion split="lines" mask="lines">Import projects from Jira, Linear or a CSV export.</tp-text-motion></p>
    </tp-scroll-trigger>
  </tp-accordion-item>
  <tp-accordion-item value="integrations">
    <span slot="label">Connect your tools</span>
    <tp-scroll-trigger reveal="up" stagger="80" reveal-repeat>
      <p><tp-text-motion split="lines" mask="lines">Link GitHub to attach pull requests to tasks.</tp-text-motion></p>
      <p><tp-text-motion split="lines" mask="lines">Add Slack to get a digest of mentions and due dates every morning.</tp-text-motion></p>
    </tp-scroll-trigger>
  </tp-accordion-item>
</tp-accordion>`}
/>

Text motion reveals a panel's lines each time its item opens. A Scroll trigger with `reveal-repeat` sequences the paragraphs, and a closed panel is hidden, so its lines reset for the next opening.

Each item asks for motion with a bubbling `tp-motion-request`. Claim only the `content` role to stagger the panel's paragraphs; the accordion still measures the panel, animates its height and decides which item is open. Because the request bubbles, a listener on one item claims motion for that item only, and a listener on the accordion covers all of them.

### Limits

- There is no distinct controlled-value mode: an accepted trigger interaction updates `value` even when the host set it externally.
- On item registration or rebuild in non-collapsible single mode, an empty or unknown `value` is replaced by the first available item. A programmatic multi-value list in single mode presents only its first available item, but the property can retain extra values until rebuild.
- When the open item is removed or disabled, fallback selection uses the first enabled item.
- An `absent` panel is hidden but remains in the DOM.

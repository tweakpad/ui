## Usage

Author each tab as a native `<button slot="tab">` and each panel as an element with `slot="panel"`, matched by `value`. Tabs supplies roles, `type="button"`, roving tabindex and the `aria-controls` and `aria-labelledby` links; `label` names the tab list.

Tab labels may include `tp-icon`, `tp-badge`, or other noninteractive content. Do not nest interactive controls inside a tab. Use `tp-button`, `tp-input`, `tp-card` and other library components inside panels. Nested Tabs own only their direct members. `dir="rtl"` follows the surrounding direction and reverses horizontal navigation; vertical navigation remains Up/Down.

Native button values are strings. For object or numeric member values, use a non-native tab host with `native-action="false"` and assign its `.value` before connection. Values use identity equality. After changing non-reactive member properties such as `.value`, `.keepMounted`, `.disabled` or `.nativeAction`, call `refresh()`. String attributes are observed automatically.

### Keyboard and activation

<Preview
  title="Automatic activation"
  align="stretch"

  <button slot="tab" value="day">Day</button>
  <button slot="tab" value="week">Week</button>
  <button slot="tab" value="month">Month</button>
  <p slot="panel" value="day">1,204 visitors today.</p>
  <p slot="panel" value="week">8,931 visitors this week.</p>
  <p slot="panel" value="month">36,410 visitors this month.</p>
</tp-tabs>`}
/>

By default activation is `manual`: arrow keys move focus and Enter or Space selects. Use `automatic` when panels are cheap to show, so selection follows focus. Arrows wrap at the ends unless the `loopFocus` property is set to `false`.

Tab enters the list at its roving entry; another Tab reaches the active panel and its content. Left/Right navigate horizontal lists, Up/Down vertical lists, and Home/End move to the ends. Wrong-axis and modified arrows do not change selection. External selection does not steal focus or replace the focused tab's roving entry while focus is in the list. Tabs use `aria-selected`/`aria-controls`; panels use `aria-labelledby` and are sequentially focusable only while selected. Author IDs are preserved.

Selection publishes a cancelable `tp-value-change` with the proposed `value`; call `preventDefault()` to keep the current tab, for example while a panel has unsaved edits. `setValue()` selects a tab from code through the same proposal and returns whether it was accepted. For controlled Tabs, set the `value` property from the start and write each accepted `detail.value` back to it. Equal selections are no-ops. Filter bubbled events by `event.target` when panels contain other controls.

### Guarding unsaved edits

For controlled Tabs, set `value` from the start and accept proposals in `onValueChange`. Skipping the write-back, or calling `preventDefault()`, keeps the current tab. Edit the name below, then try to leave the tab. The profile panel is `keep-mounted`, so its draft survives while another tab is showing. Programmatic controlled assignments do not emit change proposals. A controlled missing value selects nothing; the first enabled tab remains the keyboard entry.

<Preview

const name = document.querySelector('#tabs-guard-name');
const status = document.querySelector('#tabs-guard-status');
const save = document.querySelector('#tabs-guard-save');
await customElements.whenDefined('tp-input');
await name.updateComplete;
let saved = name.value;
const dirty = () => name.value !== saved;
tabs.onValueChange = (event) => {
  if (dirty()) {
    event.preventDefault();
    status.textContent = 'Save or discard your changes before leaving Profile.';
    return;
  }
  status.textContent = '';
  tabs.value = event.detail.value;
};
name.addEventListener('input', () => { status.textContent = ''; });
save.addEventListener('click', () => {
  saved = name.value;
  status.textContent = 'Saved.';
});
document.querySelector('#tabs-guard-discard').addEventListener('click', () => {
  name.setValue(saved);
  status.textContent = '';
});`}

### Disabled tabs

<Preview
  title="Disabled"
  align="stretch"
  code={`<tp-tabs default-value="details" label="Order" style="max-inline-size:26rem;margin-inline:auto">
  <button slot="tab" value="details">Details</button>
  <button slot="tab" value="shipping">Shipping</button>
  <button slot="tab" value="returns" aria-disabled="true">Returns</button>
  <p slot="panel" value="details">Order #10482, placed March 3.</p>
  <p slot="panel" value="shipping">Delivered March 6 by UPS.</p>
  <p slot="panel" value="returns">Returns open after delivery.</p>
</tp-tabs>`}
/>

`aria-disabled="true"` keeps a tab discoverable through arrow navigation; native `disabled` removes it from focus. Neither can be activated. Setting `disabled` on Tabs itself locks the whole list, for example while the content behind it is loading. Programmatic selection may select a disabled tab, but disabled tabs are never the sequential tab stop or user-activated.

An explicit disabled `defaultValue` is honored initially. If a selected tab is removed, renamed or subsequently disabled, uncontrolled selection falls forward to the nearest enabled successor, then backward to a predecessor, then to `null`.

### Panel mounting

Inactive panels are detached from the DOM after their exit and restored on activation, so heavy content costs nothing while hidden. Add `keep-mounted` to a panel that must stay in the document, for example one holding form fields that still submit, and it is kept hidden and inert instead. Custom elements inside them receive disconnect/connect callbacks. The public `panels` getter includes retained and detached nodes. Keep application references to panels that need updating while detached; a host `querySelector` cannot find them. Remove a panel by calling `remove()` on that node, including while detached.

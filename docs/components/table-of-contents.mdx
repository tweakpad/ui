## Usage

Use a Table of contents beside long reading content (a guide, a policy, release notes) so readers can see where they are and jump between sections. Each item names its target; the component never scans the page for headings. It finds the scroll container that holds every target, the document or a Scroll area as here, and marks the innermost target whose region crosses the reading line. Place it in a sticky column inside that same container.

Activating an item scrolls only the content's container and keeps that item current until the reader scrolls again. By default the target is also recorded in the URL as a history entry, so Back returns to the previous section; `navigation="scroll"` leaves the URL alone, for an application that routes on the fragment or a list inside an embedded panel.

The reading line follows the container's `scroll-padding-block-start`, the same CSS that clears a sticky header for anchor links, so a jump always lands on the item it marks; `activation-offset` sets it explicitly.

To keep a group current while the reader is inside one of its subsections, make the group a `section` that wraps them and point its item at the section: the indicator then spans the group and the subsection together. `depth` only indents the subsection items; the grouping comes from the sections themselves. `label` replaces the default "On this page" title, and the `title` slot takes richer content.

  script={`import { collectTargets } from '@tweakpad/ui';

const steps = document.getElementById('table-of-contents-steps');
const list = document.getElementById('table-of-contents-step-list');
const add = document.getElementById('table-of-contents-add-step');

function renderItems() {
  const records = collectTargets(steps, '[data-step]', {
    label: (element) => element.dataset.step,
  });
  list.replaceChildren(...records.map(({ element, label }) => {
    const item = document.createElement('tp-table-of-contents-item');
    item.target = element;
    item.textContent = label;
    return item;
  }));
}

const extras = [
  ['Invite your team', 'Send invitations from Settings → People. New members land in the onboarding project you just set up.'],
  ['Connect your calendar', 'Due dates appear in your calendar, and moving an event there moves the task here.'],
];
add.addEventListener('click', () => {
  const next = extras.shift();
  if (!next) return;
  const step = document.createElement('div');
  step.dataset.step = next[0];
  step.style.marginBlockEnd = 'var(--tp-space-5)';
  const title = document.createElement('strong');
  title.textContent = next[0];
  const text = document.createElement('p');
  text.style.marginBlock = 'var(--tp-space-2) 0';
  text.textContent = next[1];
  step.append(title, text);
  steps.querySelector('[data-end]').before(step);
  renderItems();
  add.disabled = extras.length === 0;
});

renderItems();`}
/>

When the sections come from data or an editor, `collectTargets` from `@tweakpad/ui` returns a record for each element a selector matches; render one item per record and give it the element as `target`. Targets need no ids and need not be headings. Run it again whenever the content changes, as adding a step does here.

The list shows the title and every item in place, for a page with room for a column. `compact` draws less attention: one short line per top-level item, with the current one marked; hovering the lines opens the full list in a card, and the lines are one Button for keyboard users. `side` is the direction the card grows, toward the content: here the lines sit on the start edge, so the card grows toward the inline end.

## Usage

A Badge is a non-focusable label, so it never adds a tab stop. Its text carries the meaning on its own: "Failed" says more than a red pill, and "12 unread" more than a bare number.

### Status in a list

  align="stretch"
  code={`<div style="display:grid;gap:var(--tp-space-3);max-inline-size:28rem;font-size:var(--tp-text-sm)">
  <div style="display:flex;align-items:center;justify-content:space-between;gap:var(--tp-space-3)">
    <span>Website redesign</span>
    <tp-badge variant="secondary">In review</tp-badge>
  </div>
  <div style="display:flex;align-items:center;justify-content:space-between;gap:var(--tp-space-3)">
    <span>Mobile onboarding</span>
    <tp-badge>Shipped</tp-badge>
  </div>
  <div style="display:flex;align-items:center;justify-content:space-between;gap:var(--tp-space-3)">
    <span>Billing migration</span>
    <tp-badge variant="destructive">Blocked</tp-badge>
  </div>
  <div style="display:flex;align-items:center;justify-content:space-between;gap:var(--tp-space-3)">
    <span>Q3 roadmap</span>
    <tp-badge variant="outline">Draft</tp-badge>
  </div>
</div>`}
/>

One badge per row names the row's state, and its variant says how much the state matters.

### Marks and progress

<Preview
  code={`<tp-badge variant="secondary">
  <tp-icon id="badge-verified-icon" size="var(--tp-icon-size-xs)"></tp-icon>
  Verified
</tp-badge>
<tp-badge variant="outline">
  <tp-spinner size="sm" label=""></tp-spinner>
  Processing
</tp-badge>
<tp-badge variant="destructive">
  <tp-icon id="badge-failed-icon" size="var(--tp-icon-size-xs)"></tp-icon>
  Payment failed
</tp-badge>`}
  script={`import { checkIcon } from '@tweakpad/ui/icons/check';
import { circleAlertIcon } from '@tweakpad/ui/icons/circle-alert';

document.getElementById('badge-verified-icon').icon = checkIcon;
document.getElementById('badge-failed-icon').icon = circleAlertIcon;`}
/>

An Icon or a Spinner before the text is a decorative mark (no icon label, `label=""` on the Spinner) when the text already says what it means. Badge does not announce changes; a state that assistive technology must hear belongs in a live region the application owns.

### Counts in buttons

<Preview
  code={`<tp-button variant="outline">Inbox <tp-badge variant="secondary">8</tp-badge></tp-button>
<tp-button variant="ghost">Pull requests <tp-badge variant="outline">3 open</tp-badge></tp-button>`}
/>

Inside a Button the badge stays passive, so the composition keeps one interactive target whose accessible name includes the count. A bare number works here because the button text supplies the noun.

### Filter chips

<Preview
  code={`<div id="badge-filters" style="display:flex;flex-wrap:wrap;align-items:center;gap:var(--tp-space-4)">
  <tp-badge interactive variant="secondary" data-filter="open">Open · 12</tp-badge>
  <tp-badge interactive variant="outline" data-filter="mine">Assigned to me · 4</tp-badge>
  <tp-badge interactive variant="outline" data-filter="archived" disabled>Archived · 0</tp-badge>
  <tp-badge interactive variant="link" data-link>Release notes</tp-badge>
</div>`}
  script={`import { html } from 'lit';

await customElements.whenDefined('tp-badge');
const asButton = {
  badge: {
    renderDelegate: ({ state, bind, content }) =>
      html\`<button type="button" ?disabled=\${state.disabled} \${bind}>\${content}</button>\`,
  },
};
const asLink = {
  badge: {
    renderDelegate: ({ bind, content }) => html\`<a href="#filter-chips" \${bind}>\${content}</a>\`,
  },
};
for (const badge of document.querySelectorAll('#badge-filters tp-badge')) {
  badge.partContracts = badge.hasAttribute('data-link') ? asLink : asButton;
  if (badge.dataset.filter) {
    badge.addEventListener('click', () => {
      badge.variant = badge.variant === 'secondary' ? 'outline' : 'secondary';
    });
  }
}`}
/>

`interactive` declares that a badge acts; the `badge` part contract supplies the native element that does, a button for a chip and a link for navigation, with `bind` on that element and `content` inside it. The pill keeps its size while its pointer target grows to the minimum, so leave room between interactive badges. The `link` variant alone never navigates; for a full action, form or loading behavior, use Button.

### Variants

<Preview
  code={`<tp-badge>Default</tp-badge>
<tp-badge variant="secondary">Secondary</tp-badge>
<tp-badge variant="destructive">Destructive</tp-badge>
<tp-badge variant="success">Success</tp-badge>
<tp-badge variant="warning">Warning</tp-badge>
<tp-badge variant="outline">Outline</tp-badge>
<tp-badge variant="ghost">Ghost</tp-badge>
<tp-badge variant="link">Link</tp-badge>`}
/>

`variant` is visual emphasis only: `destructive` for failures and blocking problems, `success` and `warning` for healthy and degraded states, `secondary` or `outline` for neutral metadata, the default for the one thing you want noticed.

## Usage

An Attachment presents a file or resource the user added or received: in a composer before sending, in a message, or in a list of documents. `filename` names it and the actions generated for it; `description` carries type, size or progress. The application owns uploading, retrying, previewing and removing, and `status` only changes how the attachment looks.

### An upload queue

<Preview
  align="stretch"
  code={`<div style="display:grid;gap:var(--tp-space-2);max-inline-size:28rem">
  <tp-attachment filename="contract-v3.docx" description="Ready to upload · 220 KB" status="idle" removable></tp-attachment>
  <tp-attachment filename="product-demo.mp4" description="Uploading · 38%" status="uploading"></tp-attachment>
  <tp-attachment filename="survey-results.xlsx" description="Scanning for viruses" status="processing"></tp-attachment>
  <tp-attachment filename="receipt-0412.heic" status="error" error-message="HEIC isn't supported. Export as JPG or PNG and try again." removable></tp-attachment>
  <tp-attachment filename="brand-guidelines.pdf" file-size="3355443" status="complete" href="#an-upload-queue" removable></tp-attachment>
</div>`}
/>

While a file is busy and has no media of its own, a Spinner takes the media's place. An error has to say how to recover, through `error-message` or the description. Without a description, `file-size` is formatted for the reader's locale, and `href` makes a finished upload a link to the file.

### A composer's tray

<Preview
  align="stretch"
  code={`<tp-attachment-group id="attachment-tray" aria-label="Files attached to this message" style="max-inline-size:32rem">
  <tp-attachment size="sm" filename="launch-brief.pdf" description="PDF · 2.4 MB" status="complete" removable>
    <tp-icon slot="media" data-icon="file"></tp-icon>
  </tp-attachment>
  <tp-attachment size="sm" filename="brand-assets.zip" description="ZIP · 48 MB" status="complete" removable>
    <tp-icon slot="media" data-icon="folder"></tp-icon>
  </tp-attachment>
  <tp-attachment size="sm" filename="meeting-room.jpg" description="JPG · 2.1 MB" media-treatment="image" status="complete" removable>
    <img slot="media" src="https://images.unsplash.com/photo-1497366811353-6870744d04b2?w=400&q=80" alt="">
  </tp-attachment>
</tp-attachment-group>`}
  script={`import { fileTextIcon } from '@tweakpad/ui/icons/file-text';
import { folderIcon } from '@tweakpad/ui/icons/folder';

const tray = document.getElementById('attachment-tray');
for (const icon of tray.querySelectorAll('tp-icon')) {
  icon.icon = icon.dataset.icon === 'folder' ? folderIcon : fileTextIcon;
}
tray.addEventListener('tp-remove', (event) => event.target.remove());`}
/>

Rows scroll the same way as cards, so a tray of files above a message box stays one line high, and a smaller `size` keeps it compact. The group takes focus so a keyboard user can scroll it. Remove fires a cancelable `tp-remove` and removes nothing itself: the handler decides, so it can confirm first or delete the upload on the server.

Media is optional: notes, linked pages and other resources without a file type read cleanly as a title, with or without a description.

### Preview, download and retry

<Preview
  align="stretch"
  code={`<div style="display:grid;gap:var(--tp-space-2);max-inline-size:28rem">
  <tp-attachment filename="research-summary.txt" description="Text · 1 KB · Select to preview" status="complete">
    <tp-icon slot="media" id="attachment-summary-icon"></tp-icon>
    <tp-button slot="trigger" id="attachment-preview-trigger" aria-label="Preview research-summary.txt"></tp-button>
    <tp-button slot="actions" id="attachment-download" variant="ghost" size="sm" download="research-summary.txt">Download</tp-button>
  </tp-attachment>
  <tp-attachment id="attachment-retry-target" filename="interview-notes.docx" status="error" error-message="The upload was interrupted. Retry to continue.">
    <tp-button slot="actions" id="attachment-retry" variant="ghost" size="sm">Retry</tp-button>
  </tp-attachment>
  <tp-dialog id="attachment-preview-dialog" label="research-summary.txt" description="Uploaded by Priya Shah · 2 June">
    <p style="margin:0">Twelve of fifteen customers asked for shared dashboards. Most export to spreadsheets today and rebuild the same charts every week.</p>
    <tp-button slot="close">Close</tp-button>
  </tp-dialog>
</div>`}
  script={`import { fileTextIcon } from '@tweakpad/ui/icons/file-text';

await customElements.whenDefined('tp-dialog');
document.getElementById('attachment-summary-icon').icon = fileTextIcon;
const summary = 'Research summary\\n\\nTwelve of fifteen customers asked for shared dashboards.';
document.getElementById('attachment-download').href = URL.createObjectURL(
  new Blob([summary], { type: 'text/plain' }),
);
document
  .getElementById('attachment-preview-dialog')
  .registerTrigger(document.getElementById('attachment-preview-trigger'));

document.getElementById('attachment-retry').addEventListener('click', (event) => {
  const attachment = document.getElementById('attachment-retry-target');
  event.currentTarget.remove();
  attachment.status = 'uploading';
  attachment.description = 'Uploading · 40%';
  setTimeout(() => {
    attachment.status = 'complete';
    attachment.description = 'Word · 64 KB';
  }, 1600);
});`}
/>

A `trigger` Button makes the whole attachment open something, here a preview Dialog it is registered with. Buttons in the `actions` slot stay separate controls, so Download and Retry never set the trigger off; give the trigger a name, since it has no visible text.

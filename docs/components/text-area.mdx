## Usage

A Text area shares the Input's value, editing and form model but keeps newlines: Enter inserts a line instead of submitting the form. Labels, descriptions and errors belong to the Field around it; a standalone Text area can take `label` for its accessible name. The default theme sizes the editor to its content from a minimum height, so short replies stay compact and long ones never scroll.

### Release notes

<Preview
  align="stretch"
  code={`<tp-field label="Release notes" description="Fixed at six rows; drag the corner to resize.">
  <tp-text-area id="text-area-notes" rows="6" placeholder="Summarize the changes in this release"></tp-text-area>
</tp-field>`}
  script={`document.getElementById('text-area-notes').hostProperties = { style: { fieldSizing: 'fixed' } };`}
/>

For a fixed height, set native fixed sizing through `hostProperties` and choose the height with `rows`. `resize` decides which way people can drag the corner: taller by default, not at all with `none`, or wider too with `inline` and `both`.

### Request body

<Preview
  align="stretch"
  code={`<tp-field label="Request body">
  <tp-text-area mono name="body" rows="5" default-value='{
  "event": "invoice.paid",
  "retry": 3
}'></tp-text-area>
</tp-field>`}
/>

`mono` shows the value in the mono font and turns off spell checking, autocorrection and autocapitalization, for JSON, queries and other text that autocorrection would break.

### Status update

<Preview
  align="stretch"
  code={`<div style="display:grid;gap:var(--tp-space-2)">
  <tp-field label="Status update">
    <tp-text-area id="text-area-status" name="status" maxlength="280" default-value="Shipping the new billing dashboard to all workspaces this afternoon."></tp-text-area>
  </tp-field>
  <output id="text-area-status-count" style="justify-self:end;color:var(--tp-muted-foreground);font-size:var(--tp-text-sm)">68 / 280</output>
</div>`}
  script={`const status = document.getElementById('text-area-status');
const count = document.getElementById('text-area-status-count');
status.addEventListener('tp-value-change', (event) => {
  count.textContent = event.detail.value.length + ' / 280';
});`}
/>

`maxlength` stops typing at the limit, and a counter beside the editor tells people how close they are. Typing, pasting and clearing each publish a cancelable `tp-value-change` with the proposed text, which suits live counters and previews; cancelling it rolls the edit back.

### Reply

<Preview
  align="stretch"
  code={`<tp-form>
  <tp-field label="Reply to Maya Chen">
    <tp-text-area name="reply" required maxlength="500" placeholder="Write a reply"></tp-text-area>
  </tp-field>
  <div slot="actions">
    <tp-button type="submit">Send reply</tp-button>
    <tp-button type="reset" variant="outline">Discard</tp-button>
  </div>
</tp-form>`}
/>

The native textarea submits with its form, and a reset restores `default-value`. `required` and `minlength` validate through the Field like any other constraint; a value people may read and copy but not edit is `readonly`, which keeps it in the form data where `disabled` drops it.

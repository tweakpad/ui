## Usage

Select picks from a list that is too long, or too dynamic, to show as radios. Native `option`, `optgroup` and `hr` children declare the choices; the component renders its own list, keyboard navigation and typeahead, and submits the selected value under `name`. Use Native Select when the browser's own picker is preferable, such as on mobile-first forms.

The default selected-item alignment is established when the popup opens. Hovering an option changes its highlight without moving the popup or scrolling the list. Keyboard navigation reveals the focused option within the list.

Item alignment attempts to place the selected/highlighted option against the Trigger. Collision correction also adjusts list scroll; unusable items or insufficient room fall back to ordinary placement.

### Options

Each `option` contributes a `value` and its text. `disabled` keeps an option visible but unselectable, `optgroup` labels a group and `hr` draws a separator. `placeholder` shows while nothing is selected.

<Preview
  title="Groups and disabled options"
  align="stretch"
  code={`<tp-field label="Plan" style="max-inline-size:20rem">
  <tp-select name="plan" placeholder="Choose a plan">
    <option value="free">Free</option>
    <option value="team">Team · $12 per seat</option>
    <option value="business">Business · $24 per seat</option>
    <hr>
    <option value="enterprise" disabled>Enterprise · Contact sales</option>
  </tp-select>
</tp-field>`}
/>

Native `option`, `optgroup` and `hr` sources are supported, including inherited optgroup disability.

### Authored options

`tp-select-option` is the library's own option element. It declares the same choice as a native `option`, accepts a non-string `value` when set as a property, and uses its text content as the label.

### Searchable

`searchable` swaps the trigger for an editable query that filters the list as people type. `matching` chooses `contains` (the default), `prefix`, `exact` or typo-tolerant `fuzzy`; `highlight-matches` marks the matched text. The query is never submitted, only the selection.

<Preview
  title="Searchable"
  align="stretch"
  code={`<tp-field label="Country" style="max-inline-size:20rem">
  <tp-select name="country" searchable highlight-matches placeholder="Search countries">
    <option value="AR">Argentina</option>
    <option value="AU">Australia</option>
    <option value="BR">Brazil</option>
    <option value="CA">Canada</option>
    <option value="DE">Germany</option>
    <option value="IN">India</option>
    <option value="JP">Japan</option>
    <option value="NL">Netherlands</option>
    <option value="SE">Sweden</option>
    <option value="GB">United Kingdom</option>
    <option value="US">United States</option>
  </tp-select>
</tp-field>`}
/>

The query, selection and open state are independent.

Set a controlled property before connection to select that lane's controlled mode. The owner accepts a proposal synchronously by updating the corresponding property in its callback. Leaving the proposal unaccepted or cancelling it restores that lane. Use `defaultValue`, `defaultInputValue` and `defaultOpen` for uncontrolled defaults; these are sampled initially and restored on form reset. `multiple` determines the selection shape: `null` or one value, versus an ordered unique array.

`matching` selects how the query matches options: `contains` (the default; locale collation, so case, accents and punctuation are ignored), `prefix` (every query word begins a word), `exact`, or `fuzzy`, which ranks options by relevance and tolerates typos and words typed out of order. Results come from, in order: `filteredItems`, a `source`, a `filter`, and otherwise `matching`; `limit` applies last.

Filtering retains selected values even when their options are not visible.

In list mode, highlighting does not change text. Both mode filters and shows a temporary selected completion suffix; inline completion keeps the item set static; none keeps it static without a completion. IME input does not navigate or commit prematurely. Arrow keys, Home/End and Enter operate through the editor's active descendant while DOM focus stays in the editor.

### Searchable multiple

With both `searchable` and `multiple`, selections show as removable chips beside the query. Backspace removes the last chip, and `show-clear` adds a button that clears the query or the selection.

<Preview
  title="Chips"
  align="stretch"
  code={`<tp-field label="Labels" style="max-inline-size:24rem">
  <tp-select name="labels" searchable multiple show-clear placeholder="Add labels">
    <option value="Bug">Bug</option>
    <option value="Design">Design</option>
    <option value="Documentation">Documentation</option>
    <option value="Performance">Performance</option>
    <option value="Security">Security</option>
    <option value="UX research">UX research</option>
  </tp-select>
</tp-field>`}
/>

Contextual Clear clears a nonempty query, otherwise selection. The Clear action shows only while the lane it clears has something to clear. Both Clear proposes both lanes atomically: cancelling either proposal leaves both committed values unchanged. Chip Remove has an accessible value-specific name; directional keys move between chips, and Backspace/Delete remove through the same selection owner.

### Grid

In a searchable Select with `grid`, `columns` lays each group's options out in rows of that many, and the arrow keys move in two dimensions. Filtering reflows the rows. It suits short, scannable options such as sizes, flags or symbols.

<Preview
  title="Columns"
  align="stretch"

  <tp-select name="size" searchable grid columns="4" placeholder="Pick a size">
    <option value="XS">XS</option>
    <option value="S">S</option>
    <option value="M">M</option>
    <option value="L">L</option>
    <option value="XL">XL</option>
    <option value="2XL">2XL</option>
    <option value="3XL">3XL</option>
    <option value="4XL">4XL</option>
  </tp-select>
</tp-field>`}

Grid records can specify `row`; actual Row containers match those logical rows. With `columns`, rows are formed instead from each group's visible options in displayed order, so filtering reflows them. When a ranked search gathers options into their groups, the arrow keys follow the displayed order.

### Data

Assign `items` when choices come from your data. Records take a `value` and `label`, groups take `type: 'group'` with nested `items`, and `type: 'separator'` divides them.

  align="stretch"

  <tp-select id="select-items" name="assignee" placeholder="Unassigned"></tp-select>
</tp-field>`}
  script={`const select = document.querySelector('#select-items');
select.items = [
  { type: 'group', label: 'Design', items: [
    { value: 'u_102', label: 'Maya Lindqvist' },
    { value: 'u_118', label: 'Tomás Herrera' },
  ] },
  { type: 'group', label: 'Engineering', items: [
    { value: 'u_131', label: 'Priya Natarajan' },
    { value: 'u_140', label: 'Jonas Becker' },
    { value: 'u_152', label: 'Aiko Sato', disabled: true },
  ] },

/>

A record's `label` can be a Lit template for rich rows, such as an avatar or a badge. Give those records a plain `text` too; it drives typeahead and what the closed trigger reads.

/>

`isItemEqual` defines identity for object values; labels and the form's serialized values are separate concerns. Form serialization uses `String(value)`, including unmatched controlled values.

Later duplicate values are diagnosed and excluded from navigation and selection.

Object-valued choices use `{value: record, label: 'Display text'}`; use the factory for arbitrary application records with primitive IDs.

`createSelectItems(data, {getValue, getLabel, diagnostic?})` lazily projects application records onto non-null primitive identifiers. It accepts absent loading data, flat data or groups, ignores holes and retains the first duplicate. Leaf records cannot themselves declare an `items` array. The returned collection provides `value`, `itemLabel`, `hasValue` and `label` (including equality and fallback arguments). `createSelectFilter({locale?, sensitivity?, ignorePunctuation?, ...Intl.CollatorOptions})` exposes locale-aware `contains`, `startsWith` and `endsWith`.

### Large lists

`virtualized` mounts only the rows near the visible part of the list while keeping its full scroll height, so hundreds or thousands of `items` open instantly. Keyboard navigation and typeahead still cover every option.

<Preview
  title="Virtualized time zones"
  align="stretch"
  code={`<tp-field label="Time zone" style="max-inline-size:20rem">
  <tp-select id="select-virtualized" name="time-zone" searchable virtualized placeholder="Search time zones"></tp-select>
</tp-field>`}
  script={`const select = document.querySelector('#select-virtualized');
select.items = Intl.supportedValuesOf('timeZone').map((zone) => ({
  value: zone,
  label: zone.replaceAll('_', ' '),
}));`}
/>

Virtualized mode requires the full ordered source. With `mountedItems`, you own the window: it controls only rendering, and `onItemHighlighted` supplies the source value, logical index and reason so you can bring an unmounted active record into view.

### Remote search

A `source` supplies the options for each query, such as a server endpoint. A query waits `search-delay` milliseconds after the last keystroke, a newer query aborts the previous one through `signal`, and the list shows a loading row meanwhile.

<Preview
  title="Search source"
  align="stretch"
  code={`<tp-field label="Customer" style="max-inline-size:20rem">
  <tp-select id="select-source" name="customer" searchable search-delay="250" placeholder="Search customers"></tp-select>
</tp-field>`}
  script={`const customers = [
  'Acme Logistics', 'Birchwood Dental', 'Cobalt Robotics', 'Delta Freight', 'Evergreen Grocers',
  'Fjord Outfitters', 'Granite Legal', 'Harbor Coffee', 'Ironclad Security', 'Juniper Health',
  'Keystone Builders', 'Lumen Studios', 'Meridian Travel', 'Northwind Traders', 'Orchard Bakery',
];
const select = document.querySelector('#select-source');
select.source = {
  // Stands in for fetch('/api/customers?q=' + query, { signal }).
  search: (query, { signal }) =>
    new Promise((resolve, reject) => {
      const timer = setTimeout(() => {
        const needle = query.trim().toLowerCase();
        resolve(customers
          .filter((name) => name.toLowerCase().includes(needle))
          .map((name) => ({ value: name.toLowerCase().replaceAll(' ', '-'), label: name })));
      }, 600);
      signal.addEventListener('abort', () => {
        clearTimeout(timer);
        reject(signal.reason);
      });
    }),
};`}
/>

With `source`, the source's results are the options: a query waits `searchDelay` milliseconds without typing, a newer query aborts the previous one, previous results stay visible while loading, and `searchStatus` (`idle`, `loading`, `loaded`, `error`) with the `tp-search-status` and `tp-search-error` events report progress. While loading the list is busy and a status row (spinner and text) replaces the empty state; after a failure it shows the error text. The status region announces the same text.

### Value changes

`tp-value-change` reports each proposed selection with its `reason`, and is cancelable. Read the committed value from `value`.

<Preview
  title="Value change"
  align="stretch"
  code={`<div style="display:grid;gap:var(--tp-space-3);max-inline-size:20rem">
  <tp-field label="Sort by">
    <tp-select id="select-sort" default-value="updated">
      <option value="updated">Last updated</option>
      <option value="created">Date created</option>
      <option value="name">Name</option>
    </tp-select>
  </tp-field>
  <output id="select-sort-output" style="color:var(--tp-muted-foreground);font-size:var(--tp-text-sm)">Sorted by updated</output>
</div>`}
  script={`const select = document.querySelector('#select-sort');
const output = document.querySelector('#select-sort-output');
select.addEventListener('tp-value-change', (event) => {
  if (event.target !== select || event.detail.cancelled) return;
  output.textContent = 'Sorted by ' + event.detail.value;
});`}
/>

Supply either `defaultValue` for an uncontrolled Select or `value` plus an owner that accepts proposals. Ownership is fixed when the component initializes. The getter exposes committed state, including during a callback. A controlled owner publishes an accepted proposal synchronously; a later listener can still veto the proposal. DOM events bubble across the shadow boundary.

<Code code={`select.value = 'apple'; // configure before connecting the element
select.onValueChange = (event) => {
  if (event.defaultPrevented || event.detail.cancelled) return;
  select.value = event.detail.value;
  queueMicrotask(() => console.log('Committed:', select.value));
};`} language="js" />

An accepted single selection closes on the item press, even when a controlled owner publishes the value later; multiple selection stays open. A canceled proposal keeps the popup open, and a controlled rejection keeps the committed markers and form value.

### In a dialog

A Select works inside a Dialog without extra setup: its popup belongs to the dialog, so it opens above the modal and stays interactive while the rest of the page is inert.

Inline mode renders an in-flow list without its own portal, positioner or popup; accepted closing of its surrounding Dialog, Alert Dialog, Drawer or Popover resets transient query/highlight.

### Keyboard and composition

Enter, Space or Alt+ArrowDown opens. Arrow keys move through enabled options; Home/End go to the boundaries. Typeahead appends exact keys, matches a locale lower-case prefix, and resets after 750 ms, on opening, or immediately after unmatched non-space input. Repeated-key cycling is available only when no non-null label starts with two identical characters. Printable text performs typeahead and does not filter the list. Composition input does not select. Enter/Space activates the highlighted option. Escape closes without selecting; Tab closes and continues normal traversal. Scroll controls respond only while their direction has overflow and stop repeating when the pointer leaves, the popup closes or the host detaches.

Use actual `tp-field` for labels/descriptions/errors, `tp-icon` for rich choice artwork, `tp-button` for adjacent actions and `tp-dialog` for modal composition.

## Usage

Autocomplete's value is the text itself: picking a suggestion replaces the text, and the form receives whatever was typed, even text that matches no suggestion. When the value must be one of the items, use a searchable Select instead. Suggestions come from `option` children, from the `items` property, or from a search source; a Field gives the input its label.

By default suggestions are ranked by relevance and tolerate typos and words typed out of order, so "rasberry" still finds Raspberry, and the matched text is highlighted.

### Country search

<Preview
  code={`<tp-field label="Country" description="Type the start of each word: un st" style="inline-size:20rem">
  <tp-autocomplete name="country" matching="prefix" placeholder="Search countries">
    <option>United Kingdom</option>
    <option>United States</option>
    <option>United Arab Emirates</option>
    <option>South Africa</option>
    <option>South Korea</option>
    <option>New Zealand</option>
  </tp-autocomplete>
</tp-field>`}
/>

For names, codes and lists where a typo match would be noise, `matching="prefix"` matches the start of each word and keeps the items in their given order; `contains` and `exact` do the same with looser and stricter tests.

When people are as likely to browse as to type, `show-trigger` adds a button that opens the full list and `open-on-input-click` opens it on a click in the text. `optgroup` children label sections of suggestions.

### Assigning a teammate

<Preview
  code={`<tp-field label="Assign to" style="inline-size:20rem">
  <tp-autocomplete name="assignee" completion-mode="both" auto-highlight show-clear placeholder="Teammate name">
    <option>Amara Okafor</option>
    <option>Daniel Kim</option>
    <option>Lucía Fernández</option>
    <option>Maya Chen</option>
    <option>Noah Williams</option>
  </tp-autocomplete>
</tp-field>`}
/>

For a short, known list, `completion-mode="both"` fills in the rest of the highlighted name as you type, with the completed part selected so typing simply continues. `auto-highlight` highlights the first suggestion, so Enter accepts it, and `show-clear` adds a button that empties the text.

### Command search

<Preview
  code={`<tp-field label="Command" description="Try: invoice, teammate, dark" style="inline-size:20rem">
  <tp-autocomplete id="autocomplete-commands" placeholder="Search commands"></tp-autocomplete>
</tp-field>`}
  script={`const commands = [
  { value: 'Create invoice', keywords: ['bill', 'billing', 'payment'] },
  { value: 'Invite member', keywords: ['teammate', 'user', 'people'] },
  { value: 'Change theme', keywords: ['dark', 'light', 'appearance'] },
  { value: 'Export data', keywords: ['csv', 'download', 'backup'] },
];

await customElements.whenDefined('tp-autocomplete');
const autocomplete = document.getElementById('autocomplete-commands');
autocomplete.items = commands.map(({ value }) => value);
autocomplete.matchFields = (item) => commands.find((command) => command.value === item)?.keywords ?? [];`}
/>

People rarely know the exact name of a command. `matchFields` adds searchable text that is never shown, such as aliases or keywords, so "dark" finds Change theme.

### Help center articles

<Preview
  code={`<tp-field label="Help center" description="Try: refund, password, seats" style="inline-size:20rem">
  <tp-autocomplete id="autocomplete-articles" placeholder="Search articles"></tp-autocomplete>
</tp-field>`}
  script={`import { createIndexSource } from '@tweakpad/ui';

const articles = [
  { title: 'Request a refund', summary: 'Refunds for annual plans within 30 days of purchase.' },
  { title: 'Reset your password', summary: 'Get a sign-in link by email when you forget your password.' },
  { title: 'Add or remove seats', summary: 'Change how many members your plan pays for.' },
  { title: 'Download invoices', summary: 'Receipts and refund credit notes for every billing period.' },
  { title: 'Turn on two-step sign-in', summary: 'Protect your password with an authenticator app.' },
];

await customElements.whenDefined('tp-autocomplete');
const autocomplete = document.getElementById('autocomplete-articles');
autocomplete.itemToText = (article) => article.title;
autocomplete.source = createIndexSource(articles, {
  fields: ['title', 'summary'],
  boost: { title: 3 },
  extract: (article, field) => article[field],
});`}
/>

`createIndexSource()` builds the same typo-tolerant index over records with several fields. Here it searches each article's title and summary but weighs the title three times, so "refund" lists Request a refund before the invoices article that only mentions it. `itemToText` names each record in the list and in the text.

### Departure airports

<Preview
  code={`<tp-field label="Departure airport" description="Results arrive after a simulated request." style="inline-size:20rem">
  <tp-autocomplete id="autocomplete-airports" name="airport" search-delay="250" placeholder="City or airport code"></tp-autocomplete>
</tp-field>`}
  script={`const airports = [
  'Amsterdam Schiphol (AMS)', 'Barcelona El Prat (BCN)', 'Berlin Brandenburg (BER)',
  'Dublin (DUB)', 'Frankfurt (FRA)', 'Lisbon Humberto Delgado (LIS)', 'London Heathrow (LHR)',
  'London Gatwick (LGW)', 'Madrid Barajas (MAD)', 'Milan Malpensa (MXP)', 'Munich (MUC)',
  'Paris Charles de Gaulle (CDG)', 'Rome Fiumicino (FCO)', 'Vienna (VIE)', 'Zurich (ZRH)',
];

await customElements.whenDefined('tp-autocomplete');
document.getElementById('autocomplete-airports').source = {
  // Stands in for fetch('/api/airports?q=' + query, { signal }).
  search(query, { signal }) {
    return new Promise((resolve, reject) => {
      const timer = setTimeout(() => {
        const text = query.trim().toLowerCase();
        resolve(airports.filter((airport) => airport.toLowerCase().includes(text)).slice(0, 8));
      }, 600);
      signal.addEventListener('abort', () => {
        clearTimeout(timer);
        reject(signal.reason);
      });
    });
  },
};`}
/>

A source's `search(query, context)` returns results, directly or as a promise, in the order they should appear, typically from a server. `search-delay` waits for a pause in typing and each new query aborts the previous one through `context.signal`; while a request is pending the list keeps the previous suggestions, or shows a loading row when there are none. `createRequestSource()` builds such a source from a URL and a response mapper.

### Profile form

<Preview
  code={`<tp-form id="autocomplete-profile" aria-label="Profile" style="inline-size:20rem">
  <tp-field label="Job title">
    <tp-autocomplete name="title" required submit-on-item-click placeholder="e.g. Product designer">
      <option>Product designer</option>
      <option>Product manager</option>
      <option>Frontend engineer</option>
      <option>Data analyst</option>
    </tp-autocomplete>
  </tp-field>
  <div slot="actions">
    <tp-button type="submit">Save profile</tp-button>
  </div>
  <output id="autocomplete-profile-result" style="color:var(--tp-muted-foreground);font-size:var(--tp-text-sm)"></output>
</tp-form>`}
  script={`const form = document.getElementById('autocomplete-profile');
const result = document.getElementById('autocomplete-profile-result');
form.onFormSubmit = (values, { data }) => {
  result.textContent = 'Saved: ' + data.get('title');
};`}
/>

With a `name`, the form receives the text, and `required` asks for some. Enter with no suggestion highlighted submits the form, and `submit-on-item-click` also submits as soon as a suggestion is picked, which suits a field that is the only thing to fill in.

## Keyboard

| Key | Action |
| --- | --- |
| <Keys keys="down" /> <Keys keys="up" /> | Open the suggestions and move the highlight through them. |
| <Keys keys="enter" /> | Accepts the highlighted suggestion; with none highlighted, submits the form. |
| <Keys keys="escape" /> | Closes the suggestions; pressed again, clears the text. |

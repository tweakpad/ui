## Usage

The value is a CSS Color 4 string serialized in the active format, while the widget keeps a floating-point color internally, so switching formats or dragging never accumulates rounding. Give the picker an inline size; its surfaces fill the width they get.

The default composition is the saturation/brightness area with hue and alpha Sliders, a format Select and numeric fields.

### Popup

`picker="popup"` puts the panel in a Popover opened from a Color input swatch. The popup header compares the original and current colors, copies the value and offers the eyedropper; pressing the original restores it.

<Preview
  title="Popup in a field"
  code={`<tp-field label="Button color" description="Used for primary actions in the theme.">
  <tp-color-picker picker="popup" name="button-color" default-value="#0f766e"></tp-color-picker>
</tp-field>`}
/>

`formatSelect`, `preview` and `eyedropper` hide their header items as they hide the inline ones. Author `slot="trigger"` content to replace the default trigger. `open` / `defaultOpen`, `setOpen(open, reason?)` and `close()` forward to the Popover, which remains the state owner; its `tp-open-change` and `tp-open-change-complete` events are re-dispatched from the widget with the Popover's reasons. Opening moves focus to the first dimension of the active view and closing returns it to the trigger.

A Color input in the `trigger` slot opens the popup instead of the browser's picker and always shows the picker's color. An inline one shows the color as a row with its text: a color typed there becomes the picker's value.

<Preview
  title="Color input trigger"
  align="stretch"
  code={`<tp-color-picker picker="popup" name="card-fill" default-value="#0f766e" style="display:block;max-inline-size:20rem;margin-inline:auto">
  <tp-color-input slot="trigger" variant="inline" label="Card fill"></tp-color-input>
</tp-color-picker>`}
/>

### In a form

With a `name`, the picker submits its string through the surrounding form and takes part in reset. Recent colors are application state: record each commit and hand the last few back through `recent`, and they appear in the popup's swatch strip.

<Preview
  title="Popup in a form"
  align="stretch"
  code={`<form id="color-picker-form" style="display:grid;gap:var(--tp-space-4);max-inline-size:24rem;margin-inline:auto">
  <tp-field label="Workspace color" description="Shown in the sidebar and on invitations.">
    <tp-color-picker picker="popup" name="workspace-color" default-value="#6d5dfc"></tp-color-picker>
  </tp-field>
  <div style="display:flex;gap:var(--tp-space-2)">
    <tp-button type="submit">Save</tp-button>
    <tp-button type="reset" variant="outline">Reset</tp-button>
  </div>
</form>
<output id="color-picker-form-output" style="display:block;margin-block-start:var(--tp-space-3);text-align:center;color:var(--tp-muted-foreground);font-size:var(--tp-text-sm)">Pick a color, then save.</output>`}
  script={`const form = document.querySelector('#color-picker-form');
const picker = form.querySelector('tp-color-picker');
const output = document.querySelector('#color-picker-form-output');
let recent = [];
picker.addEventListener('tp-value-commit', (event) => {
  if (!event.detail.value || event.detail.metadata?.formatChange) return;
  recent = [event.detail.value, ...recent.filter((color) => color !== event.detail.value)];
  picker.recent = recent.slice(0, 5);
});
form.addEventListener('submit', (event) => {
  event.preventDefault();
  output.textContent = \`Saved \${new FormData(form).get('workspace-color')}\`;
});`}
/>

The widget is form-associated: `name` submits the value string, uncontrolled reset restores the default (`form-reset`), `required` reports a missing value with `strings.valueMissing`, and restoration updates uncontrolled state. Place the picker inside `tp-field` for a label, description and error; the Field names the root group and label activation focuses the first dimension.

### Formats

`format` never follows the notation you supply: any CSS color goes in, and `value` reads back in the active format. `formats` limits the format Select; `alpha="false"` drops alpha and keeps every published value opaque.

<Preview
  title="Limited formats, no alpha"
  code={`<tp-color-picker label="Text color" default-value="rgb(30 41 59)" default-format="oklch" formats="hex rgb oklch" alpha="false" style="inline-size:18rem"></tp-color-picker>`}
/>

The widget accepts every CSS Color 4 absolute notation (hex with 3, 4, 6 or 8 digits, legacy and modern `rgb()` / `hsl()`, `hwb()`, `lab()`, `lch()`, `oklab()`, `oklch()`, `color()` in the sRGB, linear sRGB and XYZ spaces, named colors, `transparent`, `none`) plus the non-CSS `hsv()` and `device-cmyk()` notations. Whatever notation an owner supplies, `value` reads back as the canonical serialization of the active format: modern space-separated syntax, lowercase, alpha appended as `/ a` only when it is below 1 after rounding to two decimals.

Changing the format proposes `tp-format-change` (cancelable); once accepted, the widget publishes the re-serialized value through a non-cancelable `tp-value-change` followed by `tp-value-commit` with `metadata.formatChange: true`. The color itself is invariant across formats.

The read-only `color` property exposes the floating-point `{ space, coords, alpha }` record; `hsv()` and `device-cmyk()` strings are not parsable by the browser, so consumers that need CSS read `color` or pick another format.

Typing a hex value without alpha digits keeps the current alpha, text that does not parse reverts to the current color, and a hue of 360 stays 360. A drag through black, white or gray keeps the last chromatic hue and saturation.

### Views

`views` lists the available views; more than one renders a tab strip. Channel sliders edit each channel of the format, the wheel derives harmony colors from a base, and the triangle is the classic hue ring around an HSV triangle.

<Preview
  title="Channel sliders"
  code={`<tp-color-picker label="Surface" views="sliders" default-format="oklch" default-value="oklch(0.586 0.227 281.3)" style="inline-size:18rem"></tp-color-picker>`}
/>

<Preview
  title="Harmony wheel and triangle"
  code={`<div style="display:flex;flex-wrap:wrap;gap:var(--tp-space-8);justify-content:center">
  <tp-color-picker label="Campaign palette" views="wheel" default-harmony="triad" default-value="#e53935" style="inline-size:18rem"></tp-color-picker>
  <tp-color-picker label="Tint" views="triangle" default-value="#43a047" style="inline-size:18rem"></tp-color-picker>

/>

`default-harmony` sets the starting rule; a `harmony` attribute makes the rule controlled. The ring around the wheel copies each harmony color on press.

Derived handles follow the base; under `custom` every handle is its own hue and saturation pair, seeded from the previous rule so the layout does not jump.

`harmonyColors` lists the base color first and then the derived ones, in the active format, so the palette can drive the rest of your interface.

<Preview
  title="Reading the palette"
  code={`<div style="display:grid;gap:var(--tp-space-3);justify-items:center">
  <tp-color-picker id="color-picker-harmony" label="Chart palette" views="wheel" default-harmony="analogous" default-value="#039be5" style="inline-size:18rem"></tp-color-picker>
  <div id="color-picker-harmony-chips" style="display:flex;gap:var(--tp-space-2)"></div>
</div>`}
  script={`const picker = document.querySelector('#color-picker-harmony');
const chips = document.querySelector('#color-picker-harmony-chips');
const render = () => {
  chips.replaceChildren(...picker.harmonyColors.map((color, index) => {
    const chip = document.createElement('span');
    chip.title = color;
    chip.setAttribute('aria-label', index === 0 ? \`Base \${color}\` : color);
    chip.style.cssText = \`inline-size:2.5rem;block-size:1.5rem;border-radius:var(--tp-radius-md);background:\${color}\`;
    return chip;
  }));
};
await customElements.whenDefined('tp-color-picker');
await picker.updateComplete;
render();
picker.addEventListener('tp-value-commit', render);
picker.addEventListener('tp-harmony-change', () => queueMicrotask(render));`}
/>

### Swatches and schemes

Saved swatches are a property, set from data; recent colors are application-owned too, since the widget keeps no history. The schemes view generates tints, shades and related strips from the current color.

<Preview
  title="Brand swatches"
  code={`<tp-color-picker id="color-picker-swatches" label="Chart series" views="area swatches schemes" default-view="swatches" default-value="#fb8c00" style="inline-size:18rem"></tp-color-picker>`}
  script={`await customElements.whenDefined('tp-color-picker');
const picker = document.querySelector('#color-picker-swatches');
picker.swatches = [
  { label: 'Brand', colors: ['#6d5dfc', '#0f766e', '#fb8c00', '#e53935'] },
  { label: 'Neutrals', colors: ['#0f172a', '#475569', '#cbd5e1', '#f8fafc'] },
];
picker.recent = ['#039be5', '#8e24aa', '#43a047'];`}
/>

`swatches` accepts strings or `{ label, colors }` groups.

Without consumer data the widget generates tints, shades, tones, analogous, complementary, triad and tetrad rows in OKLab/OKLCH from the current color, every entry gamut-mapped to sRGB; the rows stay pinned to the color they were generated from until the "Generate schemes" wand is pressed, so strips never move under a press. Supply `schemes` (`{ label, palettes: [{ label, colors }] }[]`) to replace generation with templates chosen through the Template Select. Pressing a scheme or saved swatch proposes that color (`item-press`, or `keyboard` when selected from the keyboard); pressing the selected swatch again proposes nothing.

### Listening to changes

Drags publish `tp-value-change` while moving and one `tp-value-commit` on release, so expensive work belongs on the commit. Cancel a `tp-value-change` to reject a proposal.

<Preview
  title="Commit events"
  code={`<div style="display:grid;gap:var(--tp-space-3);justify-items:center">
  <tp-color-picker id="color-picker-events" label="Highlight" default-value="#facc15" style="inline-size:18rem"></tp-color-picker>
  <output id="color-picker-events-output" style="color:var(--tp-muted-foreground);font-size:var(--tp-text-sm)">Saved: #facc15</output>
</div>`}
  script={`const picker = document.querySelector('#color-picker-events');
const output = document.querySelector('#color-picker-events-output');
picker.addEventListener('tp-value-commit', (event) => {
  output.textContent = \`Saved: \${event.detail.value}\`;
});`}
/>

`metadata` carries the floating-point `color` of the proposal and, when known, the edited `channel`, the `surface` (`area`, `wheel`, `triangle`, `slider`, `field`, `swatch`, `scheme`, `eyedropper`, `compare`) and `formatChange`. Only the widget's own events cross its boundary; the Sliders, Inputs, Selects, Tabs, Toggle Groups and Popover inside never leak their lane events.

Escape during a drag restores the pre-press value (`escape-key`) and pointer cancellation restores it as well (`pointer`); neither commits. A capture lost before the release, or a move that reports no pressed button, ends the drag where the pointer last was and commits it (`drag`), so the last release always settles. Keyboard steps, wheel scrubbing (opt-in through `allowWheelScrub`), swatches, the eyedropper, hex Enter and blur, and `setValue()` commit immediately (a paste counts as typing, so it commits on Enter or blur). Numeric fields commit when the Number field commits (Enter or blur).

### Controlled, with limits

Set `value` to own the color: each proposal arrives in `onValueChange`, and only the values you write back are shown. `event.detail.metadata.color` carries the proposal as floating-point coordinates, so you can check it before accepting. This one refuses colors too light for white button text; drag toward white and the handle stops.

<Preview
  title="Controlled owner"
  code={`<div style="display:grid;gap:var(--tp-space-3);justify-items:center">
  <tp-color-picker id="color-picker-controlled" label="Button color" value="#2622a5" default-format="hex" alpha="false" style="inline-size:18rem"></tp-color-picker>
  <tp-button id="color-picker-controlled-sample" style="--tp-primary:#2622a5;--tp-primary-foreground:#fff">Start free trial</tp-button>
</div>`}
  script={`const picker = document.querySelector('#color-picker-controlled');
const sample = document.querySelector('#color-picker-controlled-sample');
picker.onValueChange = (event) => {
  const color = event.detail.metadata?.color;
  if (color?.space === 'srgb') {
    const [r, g, b] = color.coords;
    if (0.2126 * r + 0.7152 * g + 0.0722 * b > 0.45) {
      event.preventDefault();
      return;
    }
  }
  picker.value = event.detail.value;
  sample.style.setProperty('--tp-primary', event.detail.value);
};`}
/>

A refused proposal leaves the value, every surface, the fields and the form state unchanged.

Supply `value` for a controlled picker or `defaultValue` for an uncontrolled one; the mode stays fixed for the element's lifetime. The same rule applies to the `format`, `view`, `harmony` and `open` lanes.

### Trimming the panel

The controls around the color surface can each be turned off. `fields="false"` removes the row of value boxes, `format-select="false"` the format Select, `preview="false"` the color swatch and `eyedropper="false"` the screen picker, leaving a surface for quick, approximate choices.

The fields row (`fields`), format Select (`formatSelect`), preview swatch (`preview`) and eyedropper (`eyedropper`, rendered only where the platform `EyeDropper` API exists) are independent toggles.

### Keyboard and pointer

Every editable dimension is a hidden native range input inside its thumb or handle.

| Surface / control        | Keys                                                                                                                                                                        |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Area, triangle           | Left/Right saturation, Up/Down brightness on either input; Page Up/Down, Home, End act on the focused dimension                                                             |
| Hue ring, wheel hue      | Left/Right/Up/Down step the hue; it wraps past 0 and 360                                                                                                                    |
| Wheel saturation         | arrows step saturation; Home/End reach the bounds                                                                                                                           |
| Hue and alpha Sliders    | the Slider keyboard model; the hue Slider wraps past 0 and 360 instead of clamping                                                                                          |
| Channel Sliders / fields | Slider and Number field models (arrows, Page keys, Home/End, Shift/Control/Meta for the large step, Alt for the small one)                                                  |
| Swatches, schemes        | Toggle Group roving focus; Space/Enter select                                                                                                                               |
| Popup                    | Enter/Space on the trigger opens; Escape closes and returns focus; the header's Select, original swatch, Copy button and eyedropper are ordinary stops ahead of the surface |

On the surfaces and Sliders arrow steps use the channel step; Shift, Control or Command and the Page keys use the large step, Alt the small step. The numeric fields follow the Number field model with their last displayed digit as the step (0.001 for the OK channels, 0.1 for Lab and the OKLCH hue, 1 elsewhere), so every value the fields show is valid; Shift still uses the channel's large step. Horizontal arrows follow the writing direction on the area and Sliders; angular axes (wheel, ring) do not flip. Pointer presses capture the pointer, coalesce movement to one proposal per frame and release once. A press inside a handle (the area thumb, a wheel handle, the ring or triangle thumb, a Slider thumb) keeps the pointer's offset from the handle's center, so the handle moves with the pointer instead of jumping under it; a press elsewhere moves the handle to the press point. Under a harmony rule the derived wheel handles follow the base, so a press on one of them moves nothing, and where a derived handle shares or overlaps the base's position the base still takes the press. Shift snaps coarsely and Alt moves finely on Sliders.

### Constituents and accessibility

Every dimension exposes the slider role with an accessible name of the form `${label}: ${name}` (Hue, Saturation, Brightness, Lightness, Red, …, Alpha) and value text in display precision with its unit (`242°`, `66%`, `0.628`). The area and triangle inputs sit in a group named "Saturation and brightness", the wheel in "Hue and saturation"; custom harmony handles expose "Harmony color N: Hue/Saturation". The root is a group named by `label` (or `aria-label`). Tab order per view: tabs, surface inputs, eyedropper, hue, alpha, format Select, fields, alpha field, then one roving stop per swatch group; in the popup the header (format Select, original swatch, Copy button, eyedropper) precedes the surface. The original swatch is a Button named "Restore the original color" plus the original serialization; the current swatch is decorative; the Copy button announces its result. Harmony palette segments are Copy buttons named "Copy color" plus their serialization, grouped as "Harmony palette", in the tab order right after the wheel. `strings` overrides every name (`hue`, `alpha`, `eyedropper`, `compare`, `original`, `copy`, `palette`, `savedColors`, `viewWheel`, `formatOklch`, `harmonyTriad`, `schemeTints`, …) for localization; `locale` formats the numeric fields.

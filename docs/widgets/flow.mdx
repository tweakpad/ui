## Usage

Use a Flow where people build or read a graph of steps: an automation, a data pipeline, a signal chain, a dependency map, a run of a workflow. The value is a flow document, `{ version: 1, nodes, edges }`: each node names a type, a position and its data, and each edge connects a port of one node to a port of another. `schema` describes the node types, their ports and the control each property shows, so it, and the `icons` its types name, are set from script; `load()` replaces the document, and `default-value` seeds an uncontrolled one.

In the signal chain above every port carries a data type, which decides what may connect and paints the port, and each property of a panel node is edited by the library control its definition names, inside the node. Editing a control is a change to the document like any other, so it can be undone. An edge's kind sets its path, from the default smooth steps to curves, straight lines and routed right angles; the schema's rules choose it for new connections, curves here.

The widget fills its container's inline size and needs a block size: give it one directly or let it fill a sized parent of at least its minimum height. Drag nodes to move them, drag from a port to another port to connect, scroll or pinch to pan and zoom, and press <Keys keys="delete" /> to remove the selection; <Keys keys="mod+z" /> undoes any of it. The DOM-free engine in `@tweakpad/ui/flow` reads, validates, lays out and migrates the same documents in a worker or on a server; rendering a flow does not need it.

A builder needs a place to pick nodes from and a place to tune them. `palette` adds the node library, a sidebar grouped by the schema's categories, or a menu of columns with `palette="menu"`: drag a chip onto the canvas, or click it and then click where the node goes. Every edge label carries a "+" that inserts a node on that edge, and releasing a new connection on the empty pane opens the library at the drop point.

The inspector holds the settings a definition keeps off the node; compact nodes keep all their properties there. A double press on such a node opens it, as on "Paid orders" here, and it then follows the selection; `inspector-commit="explicit"` holds its edits until Save. Both panels can also be opened from your own controls through their open state.

A fixed or server-rendered graph can be written as `tp-flow-node` and `tp-flow-edge` children, adopted into the document by `id`. // A stand-in backend: it answers each request with run events, waits on the review and fails

const push = (event) => flow.pushRunEvent({ ...event, at: performance.now() });
flow.addEventListener('tp-run-request', async (event) => {
  const { action, scope, nodeIds } = event.detail;
  const run = ++token;
  const alive = () => run === token && flow.isConnected;
  if (action === 'clear') return flow.clearRun();
  if (action === 'stop') return push({ type: 'run_cancelled' });
  push({ type: 'run_started', ...(scope === 'graph' ? {} : { scope: nodeIds }) });
  for (const nodeId of nodeIds) {
    const node = flow.nodes.find((item) => item.id === nodeId);
    if (!flow.edges.some((edge) => edge.target === nodeId) && node.type !== 'source') {
      push({ type: 'node_skipped', nodeId, reason: 'not connected' });
      continue;

    push({ type: 'node_started', nodeId });
    await wait(500);
    if (!alive()) return;
    if (node.data.wait) {
      push({ type: 'node_waiting', nodeId, reason: node.data.wait });
      await wait(1500);
      if (!alive()) return;
    }
    if (node.data.error) {
      push({ type: 'node_failed', nodeId, error: node.data.error });
      push({ type: 'run_failed', error: node.data.error });
      return;
    }
    push({ type: 'node_completed', nodeId });
  }
  push({ type: 'run_completed' });
});`}
/>

The widget shows execution but never runs anything. Assign a run snapshot, or a trace of run events to step through, to `run`, and each node shows its status, duration or error while the edges show which branches were taken; `mode="view"` hides the ports and editing tools for a monitor. `runnable` adds Run actions that dispatch `tp-run-request` with the nodes to run in order, and your backend answers with events through `pushRunEvent()`. In the header slots, which show only when one has content, bars with `execute` and `run-summary` hold Run and the status counts. `validate` shows design problems before any run: here the CDN purge has an unconnected required input.

## Keyboard

The canvas is one tab stop that enters at the last focused node. Inside a node, <Keys keys="tab" /> moves through its ports and controls, and keys typed into a control stay with it.

| Key | Action |
| --- | --- |
| Arrow keys | Move focus to the nearest node in that direction |
| <Keys keys="Home" /> <Keys keys="End" /> | Focus the first or the last node |
| <Keys keys="shift" /> with an arrow | Nudge the selection by one grid step; with <Keys keys="mod+shift" />, four |
| <Keys keys="enter" /> | Enter the focused node; on a port, start or confirm a connection, choosing among the candidates with the arrows |
| <Keys keys="space" /> | Toggle the focused node in the selection; held, pan with the pointer |
| <Keys keys="escape" /> | Cancel the gesture, leave the node, clear the selection, or close the inspector or the node library |
| <Keys keys="delete" /> <Keys keys="backspace" /> | Delete the selection |
| <Keys keys="mod+z" /> <Keys keys="mod+shift+z" /> | Undo, redo |
| <Keys keys="mod+c" /> <Keys keys="mod+x" /> <Keys keys="mod+v" /> <Keys keys="mod+d" /> | Copy, cut, paste, duplicate the selection |
| <Keys keys="mod+a" /> | Select everything |
| <Keys keys="mod+enter" /> | Ask to run the graph, with `runnable` |
| `+` `-` | Zoom in, zoom out |
| <Keys keys="shift+1" /> <Keys keys="shift+0" /> | Zoom to fit, zoom to 100% |
| <Keys keys="v" /> <Keys keys="h" /> | Select tool, pan tool |
| <Keys keys="e" /> | Cycle through the focused node's edges |
| <Keys keys="shift+F10" /> | Open the context menu |
